# ClockConfiguration

The `ClockConfiguration` class is a Spring `@Configuration` class that provides a centralized bean definition for a `java.time.Clock` instance. By defining this bean, the application ensures that all components requiring a clock (e.g., for timestamp generation, scheduling, or time-based logic) use a consistent time source.

Using a configurable clock bean simplifies testing, as you can easily replace the system clock with a fixed or offset clock in unit tests without modifying production code.

## Bean Definition

| Method | Return Type | Description |
|--------|-------------|-------------|
| `clock()` | `java.time.Clock` | Creates and returns a `Clock` instance configured to use the system's UTC time zone. |

### `clock()`

- **Purpose**: Provides a singleton `Clock` bean that returns the current time in UTC.
- **Implementation**: Returns `Clock.systemUTC()`, which uses the system clock in the UTC time zone.
- **Usage**: Inject this bean wherever time-related operations are needed, such as:
  - Generating timestamps for audit logs
  - Calculating time differences
  - Scheduling tasks
  - Validating time-based business rules

## Example Usage

```java
@Service
public class TimeService {
    private final Clock clock;

    public TimeService(Clock clock) {
        this.clock = clock;
    }

    public Instant now() {
        return Instant.now(clock);
    }
}
```

## Testing Benefits

By using a configurable `Clock` bean, you can easily test time-dependent code:

```java
@Test
void testWithFixedClock() {
    Clock fixedClock = Clock.fixed(Instant.parse("2024-01-01T00:00:00Z"), ZoneOffset.UTC);
    
    // Replace the clock bean in the test context
    // The service will now use the fixed time
}
```

## Dependencies

- **Spring Context**: `@Configuration` and `@Bean` annotations
- **Java Standard Library**: `java.time.Clock`
