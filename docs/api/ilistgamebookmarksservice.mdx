# IListGameBookmarksService

The `IListGameBookmarksService` interface defines the contract for retrieving a paginated list of game bookmarks. It uses a cursor-based pagination strategy to efficiently fetch bookmarks in a scalable manner, particularly useful for infinite scroll or "load more" UI patterns.

This is a **sealed interface**, meaning only the explicitly permitted class (`ListGameBookmarksService`) can implement it. This design enforces a controlled hierarchy and ensures that all implementations adhere to the same pagination contract.

## Interface Definition

```java
public sealed interface IListGameBookmarksService permits ListGameBookmarksService {

    CursorPagedResponse<GameBookmarkResponse> execute(String cursor, int size);

}
```

## Method Summary

| Method | Return Type | Description |
|--------|-------------|-------------|
| `execute(String cursor, int size)` | `CursorPagedResponse<GameBookmarkResponse>` | Retrieves a cursor-based paginated list of game bookmarks. |

## Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `cursor` | `String` | The cursor indicating the starting point for the next page of results. Pass `null` or an empty string to retrieve the first page. |
| `size` | `int` | The maximum number of bookmarks to return in a single page. Must be a positive integer. |

## Return Type

The method returns a `CursorPagedResponse<GameBookmarkResponse>` object, which encapsulates:

- A list of `GameBookmarkResponse` objects representing the bookmarks for the current page.
- A cursor string to be used in subsequent requests to fetch the next page.
- Additional metadata such as whether there are more results available.

## Usage Example

```java
// First page request
CursorPagedResponse<GameBookmarkResponse> firstPage = service.execute(null, 20);

// Subsequent page request using the cursor from the previous response
CursorPagedResponse<GameBookmarkResponse> nextPage = service.execute(firstPage.getNextCursor(), 20);
```

## Implementation Notes

- The sealed interface pattern ensures that only `ListGameBookmarkService` can implement this contract, providing compile-time safety and clear documentation of the implementation hierarchy.
- Cursor-based pagination is preferred over offset-based pagination for large datasets as it provides consistent results even when data is being added or removed.
- The `size` parameter should be validated to ensure it falls within acceptable bounds (typically between 1 and 100).
