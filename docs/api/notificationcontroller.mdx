# NotificationController

The `NotificationController` is a REST controller that provides endpoints for managing user notifications within the UpMatches application. It handles listing notifications, retrieving unread counts, marking notifications as read, and deleting notifications.

## Purpose

This controller serves as the API gateway for all notification-related operations. It delegates business logic to dedicated service interfaces, ensuring a clean separation of concerns between the web layer and the application logic.

## Endpoints

### List Notifications

Retrieves a paginated list of notifications for the authenticated user.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/notifications` | Returns a paginated list of notifications |

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | Integer | 0 | Page number (zero-based) |
| `size` | Integer | 20 | Number of items per page |

**Response:** `200 OK` - Returns a `PagedResponse<NotificationResponse>` wrapped in an `ApiResponse`.

### Get Unread Count

Retrieves the count of unread notifications for the authenticated user.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/notifications/unread-count` | Returns the count of unread notifications |

**Response:** `200 OK` - Returns an `UnreadCountResponse` wrapped in an `ApiResponse`.

### Mark Notification as Read

Marks a specific notification as read.

| Method | Path | Description |
|--------|------|-------------|
| PUT | `/api/v1/notifications/{id}/read` | Marks the specified notification as read |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the notification |

**Response:** `200 OK` - Returns the updated `NotificationResponse` wrapped in an `ApiResponse`.

### Mark All Notifications as Read

Marks all notifications for the authenticated user as read.

| Method | Path | Description |
|--------|------|-------------|
| PUT | `/api/v1/notifications/read-all` | Marks all notifications as read |

**Response:** `200 OK` - Returns the number of updated notifications wrapped in an `ApiResponse`.

### Delete Notification

Deletes a specific notification.

| Method | Path | Description |
|--------|------|-------------|
| DELETE | `/api/v1/notifications/{id}` | Deletes the specified notification |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the notification |

**Response:** `204 No Content` - Returns an empty response body.

## Dependencies

The controller relies on the following service interfaces:

- `IListNotificationsService` - Handles paginated notification retrieval
- `IGetUnreadCountService` - Handles unread count calculation
- `IMarkNotificationReadService` - Handles marking individual notifications as read
- `IMarkAllReadService` - Handles marking all notifications as read
- `IDeleteNotificationService` - Handles notification deletion

## Error Handling

The controller uses `ValidationHelper.validatePaginationParameters()` to validate pagination parameters before processing requests. Invalid parameters will result in appropriate error responses.

## Notes

- All endpoints are prefixed with `/api/v1/notifications`
- Pagination defaults to page 0 with 20 items per page
- Notifications are sorted by `createdAt` in descending order
- The controller returns consistent `ApiResponse` wrappers for success responses
- The delete endpoint returns `204 No Content` without a response body
