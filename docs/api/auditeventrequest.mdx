# AuditEventRequest

The `AuditEventRequest` is a Java record class that serves as the data transfer object (DTO) for capturing and transmitting audit event information within the application. It encapsulates all relevant details about an auditable action, including the actor performing the action, the action itself, the outcome, and contextual metadata such as IP address and user agent.

This record is immutable by design, leveraging Java's record feature to provide a concise and type-safe way to define audit event payloads. It is typically used in audit logging systems to record user activities, system events, or security-related actions for compliance, monitoring, and debugging purposes.

## Record Definition

```java
public record AuditEventRequest(
    UUID actorId,
    AuditActorType actorType,
    String action,
    AuditCategory category,
    AuditOutcome outcome,
    String resourceType,
    String resourceId,
    String ipAddress,
    String userAgent,
    String correlationId,
    String requestPayload,
    String errorCode,
    String errorMessage
) {}
```

## Components

| Component | Type | Description |
|-----------|------|-------------|
| `actorId` | `UUID` | Unique identifier of the entity (user, system, or service) that performed the auditable action. |
| `actorType` | `AuditActorType` | Enum indicating the type of actor (e.g., USER, SYSTEM, SERVICE). |
| `action` | `String` | Description of the action performed (e.g., "LOGIN", "CREATE_USER", "DELETE_RECORD"). |
| `category` | `AuditCategory` | Enum categorizing the audit event (e.g., AUTHENTICATION, AUTHORIZATION, DATA_MODIFICATION). |
| `outcome` | `AuditOutcome` | Enum representing the result of the action (e.g., SUCCESS, FAILURE, DENIED). |
| `resourceType` | `String` | Type of resource affected by the action (e.g., "User", "Order", "Document"). |
| `resourceId` | `String` | Identifier of the specific resource instance affected. |
| `ipAddress` | `String` | IP address from which the action originated. |
| `userAgent` | `String` | User agent string of the client making the request. |
| `correlationId` | `String` | Unique identifier used to correlate related audit events across distributed systems. |
| `requestPayload` | `String` | Serialized representation of the request payload (e.g., JSON body) for detailed auditing. |
| `errorCode` | `String` | Error code associated with the action, if applicable (e.g., "INVALID_INPUT", "UNAUTHORIZED"). |
| `errorMessage` | `String` | Human-readable error message providing additional context about failures. |

## Usage

The `AuditEventRequest` record is typically constructed and passed to an audit service for processing. Below is an example of how to create an instance:

```java
AuditEventRequest auditEvent = new AuditEventRequest(
    UUID.randomUUID(),
    AuditActorType.USER,
    "LOGIN",
    AuditCategory.AUTHENTICATION,
    AuditOutcome.SUCCESS,
    "User",
    "user-123",
    "192.168.1.1",
    "Mozilla/5.0...",
    UUID.randomUUID().toString(),
    "{\"username\":\"john.doe\"}",
    null,
    null
);
```

## Best Practices

- **Immutability**: Since `AuditEventRequest` is a record, all fields are final and cannot be modified after creation. This ensures data integrity for audit trails.
- **Null Handling**: Fields like `errorCode` and `errorMessage` are nullable and should be set to `null` when not applicable (e.g., for successful actions).
- **Serialization**: The record is well-suited for serialization to JSON or other formats, making it easy to transmit audit events to external systems or persist them in databases.
- **Correlation**: Always provide a `correlationId` to enable tracing of related events across microservices or distributed systems.
