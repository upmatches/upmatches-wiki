# GetActivityService

The `GetActivityService` class is a Spring service component responsible for retrieving a single `Activity` entity by its unique identifier (UUID). It implements the `IGetActivityService` interface and provides a transactional, read-only operation that fetches an activity from the database and converts it into an `ActivityResponse` DTO.

## Purpose

This service encapsulates the business logic for fetching an activity by ID. It handles:
- Database lookup via `ActivityRepository`
- Error handling when the activity is not found (throws `ResourceNotFoundException`)
- Conversion of the entity to a response DTO
- Execution within a read-only transaction context for performance optimization

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `ActivityRepository` | Constructor Injection | Repository for accessing activity data in the database |

## Public Methods

### `execute(UUID id)`

Retrieves an activity by its unique identifier and returns the corresponding response DTO.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the activity to retrieve |

| Returns | Type | Description |
|---------|------|-------------|
| Success | `ActivityResponse` | The activity data wrapped in a response DTO |
| Failure | Throws `ResourceNotFoundException` | If no activity exists with the given ID |

**Example Usage:**

```java
@Autowired
private GetActivityService getActivityService;

public void someMethod() {
    UUID activityId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
    ActivityResponse response = getActivityService.execute(activityId);
    // Use response data...
}
```

## Error Handling

The service throws a `ResourceNotFoundException` with a formatted message when the requested activity ID does not exist in the database. The error message follows the pattern: `"Activity with ID '{uuid}' not found."`

## Transactional Behavior

The `execute` method is annotated with `@Transactional(readOnly = true)`, which:
- Optimizes database access for read operations
- Prevents unintended data modifications
- Improves performance by allowing database-level read optimizations

## Implementation Details

The service uses `ServiceOperationExecutor.execute()` to wrap the retrieval logic with standardized operation tracking and error handling. This utility method:
- Executes the provided lambda function
- Associates the operation with the `RETRIEVE` status
- Wraps any `ResourceNotFoundException` appropriately

The class is declared as `non-sealed`, allowing it to be extended by other service implementations if needed.
