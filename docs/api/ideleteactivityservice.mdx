# IDeleteActivityService Interface

The `IDeleteActivityService` interface defines the contract for deleting an activity within the application. It follows a command-like pattern where the service encapsulates the logic required to remove an activity identified by its unique identifier.

This interface is declared as `sealed`, meaning only explicitly permitted classes can implement it. In this case, the only permitted implementation is `DeleteActivityService`. This design enforces a controlled hierarchy and ensures that deletion logic is centralized and not extended arbitrarily.

## Interface Definition

```java
package com.upmatches.app.features.activity.services;

import java.util.UUID;

public sealed interface IDeleteActivityService permits DeleteActivityService {

    void execute(UUID id);

}
```

## Method Summary

| Method | Description |
|--------|-------------|
| `void execute(UUID id)` | Deletes the activity identified by the given UUID. |

## Method Details

### `execute`

```java
void execute(UUID id)
```

Deletes an activity from the system based on its unique identifier.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the activity to be deleted. |

**Returns:** `void` — This method does not return a value. Implementations should handle errors internally or throw appropriate runtime exceptions.

**Usage Example:**

```java
IDeleteActivityService deleteService = new DeleteActivityService();
UUID activityId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
deleteService.execute(activityId);
```

## Implementation Notes

- The interface is `sealed`, restricting implementation to `DeleteActivityService` only.
- The `execute` method is intentionally simple, accepting only the activity's UUID and performing the deletion without returning a result.
- Implementations should ensure proper error handling, such as throwing an exception if the activity does not exist or if the deletion fails due to business rules.
