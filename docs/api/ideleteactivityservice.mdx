# IDeleteActivityService Interface

The `IDeleteActivityService` interface defines the contract for deleting an activity within the application. It is a sealed interface, meaning only explicitly permitted classes (in this case, `DeleteActivityService`) can implement it. This design enforces a controlled and secure implementation hierarchy, ensuring that the deletion logic is centralized and cannot be extended arbitrarily.

## Purpose

The primary purpose of this interface is to abstract the operation of deleting an activity identified by its unique ID. By defining a single `execute` method, it provides a clear and consistent API for triggering activity deletion, while the actual implementation details (e.g., database operations, validation, event publishing) are encapsulated within the permitted implementing class.

## Interface Definition

```java
public sealed interface IDeleteActivityService permits DeleteActivityService {
    void execute(UUID id);
}
```

## Methods

### `execute`

| Parameter | Type   | Description                                      |
|-----------|--------|--------------------------------------------------|
| `id`      | `UUID` | The unique identifier of the activity to delete. |

This method performs the deletion of an activity based on its UUID. The implementation is responsible for handling any necessary validation, persistence operations, and side effects (such as logging or event emission). The method does not return a value; any errors or exceptions should be thrown as runtime exceptions or handled within the implementation.

## Usage Example

```java
// Assuming an instance of DeleteActivityService is available
IDeleteActivityService deleteService = new DeleteActivityService();

// Delete an activity with a specific UUID
UUID activityId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
deleteService.execute(activityId);
```

## Implementation Notes

- The interface is **sealed**, which restricts implementation to the `DeleteActivityService` class. This is a Java 17+ feature that enhances security and maintainability by preventing unintended extensions.
- The `execute` method is intentionally void; it does not return a success indicator. Implementations should throw exceptions (e.g., `ActivityNotFoundException`, `IllegalStateException`) to signal failure conditions.
- The use of `UUID` as the identifier ensures globally unique identification of activities, which is critical for distributed systems or when activities are referenced across different services.
