## Overview

`ListMyHostedGamesCursorService` is a Spring service class that provides cursor-based pagination for retrieving games hosted by the currently authenticated user. It implements the `IListMyHostedGamesCursorService` interface and is marked as `non-sealed`, allowing further extension if needed.

The service uses a cursor-based pagination strategy (rather than traditional offset-based pagination) to efficiently handle large datasets and provide consistent results even when new games are added during pagination.

## Dependencies

| Dependency | Type | Description |
|-----------|------|-------------|
| `GameRepository` | Repository | Data access layer for `Game` entities |
| `GameParticipantRepository` | Repository | Data access layer for game participant counts |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user's ID |
| `GameCursor` | Helper | Encodes/decodes cursor values for pagination |

## Public Methods

### `execute(String cursor, int size)`

Retrieves a paginated list of games hosted by the authenticated user, ordered by start time and ID.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `cursor` | `String` | Base64-encoded cursor string for pagination. Pass `null` or empty string for the first page. |
| `size` | `int` | Maximum number of games to return per page |

**Returns:**

| Type | Description |
|------|-------------|
| `CursorPagedResponse<GameResponse>` | A paginated response containing the list of games and a cursor for the next page |

**Behavior:**

1. Resolves the authenticated user's UUID via `userResolver.requireUserId()`
2. Decodes the cursor string to extract the last game's start time and ID (if provided)
3. Queries the database for games hosted by the user after the cursor position
4. Counts active participants for each retrieved game
5. Maps each `Game` entity to a `GameResponse` DTO with participant counts
6. Generates a new cursor for the next page if more results exist
7. Wraps the operation in `ServiceOperationExecutor` for consistent error handling and logging

**Cursor Encoding:**

The cursor encodes two values:
- `startTime` (Instant): The start time of the last game on the current page
- `id` (UUID): The ID of the last game on the current page

This composite cursor ensures stable pagination even when multiple games share the same start time.

## Private Methods

### `countParticipants(List<Game> games)`

Counts active participants for a list of games.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `games` | `List<Game>` | List of games to count participants for |

**Returns:**

| Type | Description |
|------|-------------|
| `Map<UUID, Long>` | Map of game IDs to their active participant counts |

**Behavior:**

- Extracts game IDs from the provided list
- Returns an empty map if the list is empty
- Queries `participantRepository` for counts of participants with `ACTIVE` status
- Converts the result to a map keyed by game ID

## Error Handling

The service uses `ServiceOperationExecutor.execute()` which:

- Wraps the operation with the `RETRIEVE` status
- Throws `ResourceNotFoundException` if the operation fails
- Provides consistent logging and monitoring

## Usage Example

```java
// First page - no cursor
CursorPagedResponse<GameResponse> firstPage = service.execute(null, 20);

// Subsequent pages - use cursor from previous response
CursorPagedResponse<GameResponse> nextPage = service.execute(firstPage.getNextCursor(), 20);
```

## Transactional Behavior

The `execute` method is annotated with `@Transactional(readOnly = true)`, ensuring:

- All database operations within the method execute within a single transaction
- Read-only optimization hints are provided to the database
- Consistent data view across the participant count query and game retrieval
