# ServiceOperationExecutor

## Purpose

The `ServiceOperationExecutor` is a utility class that provides a standardized way to execute service operations with comprehensive exception handling, logging, and tracing. It acts as a centralized error handling mechanism for service layer operations, translating various database, REST client, and runtime exceptions into meaningful, type-specific exceptions.

Key features include:
- Automatic trace ID generation and propagation via MDC (Mapped Diagnostic Context)
- Consistent logging across all operations
- Granular exception handling for database operations (locking, entity, data access)
- REST client exception handling with response body truncation
- Support for both return-value and void operations
- Programmer error detection and re-throwing

## Public Methods

### `execute`

```java
public static <T> T execute(
    Supplier<T> operation,
    OperationStatus operationType,
    ExceptionFactory exceptionFactory)
```

Executes a service operation with comprehensive exception handling and tracing.

| Parameter | Type | Description |
|-----------|------|-------------|
| `operation` | `Supplier<T>` | The operation to execute, must not be null |
| `operationType` | `OperationStatus` | The type of operation being performed (e.g., SAVE, UPDATE, DELETE, RETRIEVE) |
| `exceptionFactory` | `ExceptionFactory` | Factory for creating domain-specific exceptions |

**Returns:** The result of the operation

**Throws:**
- `IllegalArgumentException` - If the operation throws it (re-thrown as-is)
- `ResourceNotFoundException` - If the operation throws it (re-thrown as-is)
- Various exceptions created by the `exceptionFactory` for database, REST client, and runtime errors

### `executeVoid`

```java
public static void executeVoid(
    Runnable operation,
    OperationStatus operationType,
    ExceptionFactory exceptionFactory)
```

Executes a void service operation with the same exception handling and tracing as `execute`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `operation` | `Runnable` | The void operation to execute, must not be null |
| `operationType` | `OperationStatus` | The type of operation being performed |
| `exceptionFactory` | `ExceptionFactory` | Factory for creating domain-specific exceptions |

**Throws:** Same as `execute`

## Exception Handling Details

### Database Exceptions

The executor handles the following database-related exceptions:

| Exception Type | Handled As |
|----------------|------------|
| `OptimisticLockingFailureException` | Concurrent modification detected |
| `DeadlockLoserDataAccessException` | Database deadlock detected |
| `CannotAcquireLockException` | Cannot acquire database lock |
| `PessimisticLockingFailureException` | Resource locked by another transaction |
| `EntityNotFoundException` | Entity not found (context-dependent message) |
| `EntityExistsException` | Entity already exists |
| `DataIntegrityViolationException` | Data integrity violation (context-dependent) |
| `ConstraintViolationException` | Constraint violation (context-dependent) |
| `InvalidDataAccessResourceUsageException` | Table/column not found, SQL syntax errors |
| `JpaSystemException` | JPA system error |
| `InvalidDataAccessApiUsageException` | Invalid data access API usage |
| `PersistenceException` | General persistence error |

### REST Client Exceptions

| Exception Type | Handled As |
|----------------|------------|
| `HttpStatusCodeException` | External service error with HTTP status and response body |
| `ResourceAccessException` | External service unavailable |
| Other `RestClientException` | General external service error |

### Runtime Exceptions

Programmer errors (NullPointerException, IllegalStateException, etc.) are re-thrown as-is. All other runtime exceptions are wrapped using the provided `ExceptionFactory`.

## Usage Example

```java
@Service
public class UserService {
    
    private final ExceptionFactory exceptionFactory;
    
    public UserService(ExceptionFactory exceptionFactory) {
        this.exceptionFactory = exceptionFactory;
    }
    
    public User getUserById(Long id) {
        return ServiceOperationExecutor.execute(
            () -> userRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("User not found")),
            OperationStatus.RETRIEVE,
            exceptionFactory
        );
    }
    
    public void deleteUser(Long id) {
        ServiceOperationExecutor.executeVoid(
            () -> userRepository.deleteById(id),
            OperationStatus.DELETE,
            exceptionFactory
        );
    }
}
```

## Notes

- The class is a utility class and cannot be instantiated (private constructor)
- Trace IDs are automatically generated and managed via MDC, with cleanup in the `finally` block
- Response bodies from REST client exceptions are truncated to prevent memory issues (configurable via `MAX_RESPONSE_BODY_SIZE`)
- The `OperationStatus` enum determines context-specific error messages for entity and constraint violations
