# RefreshTokenStore

The `RefreshTokenStore` class is a Spring service that manages refresh tokens for user authentication. It provides secure storage, validation, rotation, and revocation of refresh tokens using Redis as the backing store. The class implements the `IRefreshTokenStore` interface and is conditionally created only when a `SigningKeyProvider` bean is available.

## Purpose

This service handles the complete lifecycle of refresh tokens:
- **Storage**: Securely stores refresh tokens with SHA-256 hashing
- **Validation & Rotation**: Validates tokens and automatically rotates them upon use
- **Revocation**: Supports revoking all tokens for a specific user
- **Expiry Management**: Automatically manages token expiration based on configured duration

## Key Features

- **Token Hashing**: All tokens are hashed using SHA-256 before storage for security
- **Redis Backend**: Uses Redis for fast, scalable token storage
- **Automatic Rotation**: Tokens are rotated on each validation to prevent replay attacks
- **User-Level Management**: Tracks all tokens per user for efficient revocation

## Public Methods

### `store(UUID userId, String refreshToken)`

Stores a new refresh token for a user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The unique identifier of the user |
| `refreshToken` | `String` | The refresh token to store |

The method hashes the token, creates a `RefreshTokenEntry` with the current timestamp, and stores it in Redis with the configured expiry duration. It also maintains a set of token hashes per user for efficient revocation.

### `validateAndRotate(String refreshToken)`

Validates a refresh token and rotates it, returning a new token.

| Parameter | Type | Description |
|-----------|------|-------------|
| `refreshToken` | `String` | The refresh token to validate and rotate |

**Returns**: `ValidationResult` containing the user ID and new refresh token, or `null` if the token is invalid or expired.

The method atomically retrieves and deletes the old token, removes it from the user's token set, generates a new token, and stores it. This prevents token replay attacks.

### `revokeAllForUser(UUID userId)`

Revokes all refresh tokens for a specific user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The unique identifier of the user |

This method retrieves all token hashes associated with the user, deletes each individual token entry, and then removes the user's token set from Redis.

## Inner Records

### `ValidationResult`

A record containing the result of token validation and rotation.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user ID associated with the validated token |
| `newRefreshToken` | `String` | The newly generated refresh token |

### `RefreshTokenEntry`

A private record representing a stored refresh token entry.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user ID who owns this token |
| `createdAt` | `Instant` | The timestamp when the token was created |

## Dependencies

- **StringRedisTemplate**: Redis client for token storage operations
- **ObjectMapper**: Jackson JSON serializer/deserializer for token entries
- **IJwtTokenService**: Service for generating new refresh tokens
- **JwtProperties**: Configuration properties for token expiry duration

## Security Considerations

- Tokens are hashed using SHA-256 before storage, so the raw token is never persisted
- Token rotation prevents replay attacks by invalidating tokens after use
- All token operations are atomic to prevent race conditions
- Token expiry is enforced at the Redis level for automatic cleanup
