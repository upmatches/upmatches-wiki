# RefreshTokenStore

The `RefreshTokenStore` class is a Spring service that manages refresh tokens for user authentication. It provides secure storage, validation, rotation, and revocation of refresh tokens using Redis as the backing store. The class implements the `IRefreshTokenStore` interface and is conditionally loaded only when a `SigningKeyProvider` bean is available.

## Purpose

This service handles the complete lifecycle of refresh tokens:
- **Storage**: Securely stores refresh tokens with SHA-256 hashing
- **Validation & Rotation**: Validates tokens and automatically rotates them upon use
- **Revocation**: Supports revoking all tokens for a specific user
- **Expiry Management**: Automatically handles token expiration based on configured duration

## Dependencies

| Dependency | Description |
|------------|-------------|
| `StringRedisTemplate` | Redis client for token storage |
| `ObjectMapper` | JSON serialization/deserialization |
| `IJwtTokenService` | Service for generating new refresh tokens |
| `JwtProperties` | Configuration properties for token expiry |

## Public Methods

### `store(UUID userId, String refreshToken)`

Stores a refresh token for a user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `refreshToken` | `String` | The refresh token to store |

The method hashes the token using SHA-256 and stores it in Redis with:
- A key prefix `refresh_token:` followed by the hash
- A user-specific set key `refresh_tokens:user:` followed by the user ID
- Configurable expiry duration from `JwtProperties`

### `validateAndRotate(String refreshToken)`

Validates a refresh token and rotates it (returns a new token).

| Parameter | Type | Description |
|-----------|------|-------------|
| `refreshToken` | `String` | The refresh token to validate |

| Return Type | Description |
|-------------|-------------|
| `ValidationResult` | Contains the user ID and new refresh token, or `null` if validation fails |

The method:
1. Hashes the token and retrieves it from Redis
2. Deletes the old token atomically using `getAndDelete`
3. Removes the token hash from the user's token set
4. Generates a new refresh token and stores it
5. Returns a `ValidationResult` with the user ID and new token

### `revokeAllForUser(UUID userId)`

Revokes all refresh tokens for a specific user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The user whose tokens should be revoked |

This method:
1. Retrieves all token hashes for the user from Redis
2. Deletes each individual token entry
3. Deletes the user's token set

## Inner Types

### `ValidationResult`

A record that holds the result of token validation and rotation.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `newRefreshToken` | `String` | The newly generated refresh token |

### `RefreshTokenEntry`

A private record representing a stored refresh token entry.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `createdAt` | `Instant` | Timestamp when the token was created |

## Security Considerations

- **Token Hashing**: All tokens are hashed using SHA-256 before storage, ensuring plaintext tokens are never stored
- **Atomic Operations**: Token validation and deletion use atomic Redis operations to prevent race conditions
- **Token Rotation**: Each validation automatically generates a new token, limiting the window for token theft
- **User-Level Revocation**: Supports bulk revocation of all tokens for a user, useful for security incidents

## Configuration

The token expiry duration is configured through `JwtProperties.refreshTokenExpiryDays()`. This value is converted to a `Duration` object and applied to all stored tokens.
