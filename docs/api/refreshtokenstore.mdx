# RefreshTokenStore

The `RefreshTokenStore` class is a Spring service that manages refresh tokens for user authentication. It provides secure storage, validation, rotation, and revocation of refresh tokens using Redis as the backing store. The class implements the `IRefreshTokenStore` interface and is conditionally created only when a `SigningKeyProvider` bean is available.

## Purpose

This service handles the complete lifecycle of refresh tokens:
- **Storage**: Securely stores refresh tokens with SHA-256 hashing
- **Validation**: Validates tokens and performs automatic rotation (token rotation)
- **Revocation**: Supports revoking all tokens for a specific user
- **Expiration**: Automatically manages token expiration based on configured duration

## Key Features

- **Token Hashing**: Tokens are stored as SHA-256 hashes for security
- **Redis Backend**: Uses Redis for fast, scalable token storage
- **Automatic Rotation**: Validates and replaces tokens in a single atomic operation
- **User-based Management**: Tracks all tokens per user for easy revocation
- **Thread-safe**: Uses Redis atomic operations for concurrent access

## Dependencies

- `StringRedisTemplate`: Redis operations
- `ObjectMapper`: JSON serialization/deserialization
- `IJwtTokenService`: Token generation
- `JwtProperties`: Configuration for token expiry

## Public Methods

### store

Stores a new refresh token for a user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `refreshToken` | `String` | The refresh token to store |

**Returns**: `void`

**Throws**: `IllegalStateException` if serialization fails

### validateAndRotate

Validates a refresh token and automatically rotates it (creates a new one while invalidating the old).

| Parameter | Type | Description |
|-----------|------|-------------|
| `refreshToken` | `String` | The refresh token to validate |

**Returns**: `ValidationResult` containing the user ID and new refresh token, or `null` if the token is invalid or expired

### revokeAllForUser

Revokes all refresh tokens for a specific user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The user whose tokens should be revoked |

**Returns**: `void`

## Inner Records

### ValidationResult

Contains the result of token validation and rotation.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `newRefreshToken` | `String` | The newly generated refresh token |

### RefreshTokenEntry

Internal record for storing token metadata in Redis.

| Field | Type | Description |
|-------|------|-------------|
| `userId` | `UUID` | The user's unique identifier |
| `createdAt` | `Instant` | Timestamp when the token was created |

## Implementation Details

### Token Hashing

The `hashToken` method uses SHA-256 to create a secure hash of the refresh token before storage. This ensures that even if the Redis store is compromised, the actual tokens remain protected.

### Redis Key Structure

- **Token key**: `refresh_token:{hash}` - Stores the token metadata
- **User key**: `refresh_tokens:user:{userId}` - Set of all token hashes for a user

### Token Rotation

The `validateAndRotate` method performs an atomic get-and-delete operation on the token key, ensuring that a token can only be used once. If successful, it generates a new token and stores it for the user.

## Usage Example

```java
@Autowired
private RefreshTokenStore refreshTokenStore;

// Store a new token
UUID userId = UUID.randomUUID();
String token = jwtTokenService.generateRefreshToken();
refreshTokenStore.store(userId, token);

// Validate and rotate
RefreshTokenStore.ValidationResult result = refreshTokenStore.validateAndRotate(token);
if (result != null) {
    // Token is valid, use the new token
    String newToken = result.newRefreshToken();
}

// Revoke all tokens for a user
refreshTokenStore.revokeAllForUser(userId);
```
