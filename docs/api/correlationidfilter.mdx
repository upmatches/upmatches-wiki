# CorrelationIdFilter

## Purpose

The `CorrelationIdFilter` is a Spring Boot servlet filter that implements a distributed tracing pattern by managing a correlation ID across HTTP requests. It runs with the highest precedence in the filter chain and ensures that every incoming request is tagged with a unique identifier that can be propagated through downstream services.

This filter:
- Extracts an existing correlation ID from the `X-Correlation-Id` HTTP header if present
- Generates a new 8-character UUID-based correlation ID if none exists
- Stores the correlation ID in the SLF4J Mapped Diagnostic Context (MDC) for logging purposes
- Sets the correlation ID on the HTTP response header for client-side tracing
- Properly cleans up the MDC context after request processing

## Public Methods

### `doFilterInternal`

```java
protected void doFilterInternal(HttpServletRequest request,
                                HttpServletResponse response,
                                FilterChain filterChain) throws ServletException, IOException
```

The main filter logic that processes each incoming HTTP request.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |
| `response` | `HttpServletResponse` | The outgoing HTTP response |
| `filterChain` | `FilterChain` | The filter chain to pass request/response to |

**Behavior:**

1. Resolves the correlation ID using `resolveCorrelationId()`
2. Checks if a correlation ID already exists in the MDC context
3. If no existing ID, stores the resolved ID in MDC under the `requestId` key
4. Sets the `X-Correlation-Id` response header to the current MDC value
5. Continues the filter chain processing
6. In the `finally` block, removes the MDC entry if it was newly added (to prevent memory leaks)

## Private Methods

### `resolveCorrelationId`

```java
private String resolveCorrelationId(HttpServletRequest request)
```

Determines the correlation ID to use for the current request.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `String` - The correlation ID

**Logic:**

1. Checks the `X-Correlation-Id` header from the incoming request
2. If the header exists and is not blank, returns the header value (preserving upstream correlation)
3. If no valid header exists, generates a new UUID, takes the first 8 characters, and returns that as the correlation ID

## Important Notes

- The filter uses `OncePerRequestFilter` to guarantee it executes only once per request dispatch
- The `@Order(Ordered.HIGHEST_PRECEDENCE)` annotation ensures this filter runs before any other filters
- MDC cleanup is handled in a `finally` block to guarantee proper resource cleanup even if exceptions occur
- The correlation ID length of 8 characters provides a balance between uniqueness and readability
- When a correlation ID exists in the incoming request header, it is preserved rather than replaced, enabling end-to-end tracing across microservices
