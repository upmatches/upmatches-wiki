# IMarkStartedGamesService Interface

## Purpose

The `IMarkStartedGamesService` interface defines a contract for marking games that have started within the application. It is a **sealed interface**, meaning only explicitly permitted classes (in this case, `MarkStartedGamesService`) can implement it. This design enforces a controlled hierarchy and ensures that the logic for marking started games is centralized and cannot be extended arbitrarily.

The interface exposes a single method, `execute()`, which returns an integer representing the number of games that were successfully marked as started. This pattern is commonly used in service layers to encapsulate business operations with a clear, side-effect-oriented API.

## Interface Definition

```java
package com.upmatches.app.features.game.services;

public sealed interface IMarkStartedGamesService permits MarkStartedGamesService {

    int execute();

}
```

## Public Method

| Method   | Return Type | Description                                                                 |
|----------|-------------|-----------------------------------------------------------------------------|
| `execute` | `int`       | Executes the operation to mark games as started. Returns the count of games that were successfully updated. |

## Usage Notes

- The interface is **sealed**, so only the class `MarkStartedGamesService` is allowed to implement it. This prevents unauthorized or accidental implementations elsewhere in the codebase.
- The `execute()` method is intended to be called when the application needs to transition games from a pending or scheduled state to a "started" state.
- The return value (`int`) can be used for logging, validation, or triggering subsequent actions based on how many games were affected.
- This interface follows a command-like pattern, where the operation is self-contained and does not require parameters. If additional context is needed in the future, consider extending the interface or using a parameter object.
