## Overview

`BaseEntity` is an abstract JPA mapped superclass that provides common fields and behavior for all entities in the application. It implements automatic UUID generation, Spring Data JPA auditing (creation/modification timestamps and user tracking), and soft delete functionality.

By extending this class, all concrete entities inherit a consistent set of fields and lifecycle callbacks, reducing boilerplate and ensuring uniformity across the data model.

## Key Features

- **Auto-generated UUID**: Each entity gets a unique, non-sequential UUID on creation.
- **Auditing**: Automatic tracking of creation and last modification timestamps and users (requires Spring Data JPA auditing configuration).
- **Soft Delete**: Entities can be logically deleted by setting a `deletedAt` timestamp, rather than being physically removed from the database.
- **Lombok Integration**: Uses `@Getter` and `@Setter` to automatically generate getters and setters for all fields.

## Fields

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | `Long` | Primary key, auto-generated via identity strategy | Database-generated sequential identifier |
| `uuid` | `UUID` | Not null, unique, not updatable | Universally unique identifier, generated automatically on persist |
| `createdAt` | `Instant` | Not null, not updatable | Timestamp of entity creation (set by auditing) |
| `updatedAt` | `Instant` | Not null | Timestamp of last modification (set by auditing) |
| `createdBy` | `String` | Nullable, not updatable | Username or identifier of the creator (set by auditing) |
| `updatedBy` | `String` | Nullable | Username or identifier of the last modifier (set by auditing) |
| `deletedAt` | `Instant` | Nullable | Timestamp of logical deletion; `null` means active |

## Public Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `isDeleted()` | `boolean` | Returns `true` if the entity has been soft-deleted (`deletedAt` is not null) |
| `markDeleted()` | `void` | Sets `deletedAt` to the current instant, marking the entity as deleted |

## Lifecycle Callbacks

### `@PrePersist` - `onCreate()`

Automatically invoked by JPA before the entity is first persisted. If `uuid` is `null`, it generates a new random UUID. This ensures every entity has a unique UUID even if not explicitly set.

## Usage Example

```java
@Entity
public class User extends BaseEntity {
    private String username;
    private String email;
    
    // Additional fields and methods
}

// Creating a new user
User user = new User();
user.setUsername("john_doe");
user.setEmail("john@example.com");
userRepository.save(user); // UUID, createdAt, createdBy are auto-populated

// Soft deleting a user
user.markDeleted();
userRepository.save(user); // deletedAt is now set
```

## Configuration Requirements

To enable Spring Data JPA auditing for `createdBy` and `updatedBy` fields, you must configure an `AuditorAware` bean in your Spring context:

```java
@Configuration
@EnableJpaAuditing
public class AuditConfig {
    
    @Bean
    public AuditorAware<String> auditorProvider() {
        return () -> Optional.ofNullable(SecurityContextHolder.getContext())
                .map(ctx -> ctx.getAuthentication())
                .map(Authentication::getName)
                .or(() -> Optional.of("system"));
    }
}
```

## Important Notes

- This class is abstract and cannot be instantiated directly. It must be extended by concrete entity classes.
- The `uuid` field is set only once during creation and cannot be updated afterward.
- Soft-deleted entities remain in the database. Queries should typically filter out deleted records using `WHERE deleted_at IS NULL`.
- The `createdBy` and `updatedBy` fields depend on Spring Security context; if no authenticated user is available, they may remain `null`.
