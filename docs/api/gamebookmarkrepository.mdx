# GameBookmarkRepository

The `GameBookmarkRepository` interface provides data access operations for the `GameBookmark` entity. It extends Spring Data JPA's `JpaRepository` to inherit standard CRUD functionality while adding custom query methods for bookmark-specific operations.

This repository manages the relationship between users and games they have bookmarked, supporting operations such as checking bookmark existence, retrieving individual bookmarks, and implementing cursor-based pagination for efficient retrieval of large bookmark collections.

## Interface Definition

```java
public interface GameBookmarkRepository extends JpaRepository<GameBookmark, UUID>
```

The repository works with `GameBookmark` entities using `UUID` as the primary key type.

## Methods

### Standard CRUD Methods

The following methods are inherited from `JpaRepository<GameBookmark, UUID>`:

| Method | Description |
|--------|-------------|
| `findAll()` | Retrieves all game bookmarks |
| `findById(UUID id)` | Finds a bookmark by its unique identifier |
| `save(GameBookmark bookmark)` | Creates or updates a bookmark |
| `deleteById(UUID id)` | Deletes a bookmark by its identifier |
| `count()` | Returns the total number of bookmarks |

### Custom Query Methods

#### `existsByGameIdAndUserId`

```java
boolean existsByGameIdAndUserId(UUID gameId, UUID userId)
```

Checks whether a bookmark exists for a specific game and user combination.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `gameId` | `UUID` | The unique identifier of the game |
| `userId` | `UUID` | The unique identifier of the user |

**Returns:** `boolean` - `true` if a bookmark exists for the given game and user, `false` otherwise.

---

#### `findByGameIdAndUserId`

```java
Optional<GameBookmark> findByGameIdAndUserId(UUID gameId, UUID userId)
```

Retrieves a bookmark for a specific game and user combination.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `gameId` | `UUID` | The unique identifier of the game |
| `userId` | `UUID` | The unique identifier of the user |

**Returns:** `Optional<GameBookmark>` - An Optional containing the bookmark if found, or empty if no bookmark exists for the given game and user.

#### `findByUserIdCursor`

```java
@Query(value = """
    SELECT b.* FROM game_bookmarks b
    JOIN games g ON g.id = b.game_id
    WHERE b.user_id = :userId
      AND g.deleted_at IS NULL
      AND (CAST(:afterBookmarkedAt AS timestamptz) IS NULL
           OR b.bookmarked_at < :afterBookmarkedAt
           OR (b.bookmarked_at = :afterBookmarkedAt AND b.id > :afterId))
    ORDER BY b.bookmarked_at DESC, b.id ASC
    LIMIT :size
    """, nativeQuery = true)
List<GameBookmark> findByUserIdCursor(
    @Param("userId") UUID userId,
    @Param("afterBookmarkedAt") Instant afterBookmarkedAt,
    @Param("afterId") UUID afterId,
    @Param("size") int size)
```

Performs cursor-based pagination to retrieve bookmarks for a specific user. This method efficiently handles large datasets by using a cursor approach rather than traditional offset-based pagination.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The unique identifier of the user whose bookmarks to retrieve |
| `afterBookmarkedAt` | `Instant` | The timestamp cursor; bookmarks bookmarked before this time will be returned. Pass `null` for the first page |
| `afterId` | `UUID` | The ID cursor used for tie-breaking when multiple bookmarks have the same `bookmarked_at` timestamp |
| `size` | `int` | The maximum number of bookmarks to return in a single page |

**Returns:** `List<GameBookmark>` - A list of bookmarks for the specified user, ordered by bookmark timestamp (newest first) and then by ID (ascending).

**Query Logic:**

The native SQL query performs the following operations:

1. **Joins** the `game_bookmarks` table with the `games` table to access game metadata
2. **Filters** by the specified `userId`
3. **Excludes** bookmarks for games that have been soft-deleted (`g.deleted_at IS NULL`)
4. **Applies cursor logic**: If `afterBookmarkedAt` is provided, returns only bookmarks with:
   - A `bookmarked_at` timestamp earlier than the cursor, OR
   - The same `bookmarked_at` timestamp but with an ID greater than the cursor (for tie-breaking)
5. **Orders** results by `bookmarked_at` descending (newest first) and `id` ascending
6. **Limits** the result set to the specified page size

**Usage Example:**

```java
// First page: no cursor
List<GameBookmark> firstPage = repository.findByUserIdCursor(
    userId, null, null, 20);

// Subsequent pages: use the last bookmark's timestamp and ID
GameBookmark lastBookmark = firstPage.get(firstPage.size() - 1);
List<GameBookmark> nextPage = repository.findByUserIdCursor(
    userId, lastBookmark.getBookmarkedAt(), lastBookmark.getId(), 20);
```
