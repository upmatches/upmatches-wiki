# ExpelParticipantRequest

The `ExpelParticipantRequest` class is a Java record used to encapsulate the data required when expelling a participant from a game or match. It provides a simple, immutable data structure that includes an optional reason for the expulsion.

## Purpose

This record is designed to be used as a request body in API endpoints that handle participant expulsion. It ensures that the reason provided does not exceed 280 characters, enforcing a constraint that helps maintain concise and meaningful feedback.

## Record Structure

The record is defined with a single component:

| Field    | Type     | Description                                                                 |
|----------|----------|-----------------------------------------------------------------------------|
| `reason` | `String` | An optional reason for expelling the participant. Must be at most 280 characters. |

## Validation

The `reason` field is annotated with `@Size(max = 280)`, which ensures that if a reason is provided, it does not exceed 280 characters. This validation is performed by Jakarta Bean Validation when the request is processed.

## Usage

This record is typically used in a controller method that handles participant expulsion. For example:

```java
@PostMapping("/expel")
public ResponseEntity<Void> expelParticipant(@Valid @RequestBody ExpelParticipantRequest request) {
    // Process the expulsion
}
```

## Example

```java
// Valid request with a reason
ExpelParticipantRequest request = new ExpelParticipantRequest("Violated community guidelines");

// Valid request without a reason
ExpelParticipantRequest request = new ExpelParticipantRequest(null);

// Invalid request (reason too long)
ExpelParticipantRequest request = new ExpelParticipantRequest("A".repeat(281)); // Will fail validation
```

## Notes

- The record is immutable, meaning once created, its values cannot be changed.
- The `reason` field is optional; if not provided, it will be `null`.
- Validation is handled by the Jakarta Bean Validation framework, typically triggered by the `@Valid` annotation in the controller.
