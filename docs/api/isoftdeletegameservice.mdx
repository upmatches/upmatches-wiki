# ISoftDeleteGameService Interface

The `ISoftDeleteGameService` interface defines a contract for soft-deleting a game entity within the application. Soft deletion marks a record as deleted without physically removing it from the database, allowing for potential recovery or audit trails.

This interface is a **sealed interface**, meaning it restricts which classes or interfaces can implement it. In this case, only `SoftDeleteGameService` is permitted to implement this interface.

## Purpose

- Provides a standardized method for performing soft deletion operations on game entities.
- Ensures that any implementation follows the same contract, promoting consistency across the codebase.
- The sealed nature enforces controlled extension, limiting implementation to a single designated service class.

## Method Summary

| Method | Description |
|--------|-------------|
| `void execute(UUID id)` | Executes the soft deletion of a game identified by the provided UUID. |

## Method Details

### `execute(UUID id)`

- **Description**: Initiates the soft deletion process for a game with the specified unique identifier. The implementation should mark the game as deleted in the data store without removing the record.
- **Parameters**:
  - `id` (`UUID`): The unique identifier of the game to be soft-deleted.
- **Returns**: `void` — no return value.
- **Throws**: Implementation-specific exceptions may be thrown (e.g., if the game is not found or the operation fails).

## Usage Example

```java
// Assuming an instance of SoftDeleteGameService is injected
ISoftDeleteGameService softDeleteService = new SoftDeleteGameService();
UUID gameId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
softDeleteService.execute(gameId);
```

## Implementation Notes

- The interface is sealed, so only `SoftDeleteGameService` can implement it. This design choice helps maintain a single source of truth for soft deletion logic.
- The `execute` method is intentionally simple, focusing on the action rather than return values or complex parameters.
- Consider adding validation or error handling in the implementing class to handle cases where the game ID does not exist.

## Related Components

- **SoftDeleteGameService**: The sole permitted implementation of this interface, containing the actual soft deletion logic.
- **Game Entity**: The domain object that will be soft-deleted, typically containing a `deletedAt` or `isDeleted` field.
