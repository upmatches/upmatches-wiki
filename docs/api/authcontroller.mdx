# AuthController

The `AuthController` class is a Spring REST controller that handles all authentication-related endpoints for the UpMatches application. It provides endpoints for logging in via Singpass, Auth0, and Apple, as well as token refresh and logout functionality.

## Purpose

This controller serves as the main entry point for authentication operations, managing the complete authentication lifecycle including:
- Initiating OAuth2/OIDC login flows for Singpass and Auth0
- Handling Apple Sign-In
- Token refresh and rotation
- Session logout and token revocation

## Dependencies

The controller depends on several service interfaces for authentication operations:

| Dependency | Type | Purpose |
|------------|------|---------|
| `ISingpassAuthService` | Service | Handles Singpass authentication via PAR (Pushed Authorization Request) |
| `IAuth0AuthService` | Service | Manages Auth0 authentication flows |
| `IAppleLoginService` | Service | Processes Apple Sign-In requests |
| `IAuthSessionStore` | Service | Stores authentication session data (state, nonce, code verifier) |
| `IJwtTokenService` | Service | Generates and manages JWT access tokens |
| `IRefreshTokenStore` | Service | Manages refresh token storage, validation, and rotation |
| `UserRepository` | Repository | Accesses user data from the database |
| `ICookieHelper` | Service | Manages HTTP cookies for token storage |

## Endpoints

### Singpass Login

Initiates the Singpass authentication flow using Pushed Authorization Request (PAR).

**Endpoint:** `GET /api/v1/auth/login/singpass`

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | String | No | Platform identifier. If "mobile", returns authorization URL in response body instead of redirect |

**Response:**

| Status | Description |
|--------|-------------|
| `200 OK` | Mobile platform: Returns `AuthorizationUrlResponse` with the authorization URL |
| `302 Found` | Web platform: Redirects to the Singpass authorization URL |
| `500 Internal Server Error` | If PAR request fails, throws `AuthenticationException` |

**Example Response (Mobile):**
```json
{
  "success": true,
  "data": {
    "authorizationUrl": "https://singpass.gov.sg/authorize?state=..."
  },
  "message": "Authorization URL generated.",
  "path": "/api/v1/auth/login/singpass"
}
```

### Auth0 Login

Initiates the Auth0 authentication flow with optional provider connection.

**Endpoint:** `GET /api/v1/auth/login/auth0`

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | String | No | Platform identifier. If "mobile", returns authorization URL in response body |
| `provider` | String | No | Auth0 connection provider (e.g., "google", "facebook"). Must be a valid `Auth0Connection` |

**Response:**

| Status | Description |
|--------|-------------|
| `200 OK` | Mobile platform: Returns `AuthorizationUrlResponse` with the authorization URL |
| `302 Found` | Web platform: Redirects to the Auth0 authorization URL |
| `400 Bad Request` | If provider is invalid, throws `InvalidAuthRequestException` |

**Example Response (Mobile):**
```json
{
  "success": true,
  "data": {
    "authorizationUrl": "https://auth0.com/authorize?state=..."
  },
  "message": "Authorization URL generated.",
  "path": "/api/v1/auth/login/auth0"
}
```

### Apple Login

Processes Apple Sign-In authentication.

**Endpoint:** `POST /api/v1/auth/login/apple`

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `identityToken` | String | Yes | Apple identity token |
| `authorizationCode` | String | Yes | Apple authorization code |
| `user` | String | No | Apple user identifier |

**Response:**

| Status | Description |
|--------|-------------|
| `200 OK` | Returns `AppleLoginResponse` with authentication result |
| `400 Bad Request` | If request body validation fails |

**Example Response:**
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "rt_abc123...",
    "expiresAt": "2024-01-01T00:00:00Z"
  },
  "message": "Signed in with Apple.",
  "path": "/api/v1/auth/login/apple"
}
```

### Token Refresh

Refreshes an expired access token using a refresh token.

**Endpoint:** `POST /api/v1/auth/refresh`

**Request Body (Optional):**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `refreshToken` | String | No | Refresh token (required for mobile; web uses cookies) |

**Response:**

| Status | Description |
|--------|-------------|
| `200 OK` | Returns new access token and rotated refresh token |
| `400 Bad Request` | If refresh token is missing |
| `401 Unauthorized` | If refresh token is invalid or revoked |

**Example Response (Mobile):**
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "refreshToken": "rt_new123...",
    "expiresAt": "2024-01-01T00:00:00Z"
  },
  "message": "Token refreshed successfully.",
  "path": "/api/v1/auth/refresh"
}
```

### Logout

Logs out the user by revoking all refresh tokens and clearing authentication cookies.

**Endpoint:** `POST /api/v1/auth/logout`

**Response:**

| Status | Description |
|--------|-------------|
| `200 OK` | Logout successful |

**Example Response:**
```json
{
  "success": true,
  "data": null,
  "message": "Logged out successfully.",
  "path": "/api/v1/auth/logout"
}
```

## Error Handling

The controller throws the following custom exceptions:

| Exception | HTTP Status | Description |
|-----------|-------------|-------------|
| `AuthenticationException` | 500 | Generic authentication failure |
| `InvalidAuthRequestException` | 400 | Invalid request parameters |
| `InvalidRefreshTokenException` | 401 | Invalid or revoked refresh token |

## Security Considerations

1. **State Parameter**: Each login request generates a unique state parameter to prevent CSRF attacks
2. **Nonce**: A nonce is generated for each authentication request to prevent replay attacks
3. **Code Verifier**: PKCE (Proof Key for Code Exchange) is used for secure authorization code exchange
4. **Token Rotation**: Refresh tokens are rotated on each use to limit exposure
5. **Cookie Security**: Authentication tokens are stored in HTTP-only cookies for web clients

## Implementation Details

### Session Management

The controller stores authentication sessions using the `IAuthSessionStore` service, which maps state parameters to `AuthSession` objects containing:
- State
- Nonce
- Code Verifier
- Platform identifier

### Token Generation

Access tokens are generated using the `IJwtTokenService` with user identifiers from multiple authentication providers (Singpass UUID, Auth0 UUID, Apple UUID).

### Refresh Token Flow

1. Extract refresh token from request body (mobile) or cookies (web)
2. Validate and rotate the refresh token using `IRefreshTokenStore`
3. Look up the user associated with the refresh token
4. Generate a new access token
5. Return new tokens or set cookies based on platform
