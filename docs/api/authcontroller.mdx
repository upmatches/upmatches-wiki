# AuthController

The `AuthController` class is a REST controller that handles authentication-related endpoints for the UpMatches application. It provides endpoints for logging in via Singpass, Auth0, and Apple, as well as token refresh and logout functionality. The controller delegates authentication logic to various service interfaces and manages session state, tokens, and cookies.

## Endpoints

### GET /api/v1/auth/login/singpass

Initiates Singpass authentication by generating a Pushed Authorization Request (PAR) and returning an authorization URL.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | `String` | No | Platform identifier (e.g., "mobile"). If "mobile", returns the authorization URL in the response body; otherwise, redirects to the URL. |

**Response:** Returns an `AuthorizationUrlResponse` containing the authorization URL, or a 302 redirect to the URL.

**Throws:** `AuthenticationException` if the PAR request fails.

### GET /api/v1/auth/login/auth0

Initiates Auth0 authentication and returns an authorization URL.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | `String` | No | Platform identifier (e.g., "mobile"). If "mobile", returns the authorization URL in the response body; otherwise, redirects to the URL. |
| `provider` | `String` | No | Auth0 connection provider name. If provided, must be a valid `Auth0Connection`. |

**Response:** Returns an `AuthorizationUrlResponse` containing the authorization URL, or a 302 redirect to the URL.

**Throws:** `InvalidAuthRequestException` if the provider is unsupported.

### POST /api/v1/auth/login/apple

Handles Apple Sign-In with the provided credentials.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | `AppleLoginRequest` | Yes | The Apple login request payload. |

**Response:** Returns an `AppleLoginResponse` with the authentication result.

### POST /api/v1/auth/refresh

Refreshes an authentication token. Supports both mobile (request body) and web (cookie) refresh token delivery.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | `RefreshRequest` | No | Optional request body containing the refresh token (used for mobile clients). |

**Response:** Returns a `TokenResponse` containing the new access token, refresh token, and expiration time for mobile clients. For web clients, sets new cookies and returns a success response.

**Throws:** `InvalidAuthRequestException` if no refresh token is provided. `InvalidRefreshTokenException` if the refresh token is invalid or revoked.

### POST /api/v1/auth/logout

Logs out the current user by revoking all refresh tokens and clearing authentication cookies.

**Response:** Returns a success response indicating the user has been logged out.

## Dependencies

The controller depends on the following service interfaces:

| Service | Description |
|---------|-------------|
| `ISingpassAuthService` | Handles Singpass authentication flows |
| `IAuth0AuthService` | Handles Auth0 authentication flows |
| `IAppleLoginService` | Handles Apple Sign-In |
| `IAuthSessionStore` | Manages authentication session state |
| `IJwtTokenService` | Generates and manages JWT access tokens |
| `IRefreshTokenStore` | Manages refresh token storage and validation |
| `UserRepository` | Data access for user entities |
| `ICookieHelper` | Manages HTTP cookies for authentication tokens |

## Error Handling

The controller throws the following custom exceptions:

| Exception | Description |
|-----------|-------------|
| `AuthenticationException` | Thrown when authentication fails (e.g., Singpass PAR failure) |
| `InvalidAuthRequestException` | Thrown when the authentication request is malformed (e.g., missing refresh token, unsupported provider) |
| `InvalidRefreshTokenException` | Thrown when the refresh token is invalid or has been revoked |
