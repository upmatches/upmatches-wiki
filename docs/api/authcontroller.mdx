# AuthController

The `AuthController` class is a Spring REST controller that handles all authentication-related endpoints for the UpMatches application. It provides endpoints for logging in via Singpass, Auth0, and Apple, as well as token refresh and logout functionality.

## Purpose

This controller serves as the central authentication gateway, managing:
- **Singpass Login**: Initiates the Singpass authentication flow using PAR (Pushed Authorization Request)
- **Auth0 Login**: Handles Auth0-based authentication with support for multiple providers
- **Apple Login**: Processes Sign in with Apple requests
- **Token Refresh**: Manages access token refresh using refresh tokens
- **Logout**: Handles user logout and token revocation

## Dependencies

The controller relies on several service interfaces for its operations:

| Service | Purpose |
|---------|---------|
| `ISingpassAuthService` | Handles Singpass authentication flow |
| `IAuth0AuthService` | Manages Auth0 authentication |
| `IAppleLoginService` | Processes Apple Sign In |
| `IAuthSessionStore` | Stores authentication session data |
| `IJwtTokenService` | Generates and manages JWT tokens |
| `IRefreshTokenStore` | Manages refresh token storage and validation |
| `UserRepository` | Accesses user data from the database |
| `ICookieHelper` | Manages HTTP cookies for token storage |

## Endpoints

### Singpass Login

Initiates the Singpass authentication flow.

**Endpoint:** `GET /api/v1/auth/login/singpass`

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | String | No | Platform identifier (e.g., "mobile") |
| `request` | HttpServletRequest | Yes | HTTP request object |

**Returns:** 
- For mobile platforms: `ResponseEntity<Object>` with authorization URL in response body
- For web platforms: HTTP 302 redirect to the authorization URL

**Throws:** `AuthenticationException` if PAR request fails

### Auth0 Login

Initiates the Auth0 authentication flow.

**Endpoint:** `GET /api/v1/auth/login/auth0`

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `platform` | String | No | Platform identifier (e.g., "mobile") |
| `provider` | String | No | Auth0 provider name |
| `request` | HttpServletRequest | Yes | HTTP request object |

**Returns:**
- For mobile platforms: `ResponseEntity<Object>` with authorization URL in response body
- For web platforms: HTTP 302 redirect to the authorization URL

**Throws:** `InvalidAuthRequestException` if provider is unsupported

### Apple Login

Processes Sign in with Apple authentication.

**Endpoint:** `POST /api/v1/auth/login/apple`

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | AppleLoginRequest | Yes | Apple login request payload |
| `request` | HttpServletRequest | Yes | HTTP request object |

**Returns:** `ResponseEntity<Object>` with Apple login response

### Token Refresh

Refreshes an access token using a refresh token.

**Endpoint:** `POST /api/v1/auth/refresh`

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | RefreshRequest | No | Refresh token request body (required for mobile) |
| `request` | HttpServletRequest | Yes | HTTP request object |
| `response` | HttpServletResponse | Yes | HTTP response object |

**Returns:** `ResponseEntity<Object>` with new token data

**Throws:**
- `InvalidAuthRequestException` if refresh token is missing
- `InvalidRefreshTokenException` if refresh token is invalid or revoked

### Logout

Logs out the current user and revokes all refresh tokens.

**Endpoint:** `POST /api/v1/auth/logout`

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `request` | HttpServletRequest | Yes | HTTP request object |
| `response` | HttpServletResponse | Yes | HTTP response object |

**Returns:** `ResponseEntity<Object>` with success message

## Internal Methods

### `generateState()`

Generates a unique state string for CSRF protection.

**Returns:** String - A UUID without hyphens

### `doRefresh()`

Handles the token refresh logic, supporting both mobile (request body) and web (cookie) refresh token delivery.

### `throwInvalidRefreshToken()`

Creates and throws an `InvalidRefreshTokenException`, clearing auth cookies for web clients.

### `doLogout()`

Handles the logout logic, revoking all refresh tokens for the user and clearing cookies.

## Error Handling

The controller uses custom exceptions for error handling:

| Exception | Description |
|-----------|-------------|
| `AuthenticationException` | General authentication failure |
| `InvalidAuthRequestException` | Invalid authentication request parameters |
| `InvalidRefreshTokenException` | Invalid or revoked refresh token |

## Security Considerations

- Uses state and nonce parameters for CSRF protection
- Implements PKCE (Proof Key for Code Exchange) via code verifier
- Supports token rotation for refresh tokens
- Clears authentication cookies on logout and invalid token scenarios
- Validates provider names against `Auth0Connection` enum
