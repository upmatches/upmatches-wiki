# IMarkAllReadService Interface

The `IMarkAllReadService` interface defines a contract for marking all notifications as read within the notification system of the UpMatches application. It serves as the abstraction layer for the "mark all read" functionality, allowing different implementations to be swapped in without affecting the calling code.

This interface is declared as a **sealed interface**, meaning only explicitly permitted classes (in this case, `MarkAllReadService`) can implement it. This design pattern ensures controlled inheritance and provides compile-time safety by restricting the set of possible implementations.

## Interface Definition

```java
public sealed interface IMarkAllReadService permits MarkAllReadService {
    Integer execute();
}
```

## Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `execute()` | `Integer` | Executes the operation to mark all notifications as read. Returns the number of notifications that were updated. |

## Usage

The `IMarkAllReadService` interface is typically injected into controllers or other services that need to trigger a bulk "mark all read" operation. The concrete implementation `MarkAllReadService` handles the actual database or repository logic.

### Example

```java
// Inject the service
private final IMarkAllReadService markAllReadService;

// Use it in a method
public void markAllNotificationsAsRead() {
    Integer updatedCount = markAllReadService.execute();
    // Handle the result (e.g., log, return response)
}
```

## Sealed Interface Details

- **Permitted Implementations**: `MarkAllReadService`
- **Purpose**: Restricts implementation to a single, known class, ensuring that the behavior is predictable and controlled.
- **Benefits**: 
  - Compile-time safety against unauthorized implementations
  - Clear documentation of allowed subtypes
  - Enables exhaustive pattern matching in future Java versions
