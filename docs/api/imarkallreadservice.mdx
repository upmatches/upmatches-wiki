# IMarkAllReadService

The `IMarkAllReadService` is a sealed interface that defines a contract for marking all notifications as read within the notification system of the UpMatches application. It serves as the abstraction layer for the `MarkAllReadService` implementation, ensuring a single, well-defined entry point for this operation.

## Purpose

This interface is designed to encapsulate the logic required to mark all user notifications as read. By using a sealed interface, the design enforces that only the permitted implementation (`MarkAllReadService`) can fulfill this contract, providing compile-time safety and clear architectural boundaries.

## Interface Definition

```java
public sealed interface IMarkAllReadService permits MarkAllReadService {
    Integer execute();
}
```

## Methods

### `execute()`

Executes the operation to mark all notifications as read and returns the number of notifications that were updated.

| Return Type | Description |
|-------------|-------------|
| `Integer`   | The count of notifications that were successfully marked as read. |

## Usage Example

```java
// Assuming dependency injection provides the implementation
IMarkAllReadService markAllReadService = new MarkAllReadService();
Integer updatedCount = markAllReadService.execute();
System.out.println("Marked " + updatedCount + " notifications as read.");
```

## Implementation Notes

- The interface is **sealed**, meaning only the class `MarkAllReadService` is allowed to implement it.
- The `execute()` method returns an `Integer` representing the number of affected records, which can be used for confirmation or logging purposes.
- This design promotes a clean separation of concerns and makes the service easily testable by allowing mock implementations in unit tests (though the sealed nature restricts this to the permitted class).
