# JwtProperties

The `JwtProperties` class is a Spring Boot configuration properties record that maps to the `app.jwt` prefix in your application properties file. It centralizes all JWT-related configuration, including token expiration times, issuer/audience values, and callback URLs for authentication flows.

## Purpose

This record provides a type-safe and validated way to manage JWT configuration parameters. It automatically applies sensible defaults for optional fields and performs validation on critical values like the frontend callback URL. By using Spring Boot's `@ConfigurationProperties`, it seamlessly integrates with your application's property sources (e.g., `application.yml`, environment variables).

## Configuration Properties

The following table describes each property that can be configured under the `app.jwt` prefix:

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `issuer` | String | `"upmatches"` | The JWT issuer claim (`iss`). Defaults to `"upmatches"` if blank. |
| `audience` | String | `"upmatches"` | The JWT audience claim (`aud`). Defaults to `"upmatches"` if blank. |
| `accessTokenExpiryMinutes` | Integer | `15` | Access token expiration time in minutes. Must be positive; defaults to 15 if not provided or invalid. |
| `refreshTokenExpiryDays` | Integer | `7` | Refresh token expiration time in days. Must be positive; defaults to 7 if not provided or invalid. |
| `frontendCallbackUrl` | String | **Required** | The callback URL for the frontend after authentication. Must be a valid URI and cannot be blank. |
| `mobileCallbackScheme` | String | `"upmatches"` | The custom URL scheme for mobile app callbacks. Defaults to `"upmatches"` if blank. |

## Constructor Validation

The compact constructor performs the following validations and default assignments:

1. **Blank String Handling**: `issuer`, `audience`, and `mobileCallbackScheme` default to `"upmatches"` if null or blank.
2. **Positive Integer Enforcement**: `accessTokenExpiryMinutes` and `refreshTokenExpiryDays` default to their respective constants (`15` and `7`) if null or non-positive.
3. **URI Validation**: `frontendCallbackUrl` is validated as a proper URI. An `IllegalArgumentException` is thrown if the URL is blank or malformed.

## Usage Example

To use this configuration in your application, add the following to your `application.yml` or `application.properties`:

```yaml
app:
  jwt:
    issuer: my-app
    audience: my-app-users
    access-token-expiry-minutes: 30
    refresh-token-expiry-days: 14
    frontend-callback-url: https://example.com/auth/callback
    mobile-callback-scheme: myapp
```

Then inject the properties into your services:

```java
@Service
public class JwtService {
    private final JwtProperties jwtProperties;

    public JwtService(JwtProperties jwtProperties) {
        this.jwtProperties = jwtProperties;
    }

    public void generateToken() {
        // Use jwtProperties.issuer(), jwtProperties.accessTokenExpiryMinutes(), etc.
    }
}
```

## Error Handling

The constructor throws `IllegalArgumentException` in the following cases:

- `frontendCallbackUrl` is null or blank
- `frontendCallbackUrl` is not a valid URI (e.g., malformed syntax)

All other fields have safe defaults, making the configuration resilient to missing or invalid values.
