# IGameAuthorizationService

The `IGameAuthorizationService` interface defines a contract for authorization and access control operations related to game entities within the application. It serves as a centralized authorization layer that enforces business rules and security constraints before allowing operations on games.

This interface is declared as a **sealed interface**, meaning only the `GameAuthorizationService` class is permitted to implement it. This design ensures that all authorization logic is contained within a single, well-defined implementation.

## Interface Definition

```java
public sealed interface IGameAuthorizationService permits GameAuthorizationService
```

## Methods

| Method | Description | Parameters |
|--------|-------------|------------|
| `assertCanViewGame` | Verifies that the specified user has permission to view the given game. | `Game game` - The game to check access for<br/>`UUID userId` - The unique identifier of the user |
| `assertIsOrganizer` | Ensures the specified user is the organizer of the given game. | `Game game` - The game to check<br/>`UUID userId` - The unique identifier of the user |
| `assertGameJoinable` | Validates that the game with the given ID is open for new players to join. | `UUID id` - The unique identifier of the game<br/>`Game game` - The game entity to check |
| `assertPrivateAccess` | Checks that the user has proper authorization to access a private game. | `UUID id` - The unique identifier of the game<br/>`UUID userId` - The unique identifier of the user<br/>`Game game` - The game entity to check |
| `assertNotAlreadyJoined` | Verifies that the user has not already joined the specified game. | `UUID id` - The unique identifier of the game<br/>`UUID userId` - The unique identifier of the user |
| `assertVisibilityUnchanged` | Ensures that the visibility setting of the game remains unchanged in the update request. | `UUID id` - The unique identifier of the game<br/>`Game game` - The current game entity<br/>`UpdateGameRequest request` - The update request containing proposed changes |
| `assertSlotsAboveActive` | Validates that the new number of slots is greater than or equal to the current active player count. | `UUID id` - The unique identifier of the game<br/>`Integer newSlots` - The proposed new slot count<br/>`long activeCount` - The current number of active players |
| `assertImmutableFields` | Performs a comprehensive check to ensure that immutable fields are not being modified in the update request. | `UUID id` - The unique identifier of the game<br/>`Game game` - The current game entity<br/>`UpdateGameRequest request` - The update request containing proposed changes<br/>`long activeCount` - The current number of active players |

## Usage Notes

- All methods throw appropriate exceptions when authorization checks fail, typically `IllegalArgumentException` or custom exception types.
- The interface follows a **fail-fast** pattern, where authorization checks are performed before any business logic executes.
- The `assertImmutableFields` method serves as a composite check that may internally call other assertion methods like `assertVisibilityUnchanged` and `assertSlotsAboveActive`.
- Each method accepts the game's UUID (`id`) as a parameter for logging and error reporting purposes, even when the game entity itself is also provided.
