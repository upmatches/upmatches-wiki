# TracingMdcFilter

The `TracingMdcFilter` is a Spring Boot servlet filter that automatically injects distributed tracing identifiers (Trace ID and Span ID) into the **Mapped Diagnostic Context (MDC)** of SLF4J. This enables structured logging where every log entry produced during a request can be correlated with its corresponding trace and span in a distributed tracing system (e.g., Zipkin, Jaeger).

By placing the filter at the highest precedence, it ensures that trace and span IDs are available in the MDC for the entire duration of the HTTP request, and are cleaned up immediately after the response is processed.

## Key Features

- **Automatic MDC Injection**: Extracts the current trace and span IDs from Micrometer Tracing and adds them to the SLF4J MDC.
- **Once-Per-Request Execution**: Extends `OncePerRequestFilter` to guarantee the filter logic runs exactly once per request, even if the filter is mapped multiple times.
- **Conditional Activation**: Only activates when a `Tracer` bean is present in the application context (via `@ConditionalOnBean(Tracer.class)`).
- **High Priority**: Runs at `Ordered.HIGHEST_PRECEDENCE + 10` to ensure tracing context is available before other filters.
- **Automatic Cleanup**: Removes MDC entries in a `finally` block to prevent memory leaks and context pollution across requests.

## Constants

| Constant | Value | Description |
|----------|-------|-------------|
| `MDC_TRACE_ID` | `"traceId"` | MDC key used to store the current trace ID. |
| `MDC_SPAN_ID` | `"spanId"` | MDC key used to store the current span ID. |

## Constructor

| Constructor | Description |
|-------------|-------------|
| `TracingMdcFilter(Tracer tracer)` | Creates a new filter instance with the provided Micrometer Tracing `Tracer`. The tracer is used to obtain the current span for each request. |

## Public Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `doFilterInternal(HttpServletRequest, HttpServletResponse, FilterChain)` | `void` | Core filter logic. Retrieves the current span from the tracer, injects its trace and span IDs into the MDC, proceeds with the filter chain, and removes the MDC entries in the `finally` block. |

## Usage Example

### Logback Configuration

To include the trace and span IDs in your log output, configure your Logback pattern to reference the MDC keys:

```xml
<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder>
        <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - [%X{traceId},%X{spanId}] %msg%n</pattern>
    </encoder>
</appender>
```

### Sample Log Output

```
2025-04-10 14:23:45.123 [http-nio-8080-exec-1] INFO  com.example.MyService - [abc123def456,ghi789jkl012] Processing user request
```

## Dependencies

- **Micrometer Tracing**: Provides the `Tracer` and `Span` APIs for distributed tracing.
- **Jakarta Servlet API**: Required for the servlet filter infrastructure.
- **SLF4J**: Used for the MDC (Mapped Diagnostic Context) API.
- **Spring Boot**: Provides auto-configuration and conditional bean support.

## Notes

- The filter is automatically registered as a Spring bean due to the `@Component` annotation.
- It will only be created if a `Tracer` bean is available in the application context, making it safe to include in projects that may or may not have tracing enabled.
- The `@Order(Ordered.HIGHEST_PRECEDENCE + 10)` annotation ensures this filter runs very early in the filter chain, but still allows for any absolutely critical filters (e.g., security) to run before it if needed.
- MDC cleanup is guaranteed via the `finally` block, preventing trace context from leaking into subsequent requests processed by the same thread.
