# ViewerJoinabilityResponse

The `ViewerJoinabilityResponse` record encapsulates the result of a viewer's ability to join a game session. It provides a structured response containing a boolean flag indicating whether joining is permitted, an optional reason for denial, and a list of any warnings associated with the join attempt.

This record is designed to be immutable and thread-safe, leveraging Java's `record` feature for concise data carrier semantics.

## Purpose

- **Determine Joinability**: Clearly indicates whether a viewer can join a game (`canJoin`).
- **Provide Context**: When joining is blocked, the `reason` field explains why (e.g., game full, region restriction).
- **Surface Warnings**: The `warnings` list communicates non-blocking issues that the viewer should be aware of (e.g., latency concerns, missing features).

## Usage Examples

```java
// Viewer can join with latency warning
ViewerJoinabilityResponse allowed = ViewerJoinabilityResponse.allowed(
    List.of(JoinabilityWarning.HIGH_LATENCY)
);

// Viewer cannot join because game is full
ViewerJoinabilityResponse blocked = ViewerJoinabilityResponse.blocked(
    JoinabilityReason.GAME_FULL,
    List.of(JoinabilityWarning.REGION_MISMATCH)
);
```

## Important Notes

- The `warnings` list is always defensively copied and made unmodifiable via `List.copyOf()`. This ensures immutability and prevents external modification.
- If `null` is passed for `warnings`, it is safely converted to an empty list.
- The `reason` field should only be non-null when `canJoin` is `false`. The factory methods enforce this contract.
