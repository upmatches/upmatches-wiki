# AsyncConfiguration

The `AsyncConfiguration` class is a Spring configuration component that sets up asynchronous task execution and scheduling capabilities within the application. It enables Spring's `@Async` and `@Scheduled` annotations to work by providing a custom `ThreadPoolTaskExecutor` bean.

## Purpose

This configuration ensures that methods annotated with `@Async` are executed in a separate thread pool rather than the main request thread, improving application responsiveness and scalability. It also enables scheduled task execution via `@Scheduled` annotations.

## Configuration Details

The class defines a thread pool executor with the following characteristics:

| Property | Value | Description |
|----------|-------|-------------|
| Core Pool Size | 4 | Minimum number of threads kept alive in the pool |
| Max Pool Size | 8 | Maximum number of threads allowed in the pool |
| Queue Capacity | 100 | Maximum number of tasks that can be queued before new threads are created |
| Thread Name Prefix | `async-` | Prefix for thread names (e.g., `async-1`, `async-2`) |

## Public Methods

### `taskExecutor()`

Creates and configures a `ThreadPoolTaskExecutor` bean that manages asynchronous task execution.

| Aspect | Details |
|--------|---------|
| **Bean Name** | `taskExecutor` |
| **Return Type** | `java.util.concurrent.Executor` |
| **Description** | Returns a fully configured thread pool executor for handling async tasks |

## Usage

To use this configuration in your application:

1. **For asynchronous methods**: Annotate any service method with `@Async` to execute it in the configured thread pool.

```java
@Service
public class EmailService {
    @Async
    public void sendEmail(String recipient, String message) {
        // This runs in the async thread pool
    }
}
```

2. **For scheduled tasks**: Annotate methods with `@Scheduled` to run them on a schedule.

```java
@Component
public class ReportGenerator {
    @Scheduled(cron = "0 0 8 * * ?")
    public void generateDailyReport() {
        // This runs on the scheduled timer
    }
}
```

## Thread Pool Behavior

The thread pool follows this execution flow:

1. When a task is submitted, if the number of active threads is less than `corePoolSize`, a new thread is created.
2. If all core threads are busy, the task is placed in the queue (up to `queueCapacity`).
3. If the queue is full and the number of active threads is less than `maxPoolSize`, a new thread is created.
4. If the queue is full and all `maxPoolSize` threads are busy, the task is rejected (default behavior throws `RejectedExecutionException`).

## Dependencies

- Spring Framework (for `@Configuration`, `@EnableAsync`, `@EnableScheduling`)
- Spring Scheduling (for `ThreadPoolTaskExecutor`)
