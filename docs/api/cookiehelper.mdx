# CookieHelper

The `CookieHelper` class is a Spring `@Service` component responsible for managing authentication-related HTTP cookies in a web application. It implements the `ICookieHelper` interface and provides methods to set, clear, and retrieve authentication tokens (access token, refresh token, and token expiry) as secure, HTTP-only cookies.

This helper is designed to work with JWT-based authentication, leveraging `JwtProperties` for token expiry configurations. It ensures cookies are set with appropriate security attributes (HttpOnly, Secure, SameSite) based on the request context.

## Key Features

- **Secure Cookie Management**: Automatically sets `Secure` flag based on request protocol (HTTPS).
- **HttpOnly Protection**: Access and refresh tokens are HttpOnly to prevent XSS attacks.
- **SameSite Strict**: All cookies use `SameSite=Strict` for CSRF protection.
- **JS-Readable Expiry**: A non-HttpOnly `tokenExpiry` cookie allows the SPA to know when the access token expires.
- **Token Cleanup**: Provides a method to clear all authentication cookies (e.g., on logout).

## Public Methods

### `setAuthCookies(HttpServletResponse response, HttpServletRequest request, TokenData tokenData)`

Sets three authentication cookies on the HTTP response:

| Parameter | Type | Description |
|-----------|------|-------------|
| `response` | `HttpServletResponse` | The HTTP response to add cookies to |
| `request` | `HttpServletRequest` | The HTTP request (used to determine if connection is secure) |
| `tokenData` | `TokenData` | Contains access token, refresh token, and expiry timestamp |

**Cookies Set:**
- `accessToken` - HttpOnly, Secure, SameSite=Strict, path=/, maxAge = accessTokenExpiryMinutes
- `refreshToken` - HttpOnly, Secure, SameSite=Strict, path=/, maxAge = refreshTokenExpiryDays
- `tokenExpiry` - **Not HttpOnly** (JS-readable), Secure, SameSite=Strict, path=/, maxAge = accessTokenExpiryMinutes

### `clearAuthCookies(HttpServletResponse response, HttpServletRequest request)`

Clears all three authentication cookies by setting their values to empty and maxAge to 0.

| Parameter | Type | Description |
|-----------|------|-------------|
| `response` | `HttpServletResponse` | The HTTP response to clear cookies from |
| `request` | `HttpServletRequest` | The HTTP request (used to determine if connection is secure) |

### `getRefreshTokenFromCookie(HttpServletRequest request)`

Retrieves the refresh token value from the request cookies.

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The HTTP request containing cookies |

**Returns:** `String` - The refresh token value, or `null` if not found.

## Inner Record: `TokenData`

A simple data carrier record used to pass token information to the `setAuthCookies` method.

| Field | Type | Description |
|-------|------|-------------|
| `accessToken` | `String` | The JWT access token |
| `expiresAtUtc` | `Long` | Unix timestamp (seconds) when the access token expires |
| `refreshToken` | `String` | The JWT refresh token |

## Dependencies

- `JwtProperties` - Configuration properties for JWT token expiry durations
- `ICookieHelper` - Interface contract for cookie operations
- Spring Framework `HttpServletRequest`, `HttpServletResponse`, `ResponseCookie`, `HttpHeaders`

## Usage Example

```java
// Inject the service
@Autowired
private CookieHelper cookieHelper;

// Setting cookies after successful authentication
TokenData tokenData = new TokenData(
    "eyJhbGciOiJIUzI1NiIs...",  // access token
    1700000000L,                   // expires at UTC
    "dGhpcyBpcyBhIHJlZnJl...",   // refresh token
);
cookieHelper.setAuthCookies(response, request, tokenData);

// Retrieving refresh token on subsequent requests
String refreshToken = cookieHelper.getRefreshTokenFromCookie(request);

// Clearing cookies on logout
cookieHelper.clearAuthCookies(response, request);
```

## Security Considerations

- The `tokenExpiry` cookie is intentionally **not HttpOnly** (marked with `NOSONAR S3330`) so that client-side JavaScript can read the expiry timestamp and proactively refresh the access token before it expires.
- All cookies use `SameSite=Strict` to prevent CSRF attacks.
- The `Secure` flag is dynamically set based on whether the incoming request uses HTTPS.
- Access and refresh tokens are always HttpOnly, preventing JavaScript from accessing them directly.
