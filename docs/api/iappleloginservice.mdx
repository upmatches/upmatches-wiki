# IAppleLoginService Interface

The `IAppleLoginService` interface defines the contract for Apple Sign-In authentication within the UpMatches application. It follows a sealed interface pattern to restrict implementation to only the `AppleLoginService` class, ensuring controlled and secure Apple authentication logic.

## Purpose

This interface serves as the abstraction layer for Apple login operations. By using a sealed interface, the design enforces that only the designated `AppleLoginService` can implement this contract, preventing unauthorized implementations and maintaining a clear, single-responsibility authentication flow.

## Interface Definition

```java
public sealed interface IAppleLoginService permits AppleLoginService {
    AppleLoginResponse execute(AppleLoginRequest request);
}
```

## Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `execute(AppleLoginRequest request)` | `AppleLoginResponse` | Processes an Apple login request and returns the authentication response. This is the single entry point for Apple Sign-In operations. |

## Parameters

### `execute` Method

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `AppleLoginRequest` | Contains the necessary data for Apple authentication, such as identity token, authorization code, or user information from Apple's Sign-In flow. |

## Return Type

| Type | Description |
|------|-------------|
| `AppleLoginResponse` | Encapsulates the result of the Apple login operation, including authentication tokens, user profile data, and any error information. |

## Usage Example

```java
// The interface is typically injected and used through dependency injection
public class AuthController {
    private final IAppleLoginService appleLoginService;
    
    public AuthController(IAppleLoginService appleLoginService) {
        this.appleLoginService = appleLoginService;
    }
    
    public AppleLoginResponse handleAppleLogin(AppleLoginRequest request) {
        return appleLoginService.execute(request);
    }
}
```

## Implementation Constraints

- The interface is **sealed**, meaning only the `AppleLoginService` class can implement it.
- Any attempt to create another implementation will result in a compilation error.
- This design ensures that Apple authentication logic remains centralized and consistent across the application.

## Related Components

- **`AppleLoginRequest`**: Input data transfer object for Apple login credentials.
- **`AppleLoginResponse`**: Output data transfer object containing authentication results.
- **`AppleLoginService`**: The sole implementation class that contains the actual Apple authentication logic.
