## Purpose

The `ListGamesCursorService` class is a service in a Java application that provides functionality to list games with cursor-based pagination. It is designed to handle complex filtering and querying of game data, including location-based filtering, date and time constraints, and user-specific visibility. The service ensures efficient retrieval of game data while maintaining transactional integrity and handling user-specific joinability logic.

## Public Methods

### `execute`

Executes the service operation to retrieve a paginated list of games based on the provided filter, cursor, and size.

| Parameter | Type                               | Description                                                                 |
|-----------|------------------------------------|-----------------------------------------------------------------------------|
| `filter`  | `ListGamesCursorFilterRequest`     | The filter criteria for querying games.                                     |
| `cursor`  | `String`                           | The cursor for pagination, indicating the starting point for the next page. |
| `size`    | `int`                              | The maximum number of games to retrieve.                                    |

| Return Type                          | Description                                                                 |
|--------------------------------------|-----------------------------------------------------------------------------|
| `CursorPagedResponse<GameResponse>`  | A paginated response containing a list of game responses and the next cursor. |

## Detailed Description

The `ListGamesCursorService` class is annotated with `@Service` and `@Transactional` to indicate its role as a Spring service component and to manage transaction boundaries. It implements the `IListGamesCursorService` interface, ensuring adherence to a defined contract for listing games.

### Key Components

- **Dependencies**: The class relies on several repositories and services, such as `GameRepository`, `GameParticipantRepository`, `IAuthenticatedUserResolver`, and `IGameJoinabilityService`, to perform its operations.
- **Constants**: It defines several constants for geographical calculations and time conversions, such as `KM_PER_DEGREE_LAT` for latitude conversion and `MINUTES_PER_HOUR` for time calculations.
- **Private Methods**: The class includes private methods for computing bounding boxes, validating filter fields, and converting time to minutes, which support the main execution logic.
- **BoundingBox**: A private static record `BoundingBox` is used to represent geographical boundaries for location-based filtering.

### Execution Logic

The `execute` method is the primary entry point for retrieving games. It performs the following steps:

1. **User Resolution**: Determines the optional user ID for personalized queries.
2. **Cursor Decoding**: Decodes the cursor to determine the starting point for the query.
3. **Filter Validation**: Validates the provided filter for consistency and completeness.
4. **Query Execution**: Executes the query to retrieve games, applying filters and pagination.
5. **Participant Counting**: Counts active participants for each game.
6. **Joinability Computation**: Computes joinability information for the viewer if a user is present.
7. **Response Construction**: Constructs a `CursorPagedResponse` with the retrieved game data and next cursor.

This service is crucial for applications that require efficient and scalable game listing capabilities, especially in scenarios involving complex filtering and user-specific data access.
