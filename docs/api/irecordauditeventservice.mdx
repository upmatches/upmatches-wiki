# IRecordAuditEventService

The `IRecordAuditEventService` interface defines the contract for recording audit events within the application. It is a **sealed interface**, meaning only explicitly permitted classes (in this case, `RecordAuditEventService`) can implement it. This design enforces a controlled hierarchy and ensures that audit event recording logic is centralized and not extended arbitrarily.

## Purpose

- **Audit Logging**: Provides a standardized method to persist or process audit events.
- **Sealed Contract**: Restricts implementation to a single class (`RecordAuditEventService`), promoting encapsulation and maintainability.
- **Decoupling**: Allows the rest of the application to depend on this interface rather than concrete implementations, facilitating testing and future changes.

## Method Summary

| Method | Description |
|--------|-------------|
| `record(AuditEventRequest request)` | Records an audit event based on the provided request data. |

## Method Details

### `record`

```java
void record(AuditEventRequest request)
```

Records an audit event.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `AuditEventRequest` | The request object containing the details of the audit event to be recorded. |

**Returns:** `void`

**Throws:** This method does not explicitly declare any checked exceptions. Implementations may throw runtime exceptions (e.g., `IllegalArgumentException` if the request is null or invalid).

## Usage Example

```java
@Autowired
private IRecordAuditEventService auditService;

public void someBusinessMethod() {
    AuditEventRequest event = new AuditEventRequest();
    event.setAction("USER_LOGIN");
    event.setUserId(12345L);
    event.setTimestamp(Instant.now());

    auditService.record(event);
}
```

## Implementation Notes

- The interface is **sealed** with `permits RecordAuditEventService`. Only this class can implement the interface.
- The `RecordAuditEventService` implementation should handle the actual persistence or processing of the audit event (e.g., writing to a database, sending to a message queue, or logging to a file).
- Consider adding validation logic in the implementation to ensure the `AuditEventRequest` contains all required fields before recording.
