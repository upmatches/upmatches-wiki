# IRecordAuditEventService

## Purpose

The `IRecordAuditEventService` interface defines a contract for recording audit events within the application. It is a **sealed interface**, meaning only the explicitly permitted class (`RecordAuditEventService`) can implement it. This design enforces a controlled hierarchy and ensures that audit event recording is handled by a single, designated implementation.

This interface is part of the `com.upmatches.app.features.audit.services` package and is used to decouple the audit event recording logic from its consumers, promoting loose coupling and testability.

## Interface Definition

```java
public sealed interface IRecordAuditEventService permits RecordAuditEventService {
    void record(AuditEventRequest request);
}
```

## Methods

| Method | Description | Parameters | Returns |
|--------|-------------|------------|---------|
| `record` | Records an audit event based on the provided request data. | `AuditEventRequest request` – The request object containing the details of the audit event to be recorded. | `void` |

## Usage Example

```java
// Inject or obtain an instance of IRecordAuditEventService
IRecordAuditEventService auditService = new RecordAuditEventService();

// Create an audit event request
AuditEventRequest request = new AuditEventRequest();
request.setAction("USER_LOGIN");
request.setUserId(12345L);
request.setTimestamp(LocalDateTime.now());

// Record the audit event
auditService.record(request);
```

## Implementation Notes

- The interface is **sealed** to restrict implementation to `RecordAuditEventService` only. This prevents unauthorized or unintended implementations.
- The `record` method is intentionally void; any errors or failures in recording should be handled internally by the implementing class or propagated via unchecked exceptions.
- The `AuditEventRequest` class should contain all necessary fields for an audit event (e.g., action, user ID, timestamp, IP address, etc.).
