# GameShareAccess Entity

The `GameShareAccess` entity represents a record of when a user was granted access to a shared game. It is a JPA entity mapped to the `game_share_accesses` table in the database. Each record links a specific game to a specific user and records the timestamp when the access was resolved (granted).

This entity enforces a unique constraint on the combination of `game_id` and `user_id`, ensuring that a user can only have one access record per game.

## Entity Details

| Property     | Type    | Description                                                                 |
|--------------|---------|-----------------------------------------------------------------------------|
| `id`         | UUID    | Primary key, auto-generated using UUID strategy.                            |
| `game`       | Game    | The game that was shared. Many-to-one relationship with the `Game` entity.  |
| `user`       | User    | The user who received access. Many-to-one relationship with the `User` entity. |
| `resolvedAt` | Instant | The timestamp when the access was granted. Set automatically on creation.   |

## Public Methods

### `create(Game game, User user)`

Creates a new `GameShareAccess` instance for the given game and user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `game`    | Game | The game to which access is being granted. |
| `user`    | User | The user who is receiving access. |

**Returns:** `GameShareAccess` — a new instance with the provided game and user, but without a `resolvedAt` timestamp (set automatically before persistence).

**Example usage:**
```java
GameShareAccess access = GameShareAccess.create(game, user);
```

## Lifecycle Callbacks

### `onCreate()`

A `@PrePersist` callback that automatically sets the `resolvedAt` field to the current instant (`Instant.now()`) before the entity is persisted to the database. This ensures the timestamp is always recorded at the moment of creation.

## Database Constraints

- **Unique Constraint:** The combination of `game_id` and `user_id` must be unique across the `game_share_accesses` table. This prevents duplicate access records for the same user and game.

## Dependencies

- **Lombok:** Uses `@Getter` to generate getters for all fields and `@NoArgsConstructor(access = AccessLevel.PROTECTED)` to generate a protected no-argument constructor (required by JPA).
- **Jakarta Persistence:** Standard JPA annotations for entity mapping.
- **Java Time:** Uses `java.time.Instant` for timestamp handling.
