# ListGamesCursorFilterRequest

The `ListGamesCursorFilterRequest` is a Java record that encapsulates the filtering criteria for a cursor-based paginated query of games. It provides a structured way to pass optional filter parameters such as venue IDs, skill level IDs, date/time ranges, and a geographic location with a radius.

This record is designed to be used as a request body in REST API endpoints, with built-in Jakarta Bean Validation annotations to ensure data integrity.

## Record Definition

```java
public record ListGamesCursorFilterRequest(
    List<Long> venueIds,
    List<Long> skillLevelIds,
    LocalDate fromDate,
    LocalDate toDate,
    LocalTime fromTime,
    LocalTime toTime,
    BigDecimal latitude,
    BigDecimal longitude,
    Integer radiusKm
)
```

## Fields

| Field | Type | Validation | Description |
|-------|------|------------|-------------|
| `venueIds` | `List<Long>` | `@Size(max = 20)` | List of venue IDs to filter by. Maximum 20 entries. |
| `skillLevelIds` | `List<Long>` | `@Size(max = 20)` | List of skill level IDs to filter by. Maximum 20 entries. |
| `fromDate` | `LocalDate` | None | Start date for filtering games. |
| `toDate` | `LocalDate` | None | End date for filtering games. |
| `fromTime` | `LocalTime` | None | Start time for filtering games. |
| `toTime` | `LocalTime` | None | End time for filtering games. |
| `latitude` | `BigDecimal` | `@DecimalMin(-90.0)`, `@DecimalMax(90.0)` | Latitude coordinate for location-based filtering. |
| `longitude` | `BigDecimal` | `@DecimalMin(-180.0)`, `@DecimalMax(180.0)` | Longitude coordinate for location-based filtering. |
| `radiusKm` | `Integer` | `@Min(1)`, `@Max(5)` | Search radius in kilometers for location-based filtering. Must be between 1 and 5. |

## Methods

### `hasLocation()`

Returns `true` if all three location fields (`latitude`, `longitude`, and `radiusKm`) are non-null, indicating a complete location-based filter is provided.

**Returns:** `boolean`

### `hasAnyLocationField()`

Returns `true` if at least one of the location fields (`latitude`, `longitude`, or `radiusKm`) is non-null. This can be used to validate that partial location data is not accidentally used.

**Returns:** `boolean`

### `hasSkillLevels()`

Returns `true` if the `skillLevelIds` list is non-null and not empty.

**Returns:** `boolean`

### `hasVenues()`

Returns `true` if the `venueIds` list is non-null and not empty.

**Returns:** `boolean`

## Usage Example

```java
// Create a filter request with location and skill level filters
ListGamesCursorFilterRequest filter = new ListGamesCursorFilterRequest(
    null,                          // venueIds
    List.of(1L, 2L, 3L),          // skillLevelIds
    LocalDate.now(),               // fromDate
    LocalDate.now().plusDays(7),   // toDate
    LocalTime.of(9, 0),            // fromTime
    LocalTime.of(22, 0),           // toTime
    new BigDecimal("40.7128"),     // latitude
    new BigDecimal("-74.0060"),    // longitude
    5                              // radiusKm
);

// Check if location filter is complete
if (filter.hasLocation()) {
    // Perform location-based query
}

// Check if skill level filter is active
if (filter.hasSkillLevels()) {
    // Filter by skill levels
}
```

## Validation Summary

The record enforces the following validation constraints:

- **venueIds**: Maximum 20 entries
- **skillLevelIds**: Maximum 20 entries
- **latitude**: Must be between -90.0 and 90.0
- **longitude**: Must be between -180.0 and 180.0
- **radiusKm**: Must be between 1 and 5

These validations are automatically applied when the record is used with Jakarta Bean Validation (e.g., in a Spring Boot controller with `@Valid` annotation).
