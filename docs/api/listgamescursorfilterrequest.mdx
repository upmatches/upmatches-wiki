# ListGamesCursorFilterRequest

The `ListGamesCursorFilterRequest` is a Java record that encapsulates the filtering criteria for a cursor-based paginated query of games. It provides a structured way to pass optional filters such as venue IDs, skill level IDs, date/time ranges, and geographic location parameters.

This record is designed to be used as a request object in API endpoints that list games with cursor-based pagination, allowing clients to narrow down results based on various criteria.

## Record Definition

```java
public record ListGamesCursorFilterRequest(
    List<Long> venueIds,
    List<Long> skillLevelIds,
    LocalDate fromDate,
    LocalDate toDate,
    LocalTime fromTime,
    LocalTime toTime,
    BigDecimal latitude,
    BigDecimal longitude,
    Integer radiusKm
)
```

## Fields

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `venueIds` | `List<Long>` | Max 20 entries | List of venue IDs to filter games by |
| `skillLevelIds` | `List<Long>` | Max 20 entries | List of skill level IDs to filter games by |
| `fromDate` | `LocalDate` | None | Start date for filtering games |
| `toDate` | `LocalDate` | None | End date for filtering games |
| `fromTime` | `LocalTime` | None | Start time for filtering games |
| `toTime` | `LocalTime` | None | End time for filtering games |
| `latitude` | `BigDecimal` | -90.0 to 90.0 | Latitude coordinate for location-based filtering |
| `longitude` | `BigDecimal` | -180.0 to 180.0 | Longitude coordinate for location-based filtering |
| `radiusKm` | `Integer` | 1 to 5 | Search radius in kilometers for location-based filtering |

## Validation Constraints

The record uses Jakarta Bean Validation annotations to enforce data integrity:

- **`@Size(max = 20)`**: Both `venueIds` and `skillLevelIds` lists are limited to a maximum of 20 entries each
- **`@DecimalMin` / `@DecimalMax`**: Latitude must be between -90.0 and 90.0; longitude must be between -180.0 and 180.0
- **`@Min` / `@Max`**: `radiusKm` must be between 1 and 5 kilometers

## Methods

### `hasLocation()`

Returns `true` if all three location fields (`latitude`, `longitude`, and `radiusKm`) are non-null, indicating a complete location-based filter.

**Returns:** `boolean`

### `hasAnyLocationField()`

Returns `true` if at least one of the location fields (`latitude`, `longitude`, or `radiusKm`) is non-null.

**Returns:** `boolean`

### `hasSkillLevels()`

Returns `true` if the `skillLevelIds` list is non-null and not empty.

**Returns:** `boolean`

### `hasVenues()`

Returns `true` if the `venueIds` list is non-null and not empty.

**Returns:** `boolean`

```java
    LocalDate.of(2024, 12, 31),    // toDate
    null,                           // fromTime
    null,                           // toTime
    null,                           // latitude
    null,                           // longitude
    null                            // radiusKm
);

// Check if the filter has venue criteria
if (filter.hasVenues()) {
    // Apply venue filtering logic
}

// Check if the filter has complete location data

```

## Best Practices

1. **Validation**: Always validate the request object using Jakarta Bean Validation before processing to ensure data integrity
2. **Null Safety**: Use the provided helper methods (`hasLocation()`, `hasVenues()`, etc.) to safely check which filters are active
3. **Location Filtering**: When using location-based filtering, ensure all three fields (`latitude`, `longitude`, `radiusKm`) are provided for meaningful results
4. **List Size Limits**: Respect the maximum of 20 entries per list to maintain API performance and prevent abuse
