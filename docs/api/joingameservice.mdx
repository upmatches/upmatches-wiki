# JoinGameService

The `JoinGameService` class is a Spring `@Service` component responsible for handling the business logic of a user joining a game. It implements the `IJoinGameService` interface and provides a transactional, auditable method to add a participant to a game while enforcing various business rules such as capacity limits, time overlap checks, and authorization constraints.

## Purpose

This service encapsulates the complete "join game" workflow, including:
- Resolving the authenticated user
- Looking up the game and user entities
- Performing authorization checks (joinability, private access, duplicate participation)
- Validating game capacity
- Checking for overlapping game participation
- Creating and persisting a `GameParticipant` entity
- Publishing domain events for notifications

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Persistence for game participants |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Retrieves game and user entities |
| `IGameAuthorizationService` | Service | Performs authorization checks |
| `ApplicationEventPublisher` | Spring | Publishes notification events |

## Public Methods

### `execute(UUID id)`

The main entry point for joining a game. This method is transactional and auditable.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to join |

**Returns:**

| Type | Description |
|------|-------------|
| `GameParticipantResponse` | A response object containing the participant details, activity ID, and a flag indicating if the user is the host |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | If the game or user is not found |
| `GameFullException` | If the game has reached its maximum capacity |
| `OverlappingGameException` | If the user already participates in another game with overlapping time |

**Workflow:**

1. **Resolve User** - Retrieves the authenticated user's UUID
2. **Lookup Game** - Fetches the game entity with a pessimistic lock for update
3. **Authorization Checks** - Validates:
   - Game is joinable (not cancelled, completed, etc.)
   - User has private access if the game is private
   - User has not already joined the game
4. **Capacity Check** - Counts active participants and throws `GameFullException` if the game is full
5. **Overlap Check** - Verifies no other active game participation overlaps with this game's time slot
6. **Create Participant** - Creates a new `GameParticipant` entity
7. **Persist** - Saves the participant using `ServiceOperationExecutor`
8. **Publish Notifications** - Fires events for:
   - Player joined notification
   - Game full notification (if applicable)
   - Skill mismatch warning (if applicable)
9. **Return Response** - Builds and returns a `GameParticipantResponse`

## Private Methods

### `publishNotifications(Game game, UUID actorId, User user, long newCount)`

Publishes domain events based on the join result.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `game` | `Game` | The game being joined |
| `actorId` | `UUID` | The ID of the user joining |
| `user` | `User` | The user entity |
| `newCount` | `long` | The new participant count after joining |

**Events Published:**

| Event Type | Condition |
|------------|-----------|
| `PLAYER_JOINED` | Always |
| `GAME_FULL` | When the game reaches full capacity |
| `PLAYER_WARNING_MISMATCH` | When there is a skill mismatch between the player and the game |

## Usage Example

```java
@Autowired
private JoinGameService joinGameService;

public void joinGame(UUID gameId) {
    try {
        GameParticipantResponse response = joinGameService.execute(gameId);
        // Handle successful join
    } catch (GameFullException e) {
        // Handle game full scenario
    } catch (OverlappingGameException e) {
        // Handle time overlap scenario
    }
}
```

## Notes

- The service is annotated with `@Transactional` to ensure atomicity of the join operation
- The `@Auditable` annotation logs the action with resource type "GAME" and the game ID as the resource identifier
- The class is declared as `non-sealed`, allowing further extension if needed
- All authorization checks are delegated to `IGameAuthorizationService` for separation of concerns
- Notifications are published asynchronously via Spring's `ApplicationEventPublisher`
