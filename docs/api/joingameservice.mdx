# JoinGameService

The `JoinGameService` class is a Spring service responsible for handling the business logic of a user joining a game. It validates the join request, checks for capacity and scheduling conflicts, persists the participant record, and publishes relevant notifications.

## Purpose

This service encapsulates the complete "join game" workflow, including:
- Authenticating the requesting user
- Looking up the game and user entities
- Performing authorization checks (game joinable, private access, not already joined)
- Validating game capacity
- Checking for overlapping game participation
- Persisting the new `GameParticipant` entity
- Publishing domain events for notifications (player joined, game full, skill mismatch)

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Persistence for game participant records |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Retrieves game and user entities |
| `IGameAuthorizationService` | Service | Performs authorization checks |
| `ApplicationEventPublisher` | Spring | Publishes domain events for notifications |

## Public Methods

### `execute(UUID id)`

Joins the authenticated user to the game identified by the given ID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to join |

| Returns | Type | Description |
|---------|------|-------------|
| `GameParticipantResponse` | Object | Response containing the saved participant details |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | Game or user not found |
| `GameFullException` | Game has reached its maximum capacity |
| `OverlappingGameException` | User already participates in another game during the same time period |
| `AuthorizationException` | User is not authorized to join the game |

**Behavior:**

1. Resolves the authenticated user's ID
2. Retrieves the game with a pessimistic lock for update
3. Performs authorization checks:
   - Game is joinable
   - User has private access (if applicable)
   - User has not already joined
4. Counts current active participants
5. Validates game capacity
6. Retrieves the user entity
7. Checks for overlapping game participation
8. Creates and persists a new `GameParticipant` entity
9. Publishes notification events:
   - `PLAYER_JOINED` - always published
   - `GAME_FULL` - published if game becomes full
   - `PLAYER_WARNING_MISMATCH` - published if skill mismatch detected
10. Returns the participant response

## Private Methods

### `publishNotifications(Game game, UUID actorId, User user, long newCount)`

Publishes domain events for various notification scenarios.

| Parameter | Type | Description |
|-----------|------|-------------|
| `game` | `Game` | The game being joined |
| `actorId` | `UUID` | The ID of the user joining |
| `user` | `User` | The user entity |
| `newCount` | `long` | The new participant count after joining |

## Annotations

| Annotation | Description |
|------------|-------------|
| `@Service` | Marks this class as a Spring service component |
| `@Transactional` | Ensures the entire join operation is executed within a single database transaction |
| `@Auditable(action = "GAME_JOINED", ...)` | Records an audit log entry for the join operation |

## Usage Example

```java
@Autowired
private JoinGameService joinGameService;

public void joinGame(UUID gameId) {
    GameParticipantResponse response = joinGameService.execute(gameId);
    // Handle response
}
```
