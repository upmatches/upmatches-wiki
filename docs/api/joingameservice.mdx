# JoinGameService

The `JoinGameService` class is a Spring service responsible for handling the business logic of a user joining a game. It validates that the game is joinable, not full, and that the user does not have overlapping game commitments. Upon successful validation, it creates a `GameParticipant` record, persists it, and publishes relevant notifications.

## Purpose

- **Game Joining Logic**: Orchestrates the entire join-game flow, including authorization checks, capacity validation, overlap detection, and participant creation.
- **Notification Publishing**: After a successful join, it publishes events for player joined, game full, and skill mismatch warnings.
- **Transactional Integrity**: The `execute` method is annotated with `@Transactional` to ensure atomicity of the join operation.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Persistence for game participants |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Retrieves game and user entities |
| `IGameAuthorizationService` | Service | Performs authorization checks |
| `ApplicationEventPublisher` | Spring | Publishes notification events |

## Public Methods

### `execute(UUID id)`

Joins the authenticated user to the game identified by the given ID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to join |

| Returns | Type | Description |
|---------|------|-------------|
| `GameParticipantResponse` | Object | Contains the saved participant details, activity ID, and a flag indicating if the user is the host |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `GameFullException` | The game has reached its maximum capacity |
| `OverlappingGameException` | The user already participates in another game that overlaps with this game's time range |
| `ResourceNotFoundException` | The game or user does not exist |

**Flow:**

1. Resolves the authenticated user's ID.
2. Retrieves the game with a pessimistic lock for update.
3. Performs authorization checks:
   - Game is joinable (not cancelled, completed, etc.)
   - User has private access (if the game is private)
   - User has not already joined
4. Counts current active participants.
5. Checks if the game is full; throws `GameFullException` if so.
6. Retrieves the user entity.
7. Checks for overlapping games; throws `OverlappingGameException` if found.
8. Creates a new `GameParticipant` entity.
9. Persists the participant using `ServiceOperationExecutor`.
10. Publishes notification events:
    - `PLAYER_JOINED` always
    - `GAME_FULL` if the game is now full
    - `PLAYER_WARNING_MISMATCH` if there is a skill mismatch
11. Returns a `GameParticipantResponse`.

## Private Methods

### `publishNotifications(Game game, UUID actorId, User user, long newCount)`

Publishes notification events based on the join result.

| Parameter | Type | Description |
|-----------|------|-------------|
| `game` | `Game` | The game entity |
| `actorId` | `UUID` | The ID of the user who joined |
| `user` | `User` | The user entity |
| `newCount` | `long` | The new participant count after joining |

**Events Published:**

| Event Type | Condition |
|------------|-----------|
| `PLAYER_JOINED` | Always |
| `GAME_FULL` | When `game.isFull(newCount)` is true |
| `PLAYER_WARNING_MISMATCH` | When `GameJoinabilityService.hasSkillMismatch(game, user)` is true |

## Usage Example

```java
@Autowired
private JoinGameService joinGameService;

public void joinGame(UUID gameId) {
    GameParticipantResponse response = joinGameService.execute(gameId);
    // response contains participant details
}
```

## Notes

- The service is declared as `non-sealed`, allowing it to be extended if needed.
- All authorization checks are delegated to `IGameAuthorizationService` for separation of concerns.
- The `@Auditable` annotation logs the join action for audit purposes.
- The `ServiceOperationExecutor` wraps the save operation to provide consistent error handling and logging.
