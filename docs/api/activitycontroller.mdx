# Activity Controller

The `ActivityController` class is a REST controller in the UpMatches application that handles HTTP requests related to activity management. It provides endpoints for creating, reading, updating, and deleting activities, following standard RESTful API conventions.

## Purpose

This controller serves as the entry point for all activity-related operations in the application. It delegates business logic to dedicated service interfaces and returns standardized API responses using the `ApiResponse` wrapper class. The controller is mapped to the `/api/v1/activities` base path and uses Spring's validation framework to ensure request data integrity.

## Endpoints

### List Activities

Retrieves a paginated list of activities sorted by name.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/activities` | Returns a paginated list of activities |

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | Integer | 0 | Page number (zero-based) |
| `size` | Integer | 20 | Number of items per page |

**Response:** `200 OK` - Returns a `PagedResponse<ActivityResponse>` wrapped in an `ApiResponse` with the message "Activities retrieved successfully."

### Get Activity by ID

Retrieves a single activity by its unique identifier.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/activities/{id}` | Returns a specific activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity |

**Response:** `200 OK` - Returns an `ActivityResponse` wrapped in an `ApiResponse` with the message "Activity retrieved successfully."

### Create Activity

Creates a new activity.

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/v1/activities` | Creates a new activity |

**Request Body:** `CreateActivityRequest` (validated)

**Response:** `201 Created` - Returns the created `ActivityResponse` wrapped in an `ApiResponse` with the message "Activity created successfully."

### Update Activity

Updates an existing activity.

| Method | Path | Description |
|--------|------|-------------|
| PUT | `/api/v1/activities/{id}` | Updates an existing activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity to update |

**Request Body:** `UpdateActivityRequest` (validated)

**Response:** `200 OK` - Returns the updated `ActivityResponse` wrapped in an `ApiResponse` with the message "Activity updated successfully."

### Delete Activity

Deletes an activity.

| Method | Path | Description |
|--------|------|-------------|
| DELETE | `/api/v1/activities/{id}` | Deletes an activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity to delete |

**Response:** `204 No Content` - No response body.

## Dependencies

The controller depends on the following service interfaces:

- `IListActivitiesService` - Handles paginated activity listing
- `IGetActivityService` - Handles single activity retrieval
- `ICreateActivityService` - Handles activity creation
- `IUpdateActivityService` - Handles activity updates
- `IDeleteActivityService` - Handles activity deletion

## Validation

The controller uses Spring's `@Valid` annotation on request bodies and `@Validated` at the class level to ensure incoming data meets validation constraints. Pagination parameters are validated using `ValidationHelper.validatePaginationParameters()`.

## Error Handling

All endpoints return standardized responses using the `ApiResponse` class. The controller does not handle exceptions directly; error handling is managed by a global exception handler in the application.
