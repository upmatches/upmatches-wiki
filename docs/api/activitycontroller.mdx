# Activity Controller

The `ActivityController` class is a REST controller that handles HTTP requests for managing activities in the UpMatches application. It provides endpoints for creating, reading, updating, and deleting activities, following standard RESTful API conventions.

## Purpose

This controller serves as the entry point for all activity-related operations. It delegates business logic to dedicated service classes and returns standardized API responses using the `ApiResponse` wrapper. The controller is mapped to the `/api/v1/activities` base path and supports pagination for list operations.

## Endpoints

### List Activities

Retrieves a paginated list of activities sorted by name.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/activities` | Returns a paginated list of activities |

**Query Parameters:**

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `page` | Integer | 0 | Page number (zero-indexed) |
| `size` | Integer | 20 | Number of items per page |

**Response:** `200 OK` - Returns a `PagedResponse<ActivityResponse>` wrapped in an `ApiResponse`.

### Get Activity by ID

Retrieves a single activity by its unique identifier.

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/activities/{id}` | Returns a specific activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity |

**Response:** `200 OK` - Returns an `ActivityResponse` wrapped in an `ApiResponse`.

### Create Activity

Creates a new activity.

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/v1/activities` | Creates a new activity |

**Request Body:** `CreateActivityRequest` (validated)

**Response:** `201 Created` - Returns the created `ActivityResponse` wrapped in an `ApiResponse`.

### Update Activity

Updates an existing activity.

| Method | Path | Description |
|--------|------|-------------|
| PUT | `/api/v1/activities/{id}` | Updates a specific activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity to update |

**Request Body:** `UpdateActivityRequest` (validated)

**Response:** `200 OK` - Returns the updated `ActivityResponse` wrapped in an `ApiResponse`.

### Delete Activity

Deletes an activity.

| Method | Path | Description |
|--------|------|-------------|
| DELETE | `/api/v1/activities/{id}` | Deletes a specific activity |

**Path Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | UUID | The unique identifier of the activity to delete |

**Response:** `204 No Content` - No response body.

## Dependencies

The controller depends on the following service interfaces:

- `IListActivitiesService` - Handles paginated listing of activities
- `IGetActivityService` - Handles retrieval of a single activity
- `ICreateActivityService` - Handles creation of new activities
- `IUpdateActivityService` - Handles updating existing activities
- `IDeleteActivityService` - Handles deletion of activities

## Validation

The controller uses Jakarta Bean Validation (`@Valid`) to validate request bodies and custom validation through `ValidationHelper.validatePaginationParameters()` for pagination parameters. The class is also annotated with `@Validated` to enable method-level validation.

## Error Handling

All endpoints return standardized responses using the `ApiResponse` class. The controller does not handle exceptions directly; error handling is managed by Spring's exception handling mechanisms and the application's global exception handler.
