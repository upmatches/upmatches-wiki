# IListNotificationsService

The `IListNotificationsService` interface defines the contract for retrieving a paginated list of notifications. It is part of the notification feature within the UpMatches application and follows a sealed interface pattern to restrict implementation to a single concrete class.

## Purpose

This interface provides a standardized way to fetch notifications with pagination support. By using a sealed interface, the design ensures that only the designated implementation (`ListNotificationsService`) can fulfill this contract, promoting encapsulation and controlled extensibility.

## Interface Definition

```java
public sealed interface IListNotificationsService permits ListNotificationsService {
    PagedResponse<NotificationResponse> execute(Pageable pageable);
}
```

### Key Characteristics

- **Sealed Interface**: The `sealed` keyword restricts which classes can implement this interface. Only `ListNotificationsService` is permitted.
- **Single Method Contract**: Defines a single `execute` method that accepts pagination parameters and returns a paginated response of notification data.

## Method Documentation

### `execute`

Retrieves a paginated list of notifications.

| Parameter | Type | Description |
|-----------|------|-------------|
| `pageable` | `Pageable` | Spring Data pagination object containing page number, size, and sort criteria |

| Returns | Type | Description |
|---------|------|-------------|
| Success | `PagedResponse<NotificationResponse>` | A paginated response containing a list of `NotificationResponse` objects with metadata (page number, page size, total elements, total pages) |

## Usage Example

```java
// Inject the service
private final IListNotificationsService listNotificationsService;

// Create a pageable request
Pageable pageable = PageRequest.of(0, 10, Sort.by("createdAt").descending());

// Execute the query
PagedResponse<NotificationResponse> notifications = listNotificationsService.execute(pageable);

// Access paginated results
List<NotificationResponse> items = notifications.getContent();
int totalPages = notifications.getTotalPages();
long totalElements = notifications.getTotalElements();
```

## Related Components

| Component | Description |
|-----------|-------------|
| `ListNotificationsService` | The sole permitted implementation of this interface |
| `NotificationResponse` | The DTO representing a single notification |
| `PagedResponse` | Generic wrapper for paginated API responses |

## Design Notes

- The sealed interface pattern ensures that the notification listing logic is centralized and cannot be extended arbitrarily.
- The use of `PagedResponse` provides consistent pagination metadata across the application.
- The `Pageable` parameter allows clients to control pagination and sorting without modifying the service implementation.
