# IListNotificationsService Interface

The `IListNotificationsService` interface defines the contract for retrieving paginated notifications within the UpMatches application. It is a sealed interface, meaning only the explicitly permitted class `ListNotificationsService` can implement it. This design enforces a controlled extension point for the notification listing functionality.

## Purpose

This interface abstracts the operation of fetching a paginated list of notifications. By using a sealed interface, the codebase ensures that all implementations adhere to a single, well-defined contract, improving maintainability and security. The primary use case is to provide a standardized way to retrieve notifications for a user or system, supporting pagination to handle large volumes of data efficiently.

## Interface Definition

```java
public sealed interface IListNotificationsService permits ListNotificationsService {

    PagedResponse<NotificationResponse> execute(Pageable pageable);

}
```

## Method Summary

| Method | Return Type | Description |
|--------|-------------|-------------|
| `execute(Pageable pageable)` | `PagedResponse<NotificationResponse>` | Executes the notification listing operation. Accepts a Spring Data `Pageable` object to control pagination (page number, size, sorting) and returns a `PagedResponse` containing a list of `NotificationResponse` objects along with pagination metadata. |

## Parameters

### `execute(Pageable pageable)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `pageable` | `org.springframework.data.domain.Pageable` | A Spring Data `Pageable` object that specifies the page number, page size, and optional sorting criteria for the query. |

## Return Type

### `PagedResponse<NotificationResponse>`

A generic wrapper class that encapsulates:
- A list of `NotificationResponse` objects (the actual notification data for the requested page).
- Pagination metadata such as total number of elements, total pages, current page number, and page size.

The `NotificationResponse` class contains the notification details returned to the client.

## Usage Example

```java
// Inject the service
private final IListNotificationsService listNotificationsService;

// Create a Pageable object (e.g., page 0, size 10, sorted by createdAt descending)
Pageable pageable = PageRequest.of(0, 10, Sort.by(Sort.Direction.DESC, "createdAt"));

// Execute the query
PagedResponse<NotificationResponse> response = listNotificationsService.execute(pageable);

// Access paginated results
List<NotificationResponse> notifications = response.getContent();
int totalPages = response.getTotalPages();
long totalElements = response.getTotalElements();
```

## Implementation Details

The only permitted implementation is `ListNotificationsService`. This class must provide the concrete logic for querying the notification data source (e.g., database, external API) and mapping the results to `NotificationResponse` objects, respecting the pagination constraints defined by the `Pageable` parameter.

## Related Components

- **`ListNotificationsService`**: The sole implementation class permitted by the sealed interface.
- **`NotificationResponse`**: The DTO representing a single notification in the response.
- **`PagedResponse`**: A generic wrapper for paginated API responses.
- **`Pageable`**: Spring Data interface for pagination abstraction.
