# ISingpassAuthService

The `ISingpassAuthService` interface defines the contract for Singpass authentication operations within the application. It encapsulates the core OAuth 2.0 authorization flow for Singpass, providing methods to initiate a pushed authorization request and exchange an authorization code for tokens.

This interface is declared as a **sealed interface**, meaning only the permitted class `SingpassAuthService` can implement it. This design enforces a strict hierarchy and ensures that all Singpass authentication logic is centralized in a single implementation.

## Interface Definition

```java
public sealed interface ISingpassAuthService permits SingpassAuthService
```

## Methods

### `sendPushedAuthorizationRequest`

Initiates a pushed authorization request (PAR) to the Singpass authorization server. This method is used to start the OAuth 2.0 flow by sending the required parameters and receiving a request URI that the client can use to redirect the user to Singpass for authentication.

| Parameter      | Type     | Description                                                                 |
|----------------|----------|-----------------------------------------------------------------------------|
| `state`        | `String` | A unique, non-guessable value used to maintain state between the request and callback. Prevents CSRF attacks. |
| `nonce`        | `String` | A unique value used to associate a client session with an ID token and to mitigate replay attacks. |
| `codeVerifier` | `String` | A cryptographically random string used in the PKCE (Proof Key for Code Exchange) flow to secure the authorization code exchange. |

**Returns:** `String` - The request URI that the client should use to redirect the user to the Singpass authorization endpoint.

### `exchangeAuthorizationCode`

Exchanges an authorization code for tokens (access token, ID token, and optionally refresh token) from the Singpass token endpoint. This method is called after the user has authenticated and authorized the application, and the authorization server has redirected back to the client with an authorization code.

| Parameter          | Type     | Description                                                                 |
|--------------------|----------|-----------------------------------------------------------------------------|
| `authorizationCode`| `String` | The authorization code received from the Singpass authorization server after user authentication. |
| `codeVerifier`     | `String` | The same PKCE code verifier that was used in the initial authorization request. |
| `nonce`            | `String` | The same nonce value that was used in the initial authorization request. |

**Returns:** `String` - The response from the token endpoint, typically containing the access token, ID token, and other token-related data.

## Usage Example

```java
// Inject the service
@Autowired
private ISingpassAuthService singpassAuthService;

// Step 1: Initiate authorization request
String state = generateRandomState();
String nonce = generateRandomNonce();
String codeVerifier = generateCodeVerifier();
String requestUri = singpassAuthService.sendPushedAuthorizationRequest(state, nonce, codeVerifier);

// Redirect user to requestUri for authentication...

// Step 2: Exchange authorization code for tokens
String authorizationCode = getAuthorizationCodeFromCallback();
String tokenResponse = singpassAuthService.exchangeAuthorizationCode(authorizationCode, codeVerifier, nonce);
```

## Implementation Notes

- The interface is sealed to `SingpassAuthService` only, ensuring a single, controlled implementation.
- Both methods return `String` responses, which should be parsed according to the Singpass API specification (typically JSON format).
- The PKCE flow is enforced through the `codeVerifier` parameter, providing enhanced security for public clients.
- The `state` and `nonce` parameters are critical for security and must be generated with sufficient entropy.
