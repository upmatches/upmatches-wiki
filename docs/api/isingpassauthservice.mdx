# ISingpassAuthService Interface

The `ISingpassAuthService` interface defines the contract for Singpass authentication operations within the Upmatches application. It serves as the sealed abstraction layer for handling the OAuth 2.0 authorization code flow with PKCE (Proof Key for Code Exchange) extension, specifically tailored for Singpass integration.

## Purpose

This interface encapsulates two critical phases of the Singpass authentication flow:

1. **Pushed Authorization Request (PAR)** - Initiates the authentication process by sending a pushed authorization request to Singpass
2. **Authorization Code Exchange** - Exchanges the received authorization code for tokens after user consent

The interface is declared as `sealed`, meaning only the `SingpassAuthService` class is permitted to implement it, ensuring controlled and secure implementation of the authentication logic.

## Interface Methods

### sendPushedAuthorizationRequest

Initiates the Singpass authentication flow by sending a pushed authorization request. This method implements the PAR (Pushed Authorization Requests) specification, which enhances security by sending authorization request parameters directly to the authorization server via a back-channel request.

| Parameter | Type | Description |
|-----------|------|-------------|
| `state` | `String` | A cryptographically random string used to maintain state between the request and callback, preventing CSRF attacks |
| `nonce` | `String` | A random value generated by the client to associate a client session with an ID Token, preventing replay attacks |
| `codeVerifier` | `String` | A high-entropy cryptographic random string used for PKCE, which is transformed into the code challenge for the authorization request |

**Returns:** `String` - The authorization request URI that the client should redirect the user to for authentication

### exchangeAuthorizationCode

Exchanges the authorization code received from Singpass for the actual tokens (access token, ID token, etc.). This method completes the authorization code flow by validating the PKCE challenge and nonce.

| Parameter | Type | Description |
|-----------|------|-------------|
| `authorizationCode` | `String` | The temporary authorization code received from Singpass after user authentication and consent |
| `codeVerifier` | `String` | The original PKCE code verifier used in the authorization request, used to verify the code challenge |
| `nonce` | `String` | The original nonce value used in the authorization request, used to validate the ID token |

**Returns:** `String` - The response containing the tokens (typically in JSON format) from Singpass

## Implementation Details

The interface is part of the `com.upmatches.app.features.auth.services` package and is designed to be implemented by `SingpassAuthService`. The sealed interface pattern ensures that:

- Only the designated implementation class can implement this interface
- The authentication flow remains consistent and secure
- Future modifications are controlled and predictable

## Usage Example

```java
// Inject the service
private final ISingpassAuthService singpassAuthService;

// Step 1: Initiate authentication
String authRequestUri = singpassAuthService.sendPushedAuthorizationRequest(
    state,
    nonce,
    codeVerifier
);

// Step 2: After user redirect and authorization code received
String tokenResponse = singpassAuthService.exchangeAuthorizationCode(
    authorizationCode,
    codeVerifier,
    nonce
);
```
