# AuditEventRepository

The `AuditEventRepository` interface provides data access methods for `AuditEvent` entities in the audit system. It extends Spring Data JPA's `JpaRepository` to inherit standard CRUD operations while adding custom query methods for retrieving audit events by actor or resource.

## Purpose

This repository serves as the persistence layer for audit events, enabling efficient retrieval of audit trails based on:
- **Actor identification** – Find all events performed by a specific user or system actor
- **Resource identification** – Find all events related to a specific resource (by type and ID)

Results are automatically sorted by occurrence timestamp in descending order (most recent first).

## Interface Definition

```java
@Repository
public interface AuditEventRepository extends JpaRepository<AuditEvent, Long>
```

- **Entity**: `AuditEvent`
- **Primary Key Type**: `Long`
- **Spring Stereotype**: `@Repository` – enables exception translation and component scanning

## Custom Query Methods

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findByActorIdOrderByOccurredAtDesc` | `List<AuditEvent>` | `UUID actorId` | Retrieves all audit events for a given actor, ordered by most recent occurrence first |
| `findByResourceTypeAndResourceIdOrderByOccurredAtDesc` | `List<AuditEvent>` | `String resourceType`, `String resourceId` | Retrieves all audit events for a specific resource (identified by type and ID), ordered by most recent occurrence first |

### Method Details

#### `findByActorIdOrderByOccurredAtDesc(UUID actorId)`

- **Purpose**: Fetch the complete audit trail for a specific actor (user, system, or service)
- **Parameter**: `actorId` – UUID identifying the actor who performed the actions
- **Returns**: List of `AuditEvent` objects sorted by `occurredAt` in descending order
- **Use case**: Displaying a user's activity history or auditing a specific system component

#### `findByResourceTypeAndResourceIdOrderByOccurredAtDesc(String resourceType, String resourceId)`

- **Purpose**: Fetch all audit events related to a specific resource
- **Parameters**:
  - `resourceType` – String identifying the type of resource (e.g., "User", "Order", "Document")
  - `resourceId` – String identifying the specific resource instance
- **Returns**: List of `AuditEvent` objects sorted by `occurredAt` in descending order
- **Use case**: Viewing the complete audit history for a particular entity or document

## Inherited Methods

As a `JpaRepository<AuditEvent, Long>`, this interface also inherits standard methods including:

| Method | Description |
|--------|-------------|
| `findAll()` | Retrieve all audit events |
| `findById(Long id)` | Find a specific audit event by its primary key |
| `save(AuditEvent event)` | Persist a new or updated audit event |
| `deleteById(Long id)` | Remove an audit event by its primary key |
| `count()` | Get the total number of audit events |

## Usage Example

```java
@Service
public class AuditService {
    
    private final AuditEventRepository auditEventRepository;
    
    public AuditService(AuditEventRepository auditEventRepository) {
        this.auditEventRepository = auditEventRepository;
    }
    
    public List<AuditEvent> getActorHistory(UUID actorId) {
        return auditEventRepository.findByActorIdOrderByOccurredAtDesc(actorId);
    }
    
    public List<AuditEvent> getResourceHistory(String resourceType, String resourceId) {
        return auditEventRepository.findByResourceTypeAndResourceIdOrderByOccurredAtDesc(
            resourceType, resourceId);
    }
}
```

## Notes

- The `@Repository` annotation is optional when extending `JpaRepository` but is included for clarity and to enable Spring's persistence exception translation
- Query methods follow Spring Data JPA's naming convention, automatically generating the appropriate JPQL queries
- Results are always sorted by `occurredAt` in descending order to show the most recent events first
- The `actorId` parameter uses `UUID` type, while resource identifiers use `String` for flexibility across different resource types
