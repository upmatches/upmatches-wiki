# AuditEventRepository

The `AuditEventRepository` interface provides data access operations for `AuditEvent` entities. It extends Spring Data JPA's `JpaRepository`, inheriting standard CRUD functionality while adding custom query methods for retrieving audit events by actor or resource.

## Purpose

This repository serves as the persistence layer for audit logging in the application. It enables efficient retrieval of audit trails based on two primary dimensions:
- **By actor**: Find all audit events performed by a specific user or system actor, ordered chronologically (most recent first).
- **By resource**: Find all audit events related to a specific resource (identified by type and ID), also ordered chronologically.

## Interface Definition

```java
@Repository
public interface AuditEventRepository extends JpaRepository<AuditEvent, Long>
```

The interface is annotated with `@Repository`, making it a Spring-managed bean eligible for dependency injection. It extends `JpaRepository<AuditEvent, Long>`, where:
- `AuditEvent` is the entity type being persisted.
- `Long` is the type of the entity's primary key.

## Methods

### Inherited from JpaRepository

The following standard CRUD and pagination methods are inherited from `JpaRepository` and `PagingAndSortingRepository`:

| Method | Description |
|--------|-------------|
| `findAll()` | Returns all audit events. |
| `findById(Long id)` | Finds an audit event by its primary key. |
| `save(AuditEvent event)` | Persists a new or updates an existing audit event. |
| `deleteById(Long id)` | Deletes an audit event by its primary key. |
| `count()` | Returns the total number of audit events. |

### Custom Query Methods

#### `findByActorIdOrderByOccurredAtDesc`

```java
List<AuditEvent> findByActorIdOrderByOccurredAtDesc(UUID actorId)
```

Retrieves all audit events performed by a specific actor, ordered by occurrence timestamp in descending order (most recent first).

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `actorId` | `UUID` | The unique identifier of the actor (user or system) whose audit events to retrieve. |

**Returns:** `List<AuditEvent>` - A list of audit events for the specified actor, sorted with the most recent event first. Returns an empty list if no events are found.

#### `findByResourceTypeAndResourceIdOrderByOccurredAtDesc`

```java
List<AuditEvent> findByResourceTypeAndResourceIdOrderByOccurredAtDesc(
    String resourceType, String resourceId)
```

Retrieves all audit events related to a specific resource, ordered by occurrence timestamp in descending order.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `resourceType` | `String` | The type of resource (e.g., "User", "Project", "Document"). |
| `resourceId` | `String` | The unique identifier of the resource. |

**Returns:** `List<AuditEvent>` - A list of audit events for the specified resource, sorted with the most recent event first. Returns an empty list if no events are found.

## Usage Example

```java
@Service
public class AuditService {
    
    private final AuditEventRepository auditEventRepository;
    
    public AuditService(AuditEventRepository auditEventRepository) {
        this.auditEventRepository = auditEventRepository;
    }
    
    public List<AuditEvent> getAuditTrailForUser(UUID userId) {
        return auditEventRepository.findByActorIdOrderByOccurredAtDesc(userId);
    }
    
    public List<AuditEvent> getAuditTrailForResource(String resourceType, String resourceId) {
        return auditEventRepository.findByResourceTypeAndResourceIdOrderByOccurredAtDesc(
            resourceType, resourceId);
    }
}
```

## Notes

- The repository uses Spring Data JPA's query derivation mechanism, which automatically implements the query methods based on their method names.
- Results are always ordered by `occurredAt` in descending order to show the most recent audit events first.
- The `UUID` type for `actorId` provides globally unique identifiers suitable for distributed systems.
- For large audit logs, consider adding pagination support by extending `PagingAndSortingRepository` or using Spring Data's `Pageable` parameter.
