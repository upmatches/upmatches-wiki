# AuditEventRepository

The `AuditEventRepository` interface provides data access operations for `AuditEvent` entities. It extends Spring Data JPA's `JpaRepository`, inheriting standard CRUD functionality while adding custom query methods for retrieving audit events filtered by actor or resource.

## Purpose

This repository serves as the persistence layer for audit logging within the application. It enables efficient retrieval of audit events based on:
- **Actor**: Find all events performed by a specific user, ordered chronologically (most recent first).
- **Resource**: Find all events related to a specific resource (identified by type and ID), also ordered chronologically.

## Interface Definition

```java
@Repository
public interface AuditEventRepository extends JpaRepository<AuditEvent, Long>
```

- **Extends**: `JpaRepository<AuditEvent, Long>` – provides standard CRUD operations (`save`, `findById`, `findAll`, `delete`, etc.) for `AuditEvent` entities with a primary key of type `Long`.
- **Annotation**: `@Repository` – marks this interface as a Spring Data repository, enabling exception translation and component scanning.

## Custom Query Methods

| Method | Parameters | Return Type | Description |
|--------|------------|-------------|-------------|
| `findByActorIdOrderByOccurredAtDesc` | `UUID actorId` | `List<AuditEvent>` | Retrieves all audit events performed by the specified actor, ordered by occurrence timestamp in descending order (most recent first). |
| `findByResourceTypeAndResourceIdOrderByOccurredAtDesc` | `String resourceType`, `String resourceId` | `List<AuditEvent>` | Retrieves all audit events associated with a specific resource type and resource ID, ordered by occurrence timestamp in descending order. |

### Method Details

#### `findByActorIdOrderByOccurredAtDesc`

- **Purpose**: Fetch all audit events where a specific user (actor) performed an action.
- **Parameter**: `actorId` – the UUID of the actor whose events should be retrieved.
- **Returns**: A list of `AuditEvent` objects sorted by `occurredAt` in descending order (newest first).
- **Use Case**: Displaying a user's activity history or auditing a specific user's actions.

#### `findByResourceTypeAndResourceIdOrderByOccurredAtDesc`

- **Purpose**: Fetch all audit events related to a specific resource, such as a document, profile, or transaction.
- **Parameters**:
  - `resourceType` – a string identifying the type of resource (e.g., "USER", "ORDER", "DOCUMENT").
  - `resourceId` – a string identifier for the specific resource instance.
- **Returns**: A list of `AuditEvent` objects sorted by `occurredAt` in descending order.
- **Use Case**: Viewing the complete audit trail for a particular resource, useful for compliance or debugging.

## Usage Example

```java
@Service
public class AuditService {
    
    private final AuditEventRepository auditEventRepository;
    
    public AuditService(AuditEventRepository auditEventRepository) {
        this.auditEventRepository = auditEventRepository;
    }
    
    public List<AuditEvent> getEventsByActor(UUID actorId) {
        return auditEventRepository.findByActorIdOrderByOccurredAtDesc(actorId);
    }
    
    public List<AuditEvent> getEventsByResource(String resourceType, String resourceId) {
        return auditEventRepository.findByResourceTypeAndResourceIdOrderByOccurredAtDesc(
            resourceType, resourceId);
    }
}
```

## Notes

- The repository leverages Spring Data JPA's query derivation mechanism, automatically implementing the custom methods based on their method names.
- All returned lists are ordered by `occurredAt` in descending order to present the most recent events first.
- The `@Repository` annotation is optional when extending `JpaRepository` but is included for clarity and to enable Spring's persistence exception translation.
