# JacksonConfiguration

The `JacksonConfiguration` class is a Spring `@Configuration` class that provides a customized `ObjectMapper` bean for the application. This configuration ensures consistent JSON serialization and deserialization behavior across the entire application by registering the `JavaTimeModule` and applying specific feature settings.

## Purpose

This configuration class addresses common JSON processing requirements in modern Java applications:

- **Java 8+ Date/Time Support**: Registers the `JavaTimeModule` to properly serialize and deserialize `java.time` objects (e.g., `LocalDate`, `LocalDateTime`, `ZonedDateTime`).
- **ISO 8601 Date Format**: Disables writing dates as timestamps, ensuring dates are serialized in ISO 8601 string format (e.g., `"2024-01-15T10:30:00"`).
- **Lenient Deserialization**: Prevents failures when encountering unknown JSON properties, making the API more resilient to changes.
- **Empty String Handling**: Accepts empty strings as null objects during deserialization, which is useful for handling form submissions or API requests where empty strings should be treated as null.

## Bean Definition

| Bean Name | Type | Scope | Primary |
|-----------|------|-------|---------|
| `objectMapper` | `ObjectMapper` | Singleton | Yes |

## Configuration Details

### ObjectMapper Customization

The `objectMapper()` method creates and configures an `ObjectMapper` instance with the following settings:

| Setting | Method | Description |
|---------|--------|-------------|
| JavaTimeModule | `registerModule(new JavaTimeModule())` | Enables serialization/deserialization of Java 8+ date/time types |
| WRITE_DATES_AS_TIMESTAMPS | `disable()` | Prevents dates from being written as numeric timestamps; uses ISO 8601 string format instead |
| FAIL_ON_UNKNOWN_PROPERTIES | `disable()` | Allows JSON with unknown properties to be deserialized without throwing an exception |
| ACCEPT_EMPTY_STRING_AS_NULL_OBJECT | `enable()` | Treats empty strings as null values during deserialization |

## Usage

This configuration is automatically applied by Spring Boot's auto-configuration. The `@Primary` annotation ensures that this `ObjectMapper` bean takes precedence over any other `ObjectMapper` beans in the application context.

### Example: Injecting the ObjectMapper

```java
@Service
public class UserService {
    private final ObjectMapper objectMapper;

    public UserService(ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;
    }

    public String serializeUser(User user) throws JsonProcessingException {
        return objectMapper.writeValueAsString(user);
    }

    public User deserializeUser(String json) throws JsonProcessingException {
        return objectMapper.readValue(json, User.class);
    }
}
```

### Example: JSON Output

With this configuration, a `User` object with a `birthDate` field of type `LocalDate` would be serialized as:

```json
{
  "name": "John Doe",
  "birthDate": "1990-05-15",
  "email": "john@example.com"
}
```

Instead of the default timestamp format:

```json
{
  "name": "John Doe",
  "birthDate": [1990, 5, 15],
  "email": "john@example.com"
}
```

## Dependencies

This configuration requires the following dependency in your `pom.xml` or `build.gradle`:

**Maven:**
```xml
<dependency>
    <groupId>com.fasterxml.jackson.datatype</groupId>
    <artifactId>jackson-datatype-jsr310</artifactId>
</dependency>
```

**Gradle:**
```groovy
implementation 'com.fasterxml.jackson.datatype:jackson-datatype-jsr310'
```

## Notes

- The `@Primary` annotation is crucial when multiple `ObjectMapper` beans exist in the application context, ensuring this customized version is used by default.
- This configuration is compatible with Spring Boot 2.x and 3.x applications.
- The `ACCEPT_EMPTY_STRING_AS_NULL_OBJECT` feature is particularly useful when integrating with frontend frameworks that may send empty strings for optional fields.
