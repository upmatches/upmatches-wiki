# NotificationRepository

The `NotificationRepository` interface provides data access methods for the `Notification` entity in the UpMatches application. It extends Spring Data JPA's `JpaRepository` to inherit standard CRUD operations and defines custom query methods for notification-specific functionality, including paginated retrieval, unread counts, duplicate detection, and bulk read status updates.

## Interface Definition

```java
public interface NotificationRepository extends JpaRepository<Notification, UUID>
```

The repository operates on `Notification` entities with `UUID` primary keys.

## Methods

### findByRecipientIdOrderByCreatedAtDesc

Retrieves a paginated list of notifications for a specific recipient, ordered by creation date in descending order (newest first).

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The unique identifier of the recipient |
| `pageable` | `Pageable` | Pagination and sorting information |

| Returns | Description |
|---------|-------------|
| `Page<Notification>` | A page of notifications for the specified recipient |

### countByRecipientIdAndIsReadFalse

Counts the number of unread notifications for a specific recipient.

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The unique identifier of the recipient |

| Returns | Description |
|---------|-------------|
| `long` | The count of unread notifications |

### findByIdAndRecipientId

Finds a specific notification by its ID and recipient ID. This ensures that a user can only access their own notifications.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the notification |
| `recipientId` | `UUID` | The unique identifier of the recipient |

| Returns | Description |
|---------|-------------|
| `Optional<Notification>` | An Optional containing the notification if found, or empty if not found |

### existsByRecipientIdAndTypeAndResourceId

Checks if a notification already exists for a given recipient, notification type, and resource ID. This is useful for preventing duplicate notifications.

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The unique identifier of the recipient |
| `type` | `NotificationType` | The type of notification |
| `resourceId` | `UUID` | The unique identifier of the related resource |

| Returns | Description |
|---------|-------------|
| `boolean` | `true` if a matching notification exists, `false` otherwise |

### markAllReadByRecipientId

Marks all unread notifications as read for a specific recipient. This is a modifying query that updates the `isRead` and `readAt` fields in a single database operation.

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The unique identifier of the recipient |
| `readAt` | `Instant` | The timestamp when the notifications were marked as read |

| Returns | Description |
|---------|-------------|
| `int` | The number of notifications that were updated |

:::note
This method is annotated with `@Modifying`, which means it executes an update operation rather than a select query. It should be called within a transactional context.
:::
