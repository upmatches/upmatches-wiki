# MarkExpiredGamesService

## Purpose

The `MarkExpiredGamesService` is a Spring service class responsible for automatically marking games as expired based on their current status and the current timestamp. It implements the `IMarkExpiredGamesService` interface and provides a transactional method to update games that are in `SCHEDULED` or `STARTED` status and have passed their scheduled time.

This service is typically used in scheduled tasks or batch processes to maintain data integrity by ensuring that games that should have already started or finished are properly marked as expired.

## Public Methods

### `execute()`

Executes the operation to mark expired games. This method is transactional and will roll back if an exception occurs.

**Signature:** `@Transactional public int execute()`

**Returns:** `int` - The number of games that were marked as expired

**Behavior:**
1. Captures the current timestamp using `Instant.now()`
2. Calls `gameRepository.markExpiredBefore()` with:
   - A list of game statuses to consider: `SCHEDULED` and `STARTED`
   - The current timestamp as both the expiration time and the update time
3. Wraps the operation in `ServiceOperationExecutor.execute()` with:
   - Operation status: `UPDATE`
   - Exception factory: `ResourceNotFoundException::new`

**Throws:** `ResourceNotFoundException` if the operation fails (wrapped by the executor)

## Usage Example

```java
@Service
public class GameExpirationScheduler {
    
    private final MarkExpiredGamesService markExpiredGamesService;
    
    public GameExpirationScheduler(MarkExpiredGamesService markExpiredGamesService) {
        this.markExpiredGamesService = markExpiredGamesService;
    }
    
    @Scheduled(cron = "0 */5 * * * *") // Every 5 minutes
    public void markExpiredGames() {
        int expiredCount = markExpiredGamesService.execute();
        log.info("Marked {} games as expired", expiredCount);
    }
}
```

## Notes

- The class is declared as `non-sealed`, allowing it to be extended by other classes in the same module
- The `@Transactional` annotation ensures atomicity of the update operation
- The service uses `Instant.now()` for both the expiration check and the update timestamp, ensuring consistency
- Only games with `SCHEDULED` or `STARTED` status are considered for expiration
