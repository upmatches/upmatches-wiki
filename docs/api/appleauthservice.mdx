## Overview

The `AppleAuthService` class is a part of the authentication services in the application, specifically designed to handle the verification of Apple ID tokens. It implements the `IAppleAuthService` interface and utilizes various libraries to process and verify JSON Web Tokens (JWT) issued by Apple. The service ensures that the tokens are valid, the issuer and audience match expected values, and extracts necessary claims such as the subject and email.

## Public Methods

The `AppleAuthService` class provides the following public method:

| Method | Parameters | Return Type | Description |
|--------|------------|-------------|-------------|
| `verifyIdentityToken` | `identityToken: String` | `AppleVerifiedClaims` | Verifies the given Apple ID token and returns the verified claims. Throws an `IllegalStateException` if verification fails. |

### Method Details

#### `verifyIdentityToken`

- **Parameters:**

  | Name | Type | Description |
  |------|------|-------------|
  | `identityToken` | `String` | The Apple ID token to be verified. |

- **Return Type:** `AppleVerifiedClaims`

- **Description:** This method attempts to verify the provided Apple ID token. It processes the token to ensure it is valid, checks the issuer and audience against expected values, and extracts the subject and email claims. If any of these checks fail, it throws an `IllegalStateException` with an appropriate error message. Upon successful verification, it returns an instance of `AppleVerifiedClaims` containing the subject and email.

## Internal Logic

The class uses a caching mechanism for JSON Web Key Sets (JWKS) to optimize the verification process. It fetches the JWKS from Apple's server and caches it for a specified duration (`JWKS_CACHE_SECONDS`). The `getAppleJwks` method handles this caching logic, ensuring that the JWKS is only fetched when necessary.

The verification process involves:

1. Fetching the JWKS from Apple's server if not cached or expired.
2. Using the `DefaultJWTProcessor` to process the token with the fetched JWKS.
3. Validating the issuer and audience claims against expected values from `AppleProperties`.
4. Extracting the subject and email claims from the token.

The class logs various stages of the verification process for debugging and monitoring purposes.
