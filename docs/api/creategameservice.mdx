# CreateGameService

The `CreateGameService` class is a Spring service responsible for handling the creation of new games within the application. It implements the `ICreateGameService` interface and provides a comprehensive workflow for game creation, including validation of user permissions, onboarding status, overlapping game checks, and automatic generation of share links.

## Purpose

This service orchestrates the entire game creation process, ensuring that:
- The authenticated user has the necessary permissions (Singpass authentication)
- The user has completed their onboarding profile
- No overlapping games exist for the organizer
- All referenced entities (activity, venue, skill levels) exist
- A share link is automatically generated for the new game

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameRepository` | Repository | Persistence for Game entities |
| `GameParticipantRepository` | Repository | Persistence for GameParticipant entities |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Provides lookup operations for related entities |
| `ICreateShareLinkService` | Service | Generates share links for created games |

## Public Methods

### `execute(CreateGameRequest request)`

Creates a new game based on the provided request.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `CreateGameRequest` | The request object containing all game creation details |

**Returns:**

| Type | Description |
|------|-------------|
| `GameResponse` | The response object containing the created game details, participant count, and share link |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `SingpassRequiredException` | When the user has not authenticated via Singpass |
| `OnboardingRequiredException` | When the user has not completed their profile onboarding |
| `OverlappingGameException` | When the organizer already has a game scheduled during the requested time slot |
| `ResourceNotFoundException` | When any referenced entity (activity, venue, skill level) is not found |

**Workflow:**

1. **User Resolution**: Retrieves the authenticated user's ID
2. **Activity Lookup**: Validates and retrieves the activity
3. **Organizer Resolution**: Determines if the user joins as organizer and retrieves the user entity
4. **Permission Validation**: 
   - Checks Singpass authentication status
   - Verifies onboarding completion
5. **Entity Lookup**: Retrieves venue and skill level entities
6. **Overlap Check**: If joining as organizer, verifies no scheduling conflicts
7. **Pricing Calculation**: Determines pricing structure (custom or flat rate)
8. **Game Creation**: Creates and persists the Game entity
9. **Participant Registration**: If joining as organizer, creates a GameParticipant record
10. **Share Link Generation**: Creates a share link for the new game
11. **Response Building**: Returns a comprehensive GameResponse

## Usage Example

```java
@Autowired
private CreateGameService createGameService;

public void createNewGame() {
    CreateGameRequest request = new CreateGameRequest(
        activityId,
        venueId,
        skillLevelFromId,
        skillLevelToId,
        startTime,
        endTime,
        slots,
        visibility,
        gameType,
        pricing,
        price,
        currency,
        remark,
        joinAsOrganizer
    );
    
    GameResponse response = createGameService.execute(request);
}
```

## Annotations

- `@Service`: Marks this class as a Spring service component
- `@Transactional`: Ensures the entire game creation process is atomic
- `@Auditable`: Logs the game creation event with action "GAME_CREATED" and resource type "GAME"

## Error Handling

The service uses `ServiceOperationExecutor` to handle persistence operations with proper error handling, converting repository exceptions into `ResourceNotFoundException` when entities cannot be saved.
