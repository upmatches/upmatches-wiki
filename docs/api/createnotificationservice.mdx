# CreateNotificationService

The `CreateNotificationService` class is a Spring service component responsible for creating and persisting new notifications within the UpMatches application. It implements the `ICreateNotificationService` interface and provides a transactional method to create a notification for a specific user, associating it with relevant resource metadata.

## Purpose

This service encapsulates the business logic for notification creation, ensuring that:
- The recipient user exists in the system before creating a notification.
- A new `Notification` entity is properly constructed with all required fields.
- The notification is persisted to the database within a transactional context.
- Any errors during the save operation are handled consistently using the `ServiceOperationExecutor`.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `NotificationRepository` | Repository | Handles persistence of `Notification` entities |
| `UserRepository` | Repository | Retrieves user entities by ID |
| `ServiceOperationExecutor` | Utility | Executes operations with standardized error handling |

## Public Methods

### `execute`

Creates and saves a new notification for a specified recipient user.

```java
@Transactional
public Notification execute(
    UUID recipientId,
    NotificationType type,
    String title,
    String message,
    String resourceType,
    UUID resourceId)
```

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The unique identifier of the user who will receive the notification |
| `type` | `NotificationType` | The type/category of the notification (e.g., LIKE, MATCH, MESSAGE) |
| `title` | `String` | The title or subject of the notification |
| `message` | `String` | The body content of the notification |
| `resourceType` | `String` | The type of resource associated with the notification (e.g., "post", "profile") |
| `resourceId` | `UUID` | The unique identifier of the associated resource |

**Returns:**

| Return Type | Description |
|-------------|-------------|
| `Notification` | The newly created and persisted `Notification` entity |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | If no user exists with the provided `recipientId` |

**Behavior:**

1. Retrieves the `User` entity by `recipientId` from the database.
2. If the user is not found, throws a `ResourceNotFoundException` with a descriptive message.
3. Creates a new `Notification` instance using the static factory method `Notification.create()`.
4. Persists the notification using `ServiceOperationExecutor.execute()` with the `SAVE` operation status.
5. Returns the saved `Notification` entity.

## Usage Example

```java
@Autowired
private CreateNotificationService createNotificationService;

public void sendLikeNotification(UUID likedUserId, UUID likerId) {
    Notification notification = createNotificationService.execute(
        likedUserId,
        NotificationType.LIKE,
        "New Like",
        "Someone liked your profile!",
        "user",
        likerId
    );
}
```

## Error Handling

The service uses a two-tier error handling approach:
1. **User validation**: Ensures the recipient exists before proceeding.
2. **Operation execution**: Wraps the save operation in `ServiceOperationExecutor` to handle any persistence errors consistently, converting them to `ResourceNotFoundException` if needed.

## Transactional Behavior

The `@Transactional` annotation ensures that the entire operation (user lookup, notification creation, and save) is executed within a single database transaction. If any step fails, the transaction is rolled back, maintaining data consistency.
