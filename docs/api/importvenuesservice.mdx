# ImportVenuesService

The `ImportVenuesService` class is a Spring service responsible for importing venue data from a JSON file into the system. It handles parsing, validation, and persistence of venues along with their associated stations and transit lines. The service ensures data integrity by checking for duplicates, caching entities, and performing transactional operations.

## Purpose

- Parse a JSON file containing venue import requests
- Validate and process venue data, including associated stations and transit lines
- Persist new venues, stations, and transit lines to the database
- Handle duplicate detection and entity caching for performance
- Provide audit logging for import operations

## Public Methods

### `execute(MultipartFile file)`

Processes a JSON file containing venue import requests and persists the data.

| Parameter | Type | Description |
|-----------|------|-------------|
| `file` | `MultipartFile` | The JSON file containing venue import data |

| Returns | Type | Description |
|---------|------|-------------|
| `VenueImportResponse` | `VenueImportResponse` | Response object containing the count of imported venues |

**Throws:**
- `InvalidFileException` - If the JSON file cannot be parsed or contains invalid data
- `ResourceNotFoundException` - If a referenced activity is not found

**Example usage:**
```java
@Autowired
private ImportVenuesService importVenuesService;

public void importVenues(MultipartFile file) {
    VenueImportResponse response = importVenuesService.execute(file);
    System.out.println("Imported " + response.importedCount() + " venues");
}
```

## Internal Methods

### `parseJsonFile(MultipartFile file)`

Parses the JSON file into a list of `VenueImportRequest` objects.

| Parameter | Type | Description |
|-----------|------|-------------|
| `file` | `MultipartFile` | The JSON file to parse |

| Returns | Type | Description |
|---------|------|-------------|
| `List<VenueImportRequest>` | `List<VenueImportRequest>` | List of parsed venue import requests |

**Throws:**
- `InvalidFileException` - If parsing fails

### `processImport(List<VenueImportRequest> venueDtos)`

Processes the list of venue import requests and persists them to the database.

| Parameter | Type | Description |
|-----------|------|-------------|
| `venueDtos` | `List<VenueImportRequest>` | List of venue import requests to process |

| Returns | Type | Description |
|---------|------|-------------|
| `VenueImportResponse` | `VenueImportResponse` | Response object with import count |

### `resolveStation(StationImportRequest stationDto, Map<String, TransitLine> transitLineCache, Map<String, Station> stationCache)`

Resolves a station from the import request, creating new entities if necessary.

| Parameter | Type | Description |
|-----------|------|-------------|
| `stationDto` | `StationImportRequest` | Station import request data |
| `transitLineCache` | `Map<String, TransitLine>` | Cache of transit lines by code |
| `stationCache` | `Map<String, Station>` | Cache of stations by name |

| Returns | Type | Description |
|---------|------|-------------|
| `Station` | `Station` | The resolved station entity |

**Throws:**
- `InvalidFileException` - If station code format is invalid

## Annotations

- `@Service` - Marks the class as a Spring service component
- `@Transactional` - Ensures the import operation is performed within a transaction
- `@Auditable(action = "VENUES_IMPORTED", resourceType = "VENUE", sensitive = true)` - Enables audit logging for the import operation

## Error Handling

The service handles the following error scenarios:

1. **Invalid JSON format**: Throws `InvalidFileException` with a descriptive message
2. **Missing activity**: Throws `ResourceNotFoundException` with the activity ID
3. **Invalid station code**: Throws `InvalidFileException` with the invalid code
4. **Duplicate venues**: Skips venues that already exist in the database (checked by `sourceId`)

## Performance Considerations

- Entity caching is used for activities, transit lines, and stations to minimize database queries
- Batch processing is performed within a single transaction
- Duplicate detection prevents unnecessary database operations
