# UpdateGameRequest

The `UpdateGameRequest` record is a Java DTO (Data Transfer Object) used to encapsulate the data required for updating an existing game entity in the UpMatches application. It leverages Jakarta Bean Validation annotations to enforce input constraints, ensuring that only valid data is processed by the API.

## Purpose

This record serves as the request body for an API endpoint that allows clients to modify the details of a previously created game. By using a dedicated request object, the application maintains a clear separation between the incoming data and the internal domain model, promoting maintainability and validation consistency.

## Record Structure

`UpdateGameRequest` is defined as a Java `record`, which automatically provides a canonical constructor, getter methods, `equals()`, `hashCode()`, and `toString()`. All fields are optional, allowing partial updates.

## Fields

| Field | Type | Validation Constraints | Description |
|-------|------|------------------------|-------------|
| `venueId` | `Long` | None | The identifier of the venue where the game takes place. |
| `skillLevelFromId` | `Long` | None | The minimum skill level required for participants. |
| `skillLevelToId` | `Long` | None | The maximum skill level required for participants. |
| `currency` | `String` | `@Pattern(regexp = "^[A-Z]{3}$")` | ISO-4217 three-letter currency code (e.g., USD, EUR). |
| `price` | `BigDecimal` | `@DecimalMin("0.00")`, `@Digits(integer=8, fraction=2)` | The price of the game, with up to 8 integer digits and 2 decimal places. |
| `pricing` | `PricingRequest` | `@Valid` | A nested object containing detailed pricing information. |
| `slots` | `Integer` | `@Min(1)`, `@Max(100)` | The number of available slots for the game (1-100). |
| `startTime` | `Instant` | None | The scheduled start time of the game. |
| `endTime` | `Instant` | None | The scheduled end time of the game. |
| `visibility` | `GameVisibility` | None | The visibility setting of the game (e.g., PUBLIC, PRIVATE). |
| `gameType` | `GameType` | None | The type of game (e.g., SOCCER, BASKETBALL). |
| `remark` | `String` | `@Size(max = 500)` | An optional remark or note about the game (max 500 characters). |

## Usage Example

```java
// Create an instance of UpdateGameRequest with partial data
UpdateGameRequest request = new UpdateGameRequest(
    1L,                    // venueId
    null,                  // skillLevelFromId (not updating)
    null,                  // skillLevelToId (not updating)
    "USD",                 // currency
    new BigDecimal("25.00"), // price
    null,                  // pricing (not updating)
    20,                    // slots
    Instant.now(),         // startTime
    Instant.now().plus(2, ChronoUnit.HOURS), // endTime
    GameVisibility.PUBLIC, // visibility
    GameType.SOCCER,       // gameType
    "Bring your own water bottle." // remark
);
```

## Validation Behavior

- All fields are optional; only provided fields will be updated.
- If a field is provided but fails validation, the API will return a validation error.
- The `@Valid` annotation on the `pricing` field ensures that nested `PricingRequest` objects are also validated.
- The `currency` field must be exactly three uppercase letters.
- The `price` field must be non-negative and have a maximum of 8 integer digits and 2 decimal places.
- The `slots` field must be between 1 and 100 inclusive.
- The `remark` field cannot exceed 500 characters.

## Related Classes

- `PricingRequest`: A nested DTO for detailed pricing information.
- `GameVisibility`: An enum defining visibility options (e.g., PUBLIC, PRIVATE).
- `GameType`: An enum defining the type of game (e.g., SOCCER, BASKETBALL).
