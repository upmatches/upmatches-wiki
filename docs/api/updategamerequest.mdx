# UpdateGameRequest Record

The `UpdateGameRequest` record is a Java data transfer object (DTO) used to encapsulate the fields that can be updated for an existing game entity. It leverages Jakarta Bean Validation annotations to enforce constraints on the input data, ensuring that only valid updates are processed by the application.

This record is part of the `com.upmatches.app.features.game.requests` package and is designed to work with the game management features of the UpMatches application.

## Purpose

The primary purpose of `UpdateGameRequest` is to provide a structured and validated request payload for updating game details. By using a Java record, the class is immutable, concise, and automatically provides `equals()`, `hashCode()`, and `toString()` methods. The validation annotations ensure that the data meets business rules before being passed to the service layer.

## Fields

The record contains the following fields, each with specific validation constraints:

| Field | Type | Validation | Description |
|-------|------|------------|-------------|
| `venueId` | `Long` | None | The identifier of the venue where the game takes place. |
| `skillLevelFromId` | `Long` | None | The minimum skill level required for participants. |
| `skillLevelToId` | `Long` | None | The maximum skill level required for participants. |
| `currency` | `String` | `@Pattern(regexp = "^[A-Z]{3}$")` | A 3-letter ISO-4217 currency code (e.g., USD, EUR). |
| `price` | `BigDecimal` | `@DecimalMin("0.00")`, `@Digits(integer = 8, fraction = 2)` | The price of the game, must be >= 0, with up to 8 digits and 2 decimal places. |
| `pricing` | `PricingRequest` | `@Valid` | A nested pricing request object that is validated recursively. |
| `slots` | `Integer` | `@Min(1)`, `@Max(100)` | The number of available slots for the game, between 1 and 100. |
| `startTime` | `Instant` | None | The start time of the game. |
| `endTime` | `Instant` | None | The end time of the game. |
| `visibility` | `GameVisibility` | None | The visibility setting of the game (e.g., PUBLIC, PRIVATE). |
| `gameType` | `GameType` | None | The type of game (e.g., SOCCER, BASKETBALL). |
| `remark` | `String` | `@Size(max = 500)` | An optional remark about the game, up to 500 characters. |

## Usage Example

Below is an example of how to create an instance of `UpdateGameRequest`:

```java
UpdateGameRequest request = new UpdateGameRequest(
    1L,                    // venueId
    2L,                    // skillLevelFromId
    5L,                    // skillLevelToId
    "USD",                 // currency
    new BigDecimal("25.00"), // price
    new PricingRequest(...), // pricing (nested object)
    20,                    // slots
    Instant.now(),         // startTime
    Instant.now().plus(2, ChronoUnit.HOURS), // endTime
    GameVisibility.PUBLIC, // visibility
    GameType.SOCCER,       // gameType
    "Bring your own water bottle." // remark
);
```

## Validation Summary

The record uses Jakarta Bean Validation annotations to enforce the following rules:

- **Currency**: Must be exactly 3 uppercase letters (ISO-4217 format).
- **Price**: Must be a non-negative decimal with up to 8 integer digits and 2 fraction digits.
- **Slots**: Must be between 1 and 100 (inclusive).
- **Remark**: Maximum length of 500 characters.
- **Pricing**: The nested `PricingRequest` object is validated recursively via `@Valid`.

If any validation fails, a `ConstraintViolationException` will be thrown, which should be handled by the application's exception handling mechanism.

## Related Components

- **PricingRequest**: A nested record that defines pricing details, validated via `@Valid`.
- **GameVisibility**: An enum representing the visibility options for a game.
- **GameType**: An enum representing the different types of games supported by the application.
