# GameFilterOptionsRequest

The `GameFilterOptionsRequest` record encapsulates the filtering criteria for querying games within the application. It provides a structured way to pass optional and required parameters to the game search or listing endpoints, ensuring that input validation is handled declaratively via Jakarta Bean Validation annotations.

## Purpose

This record is designed to be used as a request body or query parameter object for REST API endpoints that need to filter games based on date range, location, venue, skill level, and game type. By centralizing these fields into a single record, the code promotes type safety, immutability, and clear validation rules.

## Record Components

The record defines the following components (fields), each with its own validation constraints:

| Field | Type | Validation | Description |
|-------|------|------------|-------------|
| `fromDate` | `LocalDate` | `@NotNull` | Start date for the game search range. |
| `toDate` | `LocalDate` | `@NotNull` | End date for the game search range. |
| `venueIds` | `List<Long>` | `@Size(max = 20)` | Optional list of venue IDs to filter by (max 20). |
| `skillLevelIds` | `List<Long>` | `@Size(max = 20)` | Optional list of skill level IDs to filter by (max 20). |
| `fromTime` | `LocalTime` | None | Optional start time for filtering games within a day. |
| `toTime` | `LocalTime` | None | Optional end time for filtering games within a day. |
| `gameType` | `GameType` | None | Optional game type filter (e.g., singles, doubles). |
| `latitude` | `BigDecimal` | `@DecimalMin(-90.0)`, `@DecimalMax(90.0)` | Optional latitude for location-based filtering. |
| `longitude` | `BigDecimal` | `@DecimalMin(-180.0)`, `@DecimalMax(180.0)` | Optional longitude for location-based filtering. |
| `radiusKm` | `Integer` | `@Min(1)`, `@Max(5)` | Optional search radius in kilometers (1-5). |

## Public Methods

The record provides several convenience methods to check the presence of optional filter groups.

### `hasLocation()`

Returns `true` if all three location fields (`latitude`, `longitude`, `radiusKm`) are non-null, indicating a complete location-based filter.

**Returns:** `boolean`

### `hasAnyLocationField()`

Returns `true` if at least one of the location fields (`latitude`, `longitude`, `radiusKm`) is non-null. This is useful for validating that partial location data is not accidentally used.

**Returns:** `boolean`

### `hasSkillLevels()`

Returns `true` if the `skillLevelIds` list is non-null and not empty.

**Returns:** `boolean`

### `hasVenues()`

Returns `true` if the `venueIds` list is non-null and not empty.

**Returns:** `boolean`

## Usage Example

```java
// Creating a filter request with date range and location
GameFilterOptionsRequest request = new GameFilterOptionsRequest(
    LocalDate.of(2025, 1, 1),
    LocalDate.of(2025, 1, 31),
    null,                    // venueIds
    List.of(1L, 2L),         // skillLevelIds
    LocalTime.of(9, 0),      // fromTime
    LocalTime.of(17, 0),     // toTime
    GameType.SINGLES,
    new BigDecimal("40.7128"),
    new BigDecimal("-74.0060"),
    5                        // radiusKm
);

// Check if location filter is complete
if (request.hasLocation()) {
    // Perform location-based search
}

// Check if skill levels are specified
if (request.hasSkillLevels()) {
    // Filter by skill levels
}
```

## Validation Summary

The record leverages Jakarta Bean Validation annotations to enforce constraints at the API boundary. Key validation rules include:

- **Required fields:** `fromDate` and `toDate` must be provided.
- **List sizes:** `venueIds` and `skillLevelIds` are limited to 20 entries each.
- **Geographic bounds:** Latitude must be between -90 and 90; longitude between -180 and 180.
- **Radius:** Must be between 1 and 5 kilometers.

These validations help maintain data integrity and provide clear error messages to API consumers.
