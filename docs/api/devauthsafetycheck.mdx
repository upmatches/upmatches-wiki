# DevAuthSafetyCheck

The `DevAuthSafetyCheck` class is a Spring Boot configuration component that provides a critical safety mechanism for preventing the accidental exposure of development-only authentication endpoints in a production environment. It acts as a guardrail to ensure that a development endpoint capable of minting access tokens for any user is never enabled when the application is running with the "prod" profile.

## Purpose

In development environments, it's common to have convenience endpoints that simplify testing, such as endpoints that generate authentication tokens without requiring full credentials. However, such endpoints represent a severe security risk if they become active in production. This class automatically checks at application startup whether both conditions are true:

1. The development mint endpoint is enabled via configuration (`app.auth.dev.mint-endpoint-enabled=true`)
2. The "prod" Spring profile is active

If both conditions are met, the application fails to start with a clear, descriptive error message, preventing a potentially catastrophic security vulnerability.

## Class Details

| Aspect | Description |
|--------|-------------|
| **Package** | `com.upmatches.app.features.auth.configurations` |
| **Annotations** | `@Configuration` |
| **Dependencies** | `AuthDevProperties`, `Environment` |

## Constructor

### `DevAuthSafetyCheck(AuthDevProperties, Environment)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `authDevProperties` | `AuthDevProperties` | Configuration properties containing the development endpoint flag |
| `environment` | `Environment` | Spring's environment abstraction for accessing active profiles |

## Methods

### `verify()` (package-private)

| Aspect | Details |
|--------|---------|
| **Visibility** | Package-private (default) |
| **Annotation** | `@PostConstruct` |
| **Return Type** | `void` |
| **Throws** | `IllegalStateException` if both conditions are met |

This method performs the core safety check:

1. Retrieves the value of `authDevProperties.mintEndpointEnabled()` and checks if it equals `Boolean.TRUE`
2. Gets the list of active Spring profiles from the environment and checks if "prod" is among them
3. If both conditions are true, throws an `IllegalStateException` with a descriptive error message

The method is annotated with `@PostConstruct`, meaning it executes automatically after the bean's dependencies are injected and before the bean is put into service. This ensures the safety check runs during application startup, preventing the application from starting in an unsafe configuration.

## Error Message

When the safety check fails, the application throws an `IllegalStateException` with the following message:

```
FATAL: app.auth.dev.mint-endpoint-enabled=true is not allowed when the 'prod' profile is active. 
This would expose an endpoint that mints access tokens for any user.
```

## Usage Example

```java
// In application-dev.yml (safe configuration)
app:
  auth:
    dev:
      mint-endpoint-enabled: true

// In application-prod.yml (safe configuration - endpoint disabled)
app:
  auth:
    dev:
      mint-endpoint-enabled: false

// In application-prod.yml (UNSAFE configuration - application will fail to start)
app:
  auth:
    dev:
      mint-endpoint-enabled: true  // This will cause startup failure
```

## Best Practices

- Always keep development endpoints disabled in production configuration files
- Use this safety check pattern for any feature that should never be active in production
- Consider adding similar checks for other development-only features
- Ensure your CI/CD pipeline tests both safe and unsafe configurations
