# DevAuthSafetyCheck

The `DevAuthSafetyCheck` class is a Spring Boot configuration component that provides a critical safety mechanism for development-only authentication features. Its primary purpose is to prevent the accidental exposure of a development endpoint that mints access tokens when the application is running in a production environment.

## Overview

This class acts as a runtime guard that checks whether the application has been misconfigured to enable a development-only token minting endpoint while the `prod` profile is active. If such a dangerous configuration is detected, it throws an `IllegalStateException` during application startup, effectively preventing the application from running in an insecure state.

## Class Details

- **Package:** `com.upmatches.app.features.auth.configurations`
- **Annotations:** `@Configuration`
- **Dependencies:** `AuthDevProperties`, `Environment`

## Constructor

The constructor injects two dependencies required for the safety check:

| Parameter | Type | Description |
|-----------|------|-------------|
| `authDevProperties` | `AuthDevProperties` | Configuration properties containing the development endpoint flag |
| `environment` | `Environment` | Spring's environment abstraction to access active profiles |

## Methods

### `verify()`

| Aspect | Details |
|--------|---------|
| **Visibility** | Package-private (default) |
| **Return Type** | `void` |
| **Annotation** | `@PostConstruct` |
| **Description** | Executes automatically after bean initialization to validate that the development token minting endpoint is not enabled in a production environment |

**Behavior:**

1. Retrieves the value of `authDevProperties.mintEndpointEnabled()` and checks if it is `true`
2. Retrieves the list of active Spring profiles from the environment
3. Checks if the `prod` profile is among the active profiles
4. If both conditions are true (dev endpoint enabled AND prod profile active), throws an `IllegalStateException` with a descriptive error message

**Error Message:**

```
FATAL: app.auth.dev.mint-endpoint-enabled=true is not allowed when the 'prod' profile is active. This would expose an endpoint that mints access tokens for any user.
```

## Usage

This class is automatically instantiated and executed by Spring Boot when the application context is loaded. No manual invocation is required. Simply include this class in your Spring Boot application, and it will automatically enforce the safety check during startup.

## Example Configuration

To properly use this safety check, ensure your `application-dev.yml` or `application-dev.properties` contains:

```yaml
app:
  auth:
    dev:
      mint-endpoint-enabled: true
```

And your `application-prod.yml` or `application-prod.properties` should either omit this property or set it to `false`:

```yaml
app:
  auth:
    dev:
      mint-endpoint-enabled: false
```

## Important Notes

- This check runs during application startup, preventing the application from starting in an insecure configuration
- The check is only performed once during the `@PostConstruct` phase
- If the application starts successfully, it means the configuration is safe
- This is a development safety feature and should not be removed or disabled in production builds
