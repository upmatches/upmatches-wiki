# DeleteNotificationService

The `DeleteNotificationService` class is a Spring service responsible for deleting a notification belonging to a specific authenticated user. It ensures that only the recipient of the notification can delete it, providing a secure deletion mechanism.

## Purpose

This service handles the business logic for deleting a notification by its unique identifier (`UUID`). It performs the following steps:
1. Resolves the currently authenticated user's ID.
2. Retrieves the notification that matches both the provided ID and the authenticated user's ID.
3. If the notification is not found, it throws a `NotificationNotFoundException`.
4. If found, it deletes the notification using the repository, wrapping the operation in a service executor for consistent error handling.

## Constructor

### `DeleteNotificationService(NotificationRepository, IAuthenticatedUserResolver)`

Initializes the service with required dependencies.

| Parameter | Type | Description |
|-----------|------|-------------|
| `notificationRepository` | `NotificationRepository` | Repository for accessing notification data |
| `userResolver` | `IAuthenticatedUserResolver` | Service to resolve the currently authenticated user |

## Public Methods

### `execute(UUID id)`

Deletes a notification by its ID, ensuring it belongs to the authenticated user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the notification to delete |

**Return Type:** `void`

**Throws:**
- `NotificationNotFoundException` – If no notification with the given ID exists for the authenticated user
- `ResourceNotFoundException` – If the deletion operation fails (wrapped by `ServiceOperationExecutor`)

**Behavior:**
1. Retrieves the authenticated user's ID via `userResolver.requireUserId()`
2. Queries the repository for a notification matching both `id` and `userId`
3. If not found, throws `NotificationNotFoundException` with a formatted message
4. If found, executes the deletion using `ServiceOperationExecutor.executeVoid()` with the `DELETE` operation status

## Error Handling

The service uses a consistent error handling pattern:
- **Not Found:** Custom `NotificationNotFoundException` with a message format: `"Notification '%s' not found for user '%s'."`
- **Operation Failure:** `ResourceNotFoundException` is thrown if the deletion operation fails, as defined by the `ServiceOperationExecutor`

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `NotificationRepository` | Spring Data Repository | Provides data access methods for `Notification` entities |
| `IAuthenticatedUserResolver` | Interface | Resolves the currently authenticated user's identity |
| `ServiceOperationExecutor` | Utility | Executes service operations with consistent error handling and logging |

## Transactional Behavior

The `execute` method is annotated with `@Transactional`, ensuring that the deletion operation is performed within a database transaction. If any exception occurs, the transaction will be rolled back automatically.
