# SendFcmTestNotificationService

## Purpose

The `SendFcmTestNotificationService` class is a Spring service bean, active only in the `dev` profile, designed for testing Firebase Cloud Messaging (FCM) push notifications and Resend email notifications. It provides a controlled environment for developers to simulate various notification types (e.g., player joined, game updated, reminders) without affecting production users.

This service implements the `ISendFcmTestNotificationService` interface and handles the complete lifecycle of a test notification: resolving notification content (title, body, badge), sending via FCM push and/or Resend email, and returning a response with the delivery identifiers.

## Key Features

- **Dual-channel delivery**: Supports sending both FCM push notifications and Resend emails in a single request.
- **Notification type simulation**: Covers all notification types defined in `NotificationType` enum (player events, game events, reminders).
- **Dynamic content resolution**: Automatically generates titles, bodies, and badge counts based on the notification type and request parameters.
- **Graceful fallback**: Uses `ObjectProvider` to handle missing Firebase or Resend beans, throwing `ExternalServiceException` when unavailable.
- **Email rendering**: Leverages `EmailContentRenderer` to build HTML email content with details tables and call-to-action buttons.

## Public Methods

### `execute`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `SendFcmTestNotificationRequest` | The test notification request containing device token, email, notification type, and optional parameters |

| Returns | Type | Description |
|---------|------|-------------|
| Response | `FcmTestNotificationResponse` | Contains the message ID (push), email ID, notification type, title, body, and badge count |

This is the main entry point for sending a test notification. It:
1. Resolves the notification title, body, court count, date, and badge based on the request.
2. Sends a push notification if a device token is provided.
3. Sends an email if an email address is provided.
4. Returns a consolidated response with delivery identifiers.

**Example usage:**
```java
SendFcmTestNotificationRequest request = new SendFcmTestNotificationRequest(
    "device-token-123",
    "user@example.com",
    NotificationType.PLAYER_JOINED,
    "Morning Badminton",
    "Sports Hall",
    2,
    LocalDate.now(),
    LocalTime.of(9, 0),
    LocalTime.of(11, 0),
    "Intermediate",
    "https://app.com/game/123",
    5
);

FcmTestNotificationResponse response = service.execute(request);
// response.messageId() -> "projects/.../messages/..."
// response.emailId() -> "email-id-456"
```

## Internal Methods

### `resolveTitle`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The type of notification to generate a title for |

| Returns | Type | Description |
|---------|------|-------------|
| Title | `String` | The resolved notification title |

Maps each `NotificationType` to a predefined title string (e.g., `PLAYER_JOINED` → "A player joined your game").

### `resolveBody`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The type of notification |
| `gameTitle` | `String` | The title of the game |
| `courtCount` | `int` | Number of courts (for reminders) |
| `date` | `LocalDate` | The game date (for reminders) |

| Returns | Type | Description |
|---------|------|-------------|
| Body | `String` | The resolved notification body text |

Generates the notification body message based on the type, using `String.format` with the provided parameters.

### `resolveBadge`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `SendFcmTestNotificationRequest` | The test notification request |

| Returns | Type | Description |
|---------|------|-------------|
| Badge count | `Integer` | The badge number (null if not applicable) |

Determines the badge count:
- Uses the request's badge value if provided.
- If an email is provided, queries the database for the user's unread notification count (capped at 999).
- Returns `null` if no email is provided and no badge is specified.

### `sendPush`

| Parameter | Type | Description |
|-----------|------|-------------|
| `deviceToken` | `String` | The FCM device token |
| `type` | `NotificationType` | The notification type |
| `title` | `String` | The notification title |
| `body` | `String` | The notification body |
| `badge` | `Integer` | The badge count (optional) |

| Returns | Type | Description |
|---------|------|-------------|
| Message ID | `String` | The FCM message ID |

Sends a push notification via Firebase Cloud Messaging. If a badge is provided, it configures both APNs (iOS) and Android notification badge settings.

### `sendEmail`

| Parameter | Type | Description |
|-----------|------|-------------|
| `email` | `String` | The recipient email address |
| `type` | `NotificationType` | The notification type |
| `title` | `String` | The email subject |
| `body` | `String` | The email body text |
| `context` | `EmailContext` | The email context for rendering HTML content |

| Returns | Type | Description |
|---------|------|-------------|
| Email ID | `String` | The Resend email ID |

Sends an HTML email via Resend. Builds the email content using `EmailContentRenderer` with a details table and call-to-action button.

### `buildEmailContext`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The notification type |
| `gameTitle` | `String` | The game title |
| `venue` | `String` | The venue name |
| `date` | `LocalDate` | The game date |
| `startTime` | `LocalTime` | The start time |
| `endTime` | `LocalTime` | The end time |
| `skillLevel` | `String` | The skill level |
| `courtCount` | `int` | Number of courts |
| `gameUrl` | `String` | The game URL |

| Returns | Type | Description |
|---------|------|-------------|
| Context | `EmailContext` | The email context object |

Constructs the `EmailContext` for email rendering. For `GAME_REMINDER_3_DAYS` type, it creates an aggregate reminder context.

### `buildData`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The notification type |

| Returns | Type | Description |
|---------|------|-------------|
| Data map | `Map<String, String>` | The FCM data payload |

Builds the FCM data payload containing the notification type and, for game-related notifications, a resource type and placeholder resource ID.

### `resolveCourtCount`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The notification type |
| `requested` | `Integer` | The requested court count (nullable) |

| Returns | Type | Description |
|---------|------|-------------|
| Court count | `int` | The resolved court count |

Returns the requested court count if provided, otherwise defaults to 3 for 3-day reminders and 1 for all other types.

### `resolveDate`

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The notification type |
| `requested` | `LocalDate` | The requested date (nullable) |

| Returns | Type | Description |
|---------|------|-------------|
| Date | `LocalDate` | The resolved date in Singapore time |

Returns the requested date if provided, otherwise defaults to 3 days from now for 3-day reminders and 1 day from now for all other types.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `FirebaseMessaging` | `ObjectProvider` | Firebase Cloud Messaging client for sending push notifications |
| `Resend` | `ObjectProvider` | Resend email client for sending transactional emails |
| `ResendProperties` | Configuration | Properties for Resend email configuration (from name, address) |
| `UserRepository` | Repository | Data access for user lookup by email |
| `NotificationRepository` | Repository | Data access for counting unread notifications |
| `EmailContentRenderer` | Utility | Helper class for building HTML email content |

## Error Handling

The service throws `ExternalServiceException` in the following scenarios:

| Scenario | Error Message |
|----------|---------------|
| FirebaseMessaging bean unavailable | "FirebaseMessaging bean is not available; cannot send dev FCM test notification." |
| Resend client unavailable | "Resend client is not available; cannot send dev test email." |
| FCM push send failure | "Failed to send dev FCM test push: {error message}" |
| Resend email send failure | "Failed to send dev test email: {error message}" |

## Profile Activation

This service is only active when the Spring profile `dev` is set. This ensures test notification functionality is isolated from production environments.

```yaml
# application-dev.yml
spring:
  profiles: dev
```
