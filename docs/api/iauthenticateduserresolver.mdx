# IAuthenticatedUserResolver Interface

The `IAuthenticatedUserResolver` interface defines a contract for resolving the currently authenticated user's unique identifier (UUID) within the application. It provides two methods to retrieve the user ID: one that throws an exception if the user is not authenticated, and another that returns an `Optional` to handle the absence of an authenticated user gracefully.

This interface is declared as a **sealed interface**, meaning only the permitted class `AuthenticatedUserResolver` can implement it. This design ensures controlled extension and a clear, single implementation path for resolving the authenticated user.

## Purpose

- **Centralize User Resolution**: Provides a single, consistent way to obtain the current user's ID across the application.
- **Handle Authentication States**: Offers both a strict (exception-throwing) and a safe (Optional-based) approach to handle cases where the user may or may not be authenticated.
- **Enforce Implementation Control**: The sealed keyword restricts implementation to `AuthenticatedUserResolver`, preventing unintended or unauthorized implementations.

## Public Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `requireUserId()` | `UUID` | Returns the unique identifier of the currently authenticated user. Throws an exception (e.g., `IllegalStateException` or a custom exception) if no user is authenticated. |
| `optionalUserId()` | `Optional<UUID>` | Returns an `Optional` containing the unique identifier of the currently authenticated user, or an empty `Optional` if no user is authenticated. |

## Usage Example

```java
// Using requireUserId() when a user must be authenticated
UUID userId = userResolver.requireUserId();

// Using optionalUserId() when authentication is optional
userResolver.optionalUserId().ifPresentOrElse(
    userId -> {
        // User is authenticated, proceed with userId
    },
    () -> {
        // No authenticated user, handle accordingly
    }
);
```

## Notes

- The interface is part of the `com.upmatches.app.features.game.services` package.
- The only permitted implementation is `AuthenticatedUserResolver`.
- The `requireUserId()` method is suitable for scenarios where the operation cannot proceed without an authenticated user.
- The `optionalUserId()` method is ideal for operations that can adapt to the presence or absence of an authenticated user.
