# InfisicalSecretProvider

## Purpose

The `InfisicalSecretProvider` class is a Spring Boot `EnvironmentPostProcessor` that integrates with [Infisical](https://infisical.com/) to securely fetch and inject secrets into the application's environment at startup. It provides a robust mechanism for managing sensitive configuration values such as API keys, signing keys, and service account credentials.

The class supports three modes of operation:
1. **Infisical Integration**: Fetches secrets from an Infisical project using machine-to-machine authentication
2. **Environment Variable Fallback**: Maps environment variables to application properties when Infisical is not configured
3. **.env File Support**: Loads environment variables from a `.env` file as a fallback

## Key Features

- **Secure Key Management**: Writes sensitive key material (e.g., JWK files) to temporary files with restricted POSIX permissions
- **Automatic Cleanup**: Registers a shutdown hook to clean up temporary files on application exit
- **Configurable Mappings**: Supports predefined mappings between Infisical secret keys and Spring Boot configuration properties
- **Graceful Degradation**: Falls back to environment variables or `.env` files when Infisical is not configured

## Public Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `postProcessEnvironment(ConfigurableEnvironment, SpringApplication)` | `void` | Main entry point called by Spring Boot during environment post-processing. Loads `.env` file, resolves Infisical configuration, and fetches secrets if configured. |

## Configuration Properties

The following properties can be configured in `application.properties` or `application.yml`:

| Property | Environment Variable | Required | Default | Description |
|----------|---------------------|----------|---------|-------------|
| `app.infisical.client-id` | `INFISICAL_CLIENT_ID` | Yes (for Infisical mode) | - | Infisical client ID for authentication |
| `app.infisical.client-secret` | `INFISICAL_CLIENT_SECRET` | Yes (for Infisical mode) | - | Infisical client secret for authentication |
| `app.infisical.project-id` | `INFISICAL_PROJECT_ID` | Yes (for Infisical mode) | - | Infisical project ID |
| `app.infisical.host-uri` | `INFISICAL_HOST_URI` | No | `https://app.infisical.com` | Infisical API host URI |
| `app.infisical.environment` | `INFISICAL_ENVIRONMENT` | No | `dev` | Infisical environment (e.g., dev, staging, prod) |
| `app.infisical.secret-path` | `INFISICAL_SECRET_PATH` | No | `/` | Path within Infisical to fetch secrets from |

## Secret Mappings

### Key Secrets (Written to Temporary Files)

These secrets contain key material that is written to secure temporary files with restricted permissions:

| Infisical Secret Key | Application Property |
|---------------------|---------------------|
| `SINGPASS_PRIVATE_SIGNING_KEY` | `app.singpass.private-signing-key-path` |
| `SINGPASS_PRIVATE_ENCRYPTION_KEY` | `app.singpass.private-encryption-key-path` |

### Configuration Secrets (Injected Directly)

These secrets are injected directly into the Spring environment:

| Infisical Secret Key | Application Property |
|---------------------|---------------------|
| `AUTH0_CLIENT_SECRET` | `app.auth0.client-secret` |
| `FIREBASE_ADMIN_SDK` | `app.firebase.service-account-json` |

## Usage Example

```java
// The InfisicalSecretProvider is automatically invoked by Spring Boot
// during application startup. No manual instantiation is required.

// Configure in application.properties:
app.infisical.client-id=${INFISICAL_CLIENT_ID}
app.infisical.client-secret=${INFISICAL_CLIENT_SECRET}
app.infisical.project-id=${INFISICAL_PROJECT_ID}

// Access injected secrets in your application:
@Value("${app.auth0.client-secret}")
private String auth0ClientSecret;

@Value("${app.singpass.private-signing-key-path}")
private String signingKeyPath;
```

## Security Considerations

- **Temporary File Permissions**: Key files are created with `rw-------` (owner read/write) permissions initially, then restricted to `r--------` (owner read-only) after writing
- **Automatic Cleanup**: Temporary files are deleted on application shutdown via a registered shutdown hook
- **No Logging of Secrets**: The logger only logs metadata (e.g., "Wrote secret 'X' to temporary file"), never the actual secret values
- **Fail-Fast Behavior**: If Infisical is configured but unreachable, the application throws an `IllegalStateException` to prevent insecure startup

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Infisical client ID not configured | Falls back to environment variable mapping |
| Infisical authentication fails | Throws `IllegalStateException` |
| No secrets returned from Infisical | Throws `IllegalStateException` |
| `.env` file not found | Silently continues without loading |
| Temporary file creation fails | Throws `IllegalStateException` |
