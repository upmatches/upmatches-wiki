# InfisicalSecretProvider

## Purpose

The `InfisicalSecretProvider` class is a Spring Boot `EnvironmentPostProcessor` that integrates with [Infisical](https://infisical.com/) to securely fetch and inject secrets into the application's environment at startup. It acts as a bridge between Infisical's secret management platform and Spring's configuration system, ensuring sensitive values like API keys, signing keys, and service account credentials are never hardcoded or stored in plain text configuration files.

The class supports multiple fallback strategies for secret resolution:
1. **Primary**: Fetch secrets directly from Infisical using machine-to-machine authentication
2. **Fallback**: Read secrets from environment variables when Infisical is not configured
3. **Local Development**: Load secrets from a `.env` file for local development scenarios

## Key Features

- **Secure Key Storage**: Writes sensitive key material (e.g., SingPass keys) to temporary files with restricted POSIX permissions (owner-read only)
- **Automatic Cleanup**: Registers a JVM shutdown hook to clean up temporary files on application exit
- **Configurable Mappings**: Maps Infisical secret keys to Spring configuration properties
- **Multiple Resolution Sources**: Supports properties, environment variables, and system properties with a defined precedence order
- **Fail-Fast on Missing Credentials**: Throws `IllegalStateException` if required Infisical authentication credentials are missing

## Configuration Properties

The following properties control the Infisical integration. They can be set as Spring properties or environment variables:

| Property Key | Environment Variable | Required | Default Value | Description |
|-------------|---------------------|----------|---------------|-------------|
| `app.infisical.client-id` | `INFISICAL_CLIENT_ID` | Yes | - | Infisical machine-to-machine client ID |
| `app.infisical.client-secret` | `INFISICAL_CLIENT_SECRET` | Yes | - | Infisical machine-to-machine client secret |
| `app.infisical.project-id` | `INFISICAL_PROJECT_ID` | Yes | - | Infisical project ID |
| `app.infisical.host-uri` | `INFISICAL_HOST_URI` | No | `https://app.infisical.com` | Infisical API host URI |
| `app.infisical.environment` | `INFISICAL_ENVIRONMENT` | No | `dev` | Infisical environment (e.g., dev, staging, prod) |
| `app.infisical.secret-path` | `INFISICAL_SECRET_PATH` | No | `/` | Path within Infisical to fetch secrets from |

## Secret Mappings

The class defines two categories of secret mappings:

### Key Secrets (Written to Temporary Files)
These secrets contain cryptographic key material that must be stored as files:

| Infisical Secret Key | Spring Property | Description |
|---------------------|-----------------|-------------|
| `SINGPASS_PRIVATE_SIGNING_KEY` | `app.singpass.private-signing-key-path` | SingPass private signing key (written to temp file) |
| `SINGPASS_PRIVATE_ENCRYPTION_KEY` | `app.singpass.private-encryption-key-path` | SingPass private encryption key (written to temp file) |

### Configuration Secrets (Injected Directly)
These secrets are injected directly into the Spring environment:

| Infisical Secret Key | Spring Property | Description |
|---------------------|-----------------|-------------|
| `AUTH0_CLIENT_SECRET` | `app.auth0.client-secret` | Auth0 client secret |
| `FIREBASE_ADMIN_SDK` | `app.firebase.service-account-json` | Firebase Admin SDK service account JSON |

## Public Methods

### `postProcessEnvironment(ConfigurableEnvironment environment, SpringApplication application)`

The main entry point called by Spring Boot during application startup.

| Parameter | Type | Description |
|-----------|------|-------------|
| `environment` | `ConfigurableEnvironment` | The Spring environment to modify |
| `application` | `SpringApplication` | The Spring application instance |

**Behavior:**
1. Attempts to load a `.env` file from the current working directory
2. Resolves Infisical configuration from properties/environment variables
3. If Infisical is configured, fetches secrets and injects them into the environment
4. If Infisical is not configured, falls back to environment variable resolution

### `setDotEnvPath(Path path)`

Sets a custom path for the `.env` file (primarily used for testing).

| Parameter | Type | Description |
|-----------|------|-------------|
| `path` | `Path` | Custom path to the `.env` file |

## Internal Methods

### `resolveConfig(ConfigurableEnvironment environment)`
Resolves Infisical configuration from available sources. Returns `null` if no client ID is configured.

### `fetchSecrets(InfisicalConfig config, ConfigurableEnvironment environment)`
Connects to Infisical, authenticates using machine-to-machine auth, fetches secrets, and processes them.

### `loadDotEnvFile(ConfigurableEnvironment environment)`
Loads environment variables from a `.env` file and adds them to the Spring environment.

### `mapEnvVarSecrets(ConfigurableEnvironment environment)`
Fallback method that reads secrets directly from environment variables when Infisical is not configured.

### `processSecrets(List<Secret> secrets)`
Processes fetched secrets, writing key material to temporary files and mapping configuration values.

### `writeSecureTemporaryFile(String content)`
Creates a temporary file with restricted permissions (owner-read only) and returns its absolute path.

### `registerShutdownHookOnce()`
Registers a JVM shutdown hook to clean up temporary files (ensures it runs only once).

### `cleanupTempFiles()`
Cleans up all temporary files created during secret processing.

## Usage Example

```java
// The provider is automatically invoked by Spring Boot during startup.
// No explicit instantiation is required.

// Configure in application.properties:
app.infisical.client-id=${INFISICAL_CLIENT_ID}
app.infisical.client-secret=${INFISICAL_CLIENT_SECRET}
app.infisical.project-id=${INFISICAL_PROJECT_ID}

// Access injected secrets in your application:
@Value("${app.singpass.private-signing-key-path}")
private String signingKeyPath;

@Value("${app.auth0.client-secret}")
private String auth0ClientSecret;
```

## Error Handling

- **Missing Required Credentials**: Throws `IllegalStateException` if `INFISICAL_CLIENT_ID` is configured but `INFISICAL_CLIENT_SECRET` or `INFISICAL_PROJECT_ID` are missing
- **Connection Failures**: Throws `IllegalStateException` wrapping the original exception with a descriptive message
- **Empty Secrets**: Throws `IllegalStateException` if Infisical returns no secrets for the configured environment
- **File System Errors**: Throws `IllegalStateException` if temporary file creation fails
- **Cleanup Failures**: Logs warnings but does not prevent application shutdown

## Security Considerations

- Temporary files are created with POSIX permissions `r--------` (owner read only) on supported systems
- Key material is never logged or exposed in error messages
- Temporary files are cleaned up on JVM shutdown
- The `.env` file is only loaded for local development and should not be used in production
- All secrets are injected into the Spring environment at the highest priority level
