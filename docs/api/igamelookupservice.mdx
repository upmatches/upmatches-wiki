## Overview

The `IGameLookupService` interface defines a contract for retrieving domain entities within the game management context. It serves as a centralized lookup service that provides type-safe methods for fetching core business objects such as `Game`, `Activity`, `Venue`, `User`, and `SkillLevel` by their respective identifiers.

This interface is declared as a **sealed interface**, meaning only explicitly permitted classes (in this case, `GameLookupService`) can implement it. This design enforces a controlled implementation hierarchy and ensures that all lookup operations follow a consistent pattern.

## Purpose

The primary purpose of this interface is to abstract the retrieval of domain entities from their persistence layer. By providing dedicated lookup methods, it promotes:

- **Consistency**: All entity lookups follow the same pattern and error handling strategy.
- **Type Safety**: Each method returns a specific entity type, eliminating the need for casting.
- **Separation of Concerns**: The interface isolates lookup logic from business logic, making the codebase more maintainable and testable.

## Methods

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findGameOrThrow` | `Game` | `UUID id` | Retrieves a game by its unique identifier. Throws an exception if the game is not found. |
| `findGameForUpdateOrThrow` | `Game` | `UUID id` | Retrieves a game with a pessimistic lock for update operations. Throws an exception if not found. |
| `findGameIgnoringDeletedOrThrow` | `Game` | `UUID id` | Retrieves a game even if it has been soft-deleted. Throws an exception if not found. |
| `findActivityOrThrow` | `Activity` | `UUID id` | Retrieves an activity by its unique identifier. Throws an exception if not found. |
| `findVenueOrThrow` | `Venue` | `Long id` | Retrieves a venue by its unique identifier. Throws an exception if not found. |
| `findUserOrThrow` | `User` | `UUID id` | Retrieves a user by their unique identifier. Throws an exception if not found. |
| `findUserForUpdateOrThrow` | `User` | `UUID id` | Retrieves a user with a pessimistic lock for update operations. Throws an exception if not found. |
| `findSkillLevelOrThrow` | `SkillLevel` | `Long id` | Retrieves a skill level by its unique identifier. Throws an exception if not found. |

## Usage Notes

- All methods follow the "or throw" naming convention, indicating that they will throw an exception (typically a `NotFoundException` or similar) if the requested entity does not exist.
- The interface uses `UUID` for `Game`, `Activity`, and `User` identifiers, while `Venue` and `SkillLevel` use `Long` identifiers.
- The `findGameForUpdateOrThrow` and `findUserForUpdateOrThrow` methods are designed for scenarios where concurrent modifications need to be prevented, typically by acquiring a database-level lock.
- The `findGameIgnoringDeletedOrThrow` method is useful for administrative operations where soft-deleted records need to be accessed.

## Implementation

The only permitted implementation of this interface is `GameLookupService`. Implementations must provide concrete logic for each lookup method, typically delegating to corresponding repository classes and handling the "not found" scenarios by throwing appropriate exceptions.
