# IGameLookupService Interface

The `IGameLookupService` interface defines a contract for retrieving core domain entities within the game management system. It serves as a centralized lookup service that provides type-safe methods for fetching `Game`, `Activity`, `Venue`, `User`, and `SkillLevel` entities by their respective identifiers.

This interface is declared as a **sealed interface**, meaning only the permitted implementation (`GameLookupService`) can implement it. This design pattern enforces controlled extensibility and ensures that all lookup operations follow a consistent contract.

## Purpose

- Provides a unified API for entity retrieval across the game service layer
- Ensures consistent error handling through `orThrow` method naming convention
- Supports different lookup semantics (standard find, find for update, find ignoring soft-deleted records)
- Enforces type safety with specific identifier types (`UUID` for most entities, `Long` for `Venue` and `SkillLevel`)

## Method Summary

| Method | Return Type | Parameter(s) | Description |
|--------|-------------|--------------|-------------|
| `findGameOrThrow` | `Game` | `UUID id` | Retrieves a game by its UUID. Throws an exception if not found. |
| `findGameForUpdateOrThrow` | `Game` | `UUID id` | Retrieves a game with a pessimistic lock for update operations. Throws if not found. |
| `findGameIgnoringDeletedOrThrow` | `Game` | `UUID id` | Retrieves a game regardless of its soft-delete status. Throws if not found. |
| `findActivityOrThrow` | `Activity` | `UUID id` | Retrieves an activity by its UUID. Throws if not found. |
| `findVenueOrThrow` | `Venue` | `Long id` | Retrieves a venue by its numeric identifier. Throws if not found. |
| `findUserOrThrow` | `User` | `UUID id` | Retrieves a user by their UUID. Throws if not found. |
| `findUserForUpdateOrThrow` | `User` | `UUID id` | Retrieves a user with a pessimistic lock for update operations. Throws if not found. |
| `findSkillLevelOrThrow` | `SkillLevel` | `Long id` | Retrieves a skill level by its numeric identifier. Throws if not found. |

## Usage Notes

- All methods follow the "orThrow" pattern, indicating they will throw an appropriate exception (typically a `NotFoundException` or similar) when the requested entity does not exist
- The `findGameForUpdateOrThrow` and `findUserForUpdateOrThrow` methods are designed for concurrent update scenarios where database-level locking is required
- The `findGameIgnoringDeletedOrThrow` method is useful for administrative operations that need to access soft-deleted records
- Identifier types are intentionally different: `UUID` for `Game`, `Activity`, and `User` entities; `Long` for `Venue` and `SkillLevel` entities

## Implementation

This interface is implemented by the `GameLookupService` class. The implementation should provide concrete database access logic for each method while adhering to the contract defined by this interface.
