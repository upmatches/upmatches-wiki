# RecordAuditEventService

## Purpose

The `RecordAuditEventService` is a Spring service class responsible for recording audit events in the application. It implements the `IRecordAuditEventService` interface and provides a transactional mechanism to persist audit events to the database while simultaneously logging them to a dedicated audit logger.

This service ensures that audit events are reliably stored and logged, with built-in error handling to prevent audit failures from impacting the main application flow. It uses a separate transaction (`REQUIRES_NEW` propagation) to ensure audit records are committed independently of the calling transaction.

## Public Methods

### `record(AuditEventRequest request)`

Records an audit event by persisting it to the database and logging it to the audit logger.

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `AuditEventRequest` | The audit event request containing all event details (actor, action, resource, outcome, etc.) |

**Return Type:** `void`

**Behavior:**
1. Builds an `AuditEvent` entity from the request using the `buildEvent` method.
2. Persists the event to the database using `ServiceOperationExecutor` with `OperationStatus.SAVE`.
3. Emits a structured JSON log entry to the dedicated audit logger.
4. Catches any `RuntimeException` and logs the failure without rethrowing, ensuring audit failures don't propagate.

**Transactional Behavior:** Uses `@Transactional(propagation = Propagation.REQUIRES_NEW)` to ensure the audit event is saved in a separate transaction, independent of any parent transaction.

**Return Type:** `AuditEvent`

### `emitLog(AuditEventRequest request)`

Generates and writes a structured JSON log entry to the dedicated audit logger.

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `AuditEventRequest` | The audit event request containing all event details |

**Behavior:**
1. Builds a `LinkedHashMap` with structured audit fields (action, category, outcome, actor details, resource details, correlation ID, IP address, error code).
2. Serializes the map to JSON using `ObjectMapper`.
3. Logs the JSON string to the `AUDIT` logger at INFO level.
4. Falls back to logging the map directly if JSON serialization fails.

## Logging

The service uses two loggers:
- **AUDIT Logger** (`AUDIT`): Dedicated logger for structured audit log entries in JSON format.
- **Application Logger** (`RecordAuditEventService.class`): For logging failures and errors during audit event processing.

## Error Handling

- If the database save operation fails, the error is logged but not propagated to the caller.
- If JSON serialization of the audit log fails, the service falls back to logging the raw map structure.
- All runtime exceptions during audit recording are caught and logged with the action and actor ID for traceability.
