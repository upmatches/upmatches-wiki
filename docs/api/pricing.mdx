## Purpose

The `Pricing` record is a value object that encapsulates different pricing models for a service or product. It supports three distinct pricing modes:

- **Flat**: A single price for all users.
- **Gendered**: Different prices for male and female users.
- **Shuttlecock**: A base price plus a per-shuttle price.

The record enforces strict validation rules to ensure that only the fields relevant to the selected pricing mode are populated, and that all monetary amounts are non-negative.

## Constructor

The canonical constructor performs the following validations:

- `mode` and `currency` must not be `null`.
- All `BigDecimal` fields must be non-negative (or `null`).
- The combination of fields must be valid for the selected `PricingMode`:
  - `FLAT`: requires `flatPrice`; all other price fields must be `null`.
  - `GENDERED`: requires `malePrice` and `femalePrice`; `flatPrice`, `basePrice`, and `pricePerShuttle` must be `null`.
  - `SHUTTLECOCK`: requires `basePrice` and `pricePerShuttle`; `flatPrice`, `malePrice`, and `femalePrice` must be `null`.

## Public Methods

### Static Factory Methods

| Method | Parameters | Return Type | Description |
|--------|------------|-------------|-------------|
| `flat` | `BigDecimal amount, Currency currency` | `Pricing` | Creates a `Pricing` instance with `FLAT` mode. |
| `gendered` | `BigDecimal male, BigDecimal female, Currency currency` | `Pricing` | Creates a `Pricing` instance with `GENDERED` mode. |
| `shuttlecock` | `BigDecimal base, BigDecimal perShuttle, Currency currency` | `Pricing` | Creates a `Pricing` instance with `SHUTTLECOCK` mode. |

### Instance Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `representativeAmount()` | `BigDecimal` | Returns a single representative price for backward compatibility: <ul><li>`FLAT`: the flat price</li><li>`GENDERED`: the lower of male and female prices</li><li>`SHUTTLECOCK`: the base price</li></ul> |
| `semanticEquals(Pricing other)` | `boolean` | Compares two `Pricing` instances using `BigDecimal.compareTo()` for scale-tolerant equality. This is useful when comparing values from different sources (e.g., API vs. database) where scale may differ. |

## Record Components

| Component | Type | Description |
|-----------|------|-------------|
| `mode` | `PricingMode` | The pricing mode (FLAT, GENDERED, or SHUTTLECOCK). |
| `currency` | `Currency` | The currency of all monetary amounts. |
| `flatPrice` | `BigDecimal` | The flat price (used only in FLAT mode). |
| `malePrice` | `BigDecimal` | The male price (used only in GENDERED mode). |
| `femalePrice` | `BigDecimal` | The female price (used only in GENDERED mode). |
| `basePrice` | `BigDecimal` | The base price (used only in SHUTTLECOCK mode). |
| `pricePerShuttle` | `BigDecimal` | The price per shuttle (used only in SHUTTLECOCK mode). |

## Usage Example

```java
// Create a flat pricing of $10.00 USD
Pricing flatPricing = Pricing.flat(new BigDecimal("10.00"), Currency.getInstance("USD"));

// Create gendered pricing
Pricing genderedPricing = Pricing.gendered(
    new BigDecimal("12.00"),
    new BigDecimal("10.00"),
    Currency.getInstance("USD")
);

// Create shuttlecock pricing
Pricing shuttlePricing = Pricing.shuttlecock(
    new BigDecimal("5.00"),
    new BigDecimal("2.50"),
    Currency.getInstance("USD")
);

// Get representative amount
BigDecimal repAmount = flatPricing.representativeAmount(); // 10.00

// Compare with scale tolerance
Pricing other = Pricing.flat(new BigDecimal("10"), Currency.getInstance("USD"));
boolean equal = flatPricing.semanticEquals(other); // true (10.00 vs 10)
```

## Validation Rules

The record enforces the following constraints:

1. **Mode and Currency**: Both must be non-null.
2. **Non-negative amounts**: All `BigDecimal` fields must be non-negative (or `null`).
3. **Mode-specific field requirements**:
   - `FLAT`: `flatPrice` must be non-null; all other price fields must be null.
   - `GENDERED`: `malePrice` and `femalePrice` must be non-null; `flatPrice`, `basePrice`, and `pricePerShuttle` must be null.
   - `SHUTTLECOCK`: `basePrice` and `pricePerShuttle` must be non-null; `flatPrice`, `malePrice`, and `femalePrice` must be null.
