# ExpelParticipantService

## Purpose

The `ExpelParticipantService` is a Spring service class responsible for handling the expulsion of a participant from a game. It enforces business rules such as preventing an organizer from expelling themselves, validates that the participant exists and is active, and publishes a notification event upon successful expulsion.

This service implements the `IExpelParticipantService` interface and is annotated with `@Service` and `@Transactional` to ensure database consistency.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Persistence layer for game participant entities |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user's ID |
| `IGameLookupService` | Service | Retrieves game entities by ID |
| `IGameAuthorizationService` | Service | Validates that the current user is the game organizer |
| `ApplicationEventPublisher` | Spring Event | Publishes domain events for notification purposes |

## Public Methods

### `execute`

```java
@Transactional
@Auditable(action = "PARTICIPANT_EXPELLED", resourceType = "GAME", resourceIdExpression = "#args[0]")
public void execute(UUID gameId, UUID participantId, ExpelParticipantRequest request)
```

Expels a participant from a game. This method performs the following steps:

1. Resolves the authenticated user's ID.
2. Retrieves the game and verifies the user is the organizer.
3. Finds the active participant record for the given participant ID within the specified game.
4. Validates that the organizer is not attempting to expel themselves.
5. Marks the participant as having left the game.
6. Persists the change.
7. Publishes a `GameNotificationEvent` of type `PLAYER_REMOVED_FROM_GAME`.

#### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `gameId` | `UUID` | The unique identifier of the game |
| `participantId` | `UUID` | The unique identifier of the participant to expel |
| `request` | `ExpelParticipantRequest` | Contains the reason for expulsion |

#### Throws

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | If the participant is not found in the game or is not active |
| `CannotExpelSelfException` | If the organizer attempts to expel themselves |

#### Audit Trail

This method is annotated with `@Auditable`, which automatically records an audit event with:
- **Action**: `PARTICIPANT_EXPELLED`
- **Resource Type**: `GAME`
- **Resource ID**: The game ID (first argument)

#### Logging

On successful expulsion, the service logs the following information at INFO level:
- Organizer user ID
- Participant ID
- Expelled user ID
- Game ID
- Expulsion reason

## Example Usage

```java
@Autowired
private ExpelParticipantService expelParticipantService;

public void expelPlayer(UUID gameId, UUID participantId, String reason) {
    ExpelParticipantRequest request = new ExpelParticipantRequest(reason);
    expelParticipantService.execute(gameId, participantId, request);
}
```

## Business Rules

1. **Self-expulsion prevention**: An organizer cannot expel themselves from the game. They must use the leave functionality instead.
2. **Active participant only**: Only participants with `ParticipantStatus.ACTIVE` can be expelled.
3. **Organizer authorization**: Only the game organizer can expel participants.
4. **Notification**: The expelled user receives a `PLAYER_REMOVED_FROM_GAME` notification.

## Related Components

- `GameParticipant` - The entity representing a participant in a game
- `ExpelParticipantRequest` - The request DTO containing the expulsion reason
- `GameNotificationEvent` - The event published for notification purposes
