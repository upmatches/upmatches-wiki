# ExpelParticipantService

## Purpose

The `ExpelParticipantService` is a Spring service responsible for handling the expulsion of a participant from a game. It ensures that only the game organizer can expel participants, prevents self-expulsion (which should be handled by a separate "leave" operation), and publishes appropriate notifications upon successful expulsion.

This service implements the `IExpelParticipantService` interface and is annotated with `@Service` and `@Transactional` to ensure proper transaction management.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Data access for game participants |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Retrieves game entities by ID |
| `IGameAuthorizationService` | Service | Validates organizer permissions |
| `ApplicationEventPublisher` | Spring Event | Publishes notification events |

## Public Methods

### `execute(UUID gameId, UUID participantId, ExpelParticipantRequest request)`

Expels a participant from a game. This method is transactional and auditable.

#### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `gameId` | `UUID` | The unique identifier of the game |
| `participantId` | `UUID` | The unique identifier of the participant to expel |
| `request` | `ExpelParticipantRequest` | Contains the reason for expulsion |

#### Returns

`void`

#### Exceptions

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | Participant not found in the specified game, or participant is not active |
| `CannotExpelSelfException` | The organizer attempts to expel themselves |
| `AuthorizationException` | The current user is not the game organizer |

#### Behavior

1. **Authentication**: Resolves the currently authenticated user ID
2. **Game Lookup**: Retrieves the game entity or throws `ResourceNotFoundException`
3. **Authorization**: Verifies the current user is the game organizer
4. **Participant Validation**: Finds the participant by ID, ensuring they belong to the specified game and have `ACTIVE` status
5. **Self-Expulsion Check**: Prevents the organizer from expelling themselves
6. **Status Update**: Calls `participant.leave()` to update the participant's status
7. **Persistence**: Saves the updated participant using `ServiceOperationExecutor`
8. **Notification**: Publishes a `GameNotificationEvent` of type `PLAYER_REMOVED_FROM_GAME` to the expelled user

#### Audit Trail

This method is annotated with `@Auditable`:
- **Action**: `PARTICIPANT_EXPELLED`
- **Resource Type**: `GAME`
- **Resource ID Expression**: `#args[0]` (the game ID)

## Logging

The service logs the following information upon successful expulsion:
- Organizer ID
- Participant ID
- Expelled user ID
- Game ID
- Expulsion reason

## Usage Example

```java
@Autowired
private ExpelParticipantService expelParticipantService;

public void expelPlayer(UUID gameId, UUID participantId, String reason) {
    ExpelParticipantRequest request = new ExpelParticipantRequest(reason);
    expelParticipantService.execute(gameId, participantId, request);
}
```
