# IGameJoinabilityService Interface

The `IGameJoinabilityService` interface defines the contract for determining whether a viewer can join a game session. It provides methods to evaluate joinability for individual games and batch operations, considering factors such as participant counts, game state, and user identity.

This sealed interface permits only `GameJoinabilityService` as its implementation, ensuring controlled extension and type safety within the game joinability domain.

## Interface Definition

```java
public sealed interface IGameJoinabilityService permits GameJoinabilityService {
    // Methods defined below
}
```

## Methods

### `compute`

Evaluates joinability for a single game based on current participant count and requesting user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `game` | `Game` | The game entity to evaluate for joinability |
| `participantCount` | `long` | Current number of participants in the game |
| `userId` | `UUID` | Unique identifier of the user requesting to join |

**Returns:** `ViewerJoinabilityResponse` - A response object indicating whether the viewer can join and any relevant constraints or reasons.

### `computeBatch`

Evaluates joinability for multiple games simultaneously, allowing efficient batch processing.

| Parameter | Type | Description |
|-----------|------|-------------|
| `games` | `List<Game>` | List of game entities to evaluate |
| `participantCountsByGameId` | `Map<UUID, Long>` | Map of game IDs to their current participant counts |
| `userId` | `UUID` | Unique identifier of the user requesting to join |

**Returns:** `Map<UUID, ViewerJoinabilityResponse>` - A map of game IDs to their corresponding joinability responses.

## Usage Example

```java
// Single game evaluation
ViewerJoinabilityResponse response = joinabilityService.compute(
    game, 
    game.getParticipantCount(), 
    currentUserId
);

if (response.canJoin()) {
    // Allow user to join the game
} else {
    // Show reason why user cannot join
    System.out.println("Cannot join: " + response.getReason());
}

// Batch evaluation for multiple games
List<Game> availableGames = gameRepository.findAvailableGames();
Map<UUID, Long> participantCounts = gameRepository.getParticipantCounts(availableGames);
Map<UUID, ViewerJoinabilityResponse> responses = joinabilityService.computeBatch(
    availableGames,
    participantCounts,
    currentUserId
);
```

## Implementation Notes

- The interface is sealed, meaning only `GameJoinabilityService` can implement it
- The `ViewerJoinabilityResponse` object typically contains:
  - `canJoin()` - boolean indicating joinability
  - `getReason()` - string explaining why join is denied (if applicable)
  - Additional metadata about game capacity or restrictions
- Batch processing is optimized for performance when evaluating multiple games simultaneously
