# PublicReadRateLimitFilter

## Purpose

The `PublicReadRateLimitFilter` is a Spring Boot servlet filter that implements rate limiting for public read endpoints in the UpMatches application. It extends `OncePerRequestFilter` to ensure each request is processed exactly once.

This filter protects three categories of endpoints from excessive usage:
- **Games**: `/api/v1/games/**`
- **Venues**: `/api/v1/venues`
- **Activities**: `/api/v1/activities/**`

Rate limits are enforced per client (identified by IP address or authenticated user subject) using Redis as the backing store. The filter differentiates between anonymous and authenticated users, applying different limits to each.

## Key Features

- **Redis-backed rate limiting** using atomic increment operations
- **Differentiated limits** for anonymous (60 requests/minute) and authenticated (240 requests/minute) users
- **Client identification** via JWT subject for authenticated users or `X-Forwarded-For` header / remote IP for anonymous users
- **RFC 9457 Problem Details** response format for rate limit exceeded errors
- **Conditional activation** via `@ConditionalOnBean(StringRedisTemplate.class)`

## Configuration

| Property | Value | Description |
|----------|-------|-------------|
| Anonymous limit | 60 | Maximum requests per minute for unauthenticated users |
| Authenticated limit | 240 | Maximum requests per minute for authenticated users |
| Window duration | 60 seconds | Time window for rate limit counting |

## Rate Limit Algorithm

1. **Request arrives** and passes the `shouldNotFilter` check (must be GET request to a monitored endpoint)
2. **Bucket resolution** maps the URI to a rate limit bucket
3. **Subject resolution** identifies the client (JWT subject for authenticated users, IP for anonymous)
4. **Redis increment** atomically increments the counter for the key `{bucketPrefix}{subject}`
5. **First request** sets the key expiration to 60 seconds
6. **Limit check** compares the counter against the appropriate limit (60 or 240)
7. **If exceeded**, returns HTTP 429 with Problem Details JSON
8. **If allowed**, continues the filter chain

## Response Format (Rate Limit Exceeded)

When the rate limit is exceeded, the filter returns an HTTP 429 response with `Content-Type: application/problem+json`:

```json
{
  "type": "https://upmatches.com/problems/rate-limit-exceeded",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded for 'games' endpoint. Retry after 60 seconds.",
  "instance": "/api/v1/games"
}
```

The response also includes a `Retry-After` header set to 60 seconds.

## Dependencies

- Spring Boot Web (`jakarta.servlet`)
- Spring Data Redis (`StringRedisTemplate`)
- Spring Security (`Authentication`, `Jwt`)
- Jackson (`ObjectMapper`)
- Spring Boot auto-configuration (`@ConditionalOnBean`)

## Usage Notes

- The filter is only activated when a `StringRedisTemplate` bean is available in the application context
- Only GET requests to the specified endpoints are rate-limited
- Authenticated users are identified by their JWT subject claim
- Anonymous users are identified by the first IP address in the `X-Forwarded-For` header, falling back to the remote address
- The filter uses a sliding window approach via Redis key expiration
