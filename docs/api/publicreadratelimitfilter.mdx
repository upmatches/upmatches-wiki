# PublicReadRateLimitFilter

## Purpose

The `PublicReadRateLimitFilter` is a Spring Boot servlet filter that implements rate limiting for public read-only API endpoints. It protects specific GET endpoints (`/api/v1/games`, `/api/v1/venues`, and `/api/v1/activities`) from excessive requests by tracking request counts per client in Redis.

The filter distinguishes between anonymous users (rate-limited by IP address) and authenticated users (rate-limited by JWT subject), applying different limits:
- **Anonymous users**: 60 requests per 60-second window
- **Authenticated users**: 240 requests per 60-second window

When a client exceeds their rate limit, the filter returns a `429 Too Many Requests` response with a `ProblemDetail` JSON body and a `Retry-After` header.

## Dependencies

- **Spring Boot**: `OncePerRequestFilter`, `ConditionalOnBean`
- **Spring Security**: `SecurityContextHolder`, `Jwt`
- **Redis**: `StringRedisTemplate`
- **Jackson**: `ObjectMapper`
- **Jakarta Servlet**: `FilterChain`, `HttpServletRequest`, `HttpServletResponse`

## Configuration

The filter is automatically activated when a `StringRedisTemplate` bean is available in the application context (via `@ConditionalOnBean(StringRedisTemplate.class)`).

## Internal Record

### `Bucket`

| Field | Type | Description |
|-------|------|-------------|
| `name` | `String` | Human-readable bucket name (e.g., "games", "venues", "activities") |
| `keyPrefix` | `String` | Redis key prefix for the bucket (e.g., "rl:public:games:") |

## Rate Limiting Algorithm

1. **Subject Resolution**: The filter determines the client identity:
   - If authenticated via JWT, uses the JWT subject
   - If anonymous, uses the client IP address (respecting `X-Forwarded-For` header)

2. **Key Construction**: Creates a Redis key combining the bucket prefix and the subject (e.g., `rl:public:games:user123`)

3. **Counter Increment**: Uses Redis `INCR` command to atomically increment the counter for the key

4. **Expiry Setting**: On the first request (counter = 1), sets a TTL of 60 seconds on the key

5. **Limit Check**: Compares the counter value against the applicable limit (60 for anonymous, 240 for authenticated)

6. **Response**: If the limit is exceeded, returns a 429 response; otherwise, continues the filter chain

## Response Format

When rate limited, the filter returns:

```json
{
  "type": "https://upmatches.com/problems/rate-limit-exceeded",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded for 'games' endpoint. Retry after 60 seconds.",
  "instance": "/api/v1/games"
}
```

With the following HTTP headers:
- `Content-Type: application/problem+json`
- `Retry-After: 60`

## Protected Endpoints

| Endpoint | Bucket Name | Redis Key Prefix |
|----------|-------------|------------------|
| `/api/v1/games/**` | games | `rl:public:games:` |
| `/api/v1/venues` | venues | `rl:public:venues:` |
| `/api/v1/activities/**` | activities | `rl:public:activities:` |

## Usage Example

```java
// The filter is automatically registered by Spring Boot
// No additional configuration is needed beyond having a StringRedisTemplate bean

// To customize limits, modify the constants:
private static final int ANONYMOUS_LIMIT = 60;      // Change to desired limit
private static final int AUTHENTICATED_LIMIT = 240;  // Change to desired limit
private static final long WINDOW_SECONDS = 60L;      // Change to desired window
```
