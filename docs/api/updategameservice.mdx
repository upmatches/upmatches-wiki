# UpdateGameService

The `UpdateGameService` class is a Spring service responsible for handling game update operations within the UpMatches application. It implements the `IUpdateGameService` interface and provides a comprehensive, transactional workflow for updating game details while enforcing business rules, authorization checks, and audit logging.

## Purpose

This service orchestrates the complete game update process, including:
- User authentication and authorization verification
- Game lookup and validation
- Immutable field protection
- Participant count validation
- Venue, skill level, and pricing resolution
- Database persistence with transactional integrity
- Audit logging via the `@Auditable` annotation
- Event publishing for notification systems

## Public Methods

### `execute`

```java
@Transactional
@Auditable(action = "GAME_UPDATED", resourceType = "GAME", resourceIdExpression = "#args[0]")
public GameResponse execute(UUID id, UpdateGameRequest request)
```

Updates an existing game with the provided request data.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to update |
| `request` | `UpdateGameRequest` | The request object containing updated game fields |

**Returns:** `GameResponse` - A response object containing the updated game details for the viewer.

**Throws:**
- `ResourceNotFoundException` if the game or related entities are not found
- Authorization exceptions if the user is not the organizer or validation fails

**Workflow:**
1. Resolves the authenticated user ID
2. Looks up the game for update or throws an exception
3. Verifies the user is the game organizer
4. Validates visibility hasn't changed
5. Counts active participants
6. Validates immutable fields haven't changed
7. Validates new slot count is above active participant count
8. Resolves and updates all game fields
9. Persists the updated game
10. Publishes a `GAME_UPDATED` notification event
11. Returns the game response

## Private Helper Methods

### `resolveVenue`

```java
private Venue resolveVenue(Game game, UpdateGameRequest request)
```

Resolves the venue for the update. Returns the venue from the request if provided, otherwise keeps the existing game venue.

### `resolveSkillLevelFrom`

```java
private SkillLevel resolveSkillLevelFrom(Game game, UpdateGameRequest request)
```

Resolves the starting skill level for the update. Returns the skill level from the request if provided, otherwise keeps the existing value.

### `resolveSkillLevelTo`

```java
private SkillLevel resolveSkillLevelTo(Game game, UpdateGameRequest request)
```

Resolves the ending skill level for the update. Returns the skill level from the request if provided, otherwise keeps the existing value.

### `resolveCurrency`

```java
private Currency resolveCurrency(Game game, UpdateGameRequest request)
```

Resolves the currency for pricing. Creates a new `Currency` instance from the request if provided, otherwise creates one from the existing game currency.

### `resolvePricing`

```java
private Pricing resolvePricing(Game game, UpdateGameRequest request)
```

Resolves the pricing for the update with the following precedence:
1. Structured `pricing` object on the request (if supplied)
2. Legacy `price` and optional `currency` fields on the request (for backward compatibility)
3. Existing pricing on the game (fallback)

## Usage Example

```java
@Autowired
private UpdateGameService updateGameService;

public void updateGameExample() {
    UUID gameId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
    UpdateGameRequest request = new UpdateGameRequest(
        null, // venueId (keep existing)
        null, // skillLevelFromId (keep existing)
        null, // skillLevelToId (keep existing)
        20,   // slots
        null, // startTime (keep existing)
        null, // endTime (keep existing)
        null, // gameType (keep existing)
        "Updated game remarks",
        null, // pricing (keep existing)
        null, // price (keep existing)
        null  // currency (keep existing)
    );
    
    GameResponse response = updateGameService.execute(gameId, request);
}
```

## Notes

- The service is annotated with `@Service` and is a `non-sealed` implementation of `IUpdateGameService`
- All update operations are wrapped in a single database transaction (`@Transactional`)
- Audit logging is automatically applied via the `@Auditable` annotation
- The service publishes domain events for notification processing
- Legacy pricing fields (`price` and `currency`) are supported for backward compatibility with older clients
