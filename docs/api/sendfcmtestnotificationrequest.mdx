# SendFcmTestNotificationRequest

## Purpose

The `SendFcmTestNotificationRequest` record is a Java data transfer object (DTO) used to encapsulate the payload for sending a test Firebase Cloud Messaging (FCM) notification. It defines the required and optional fields for constructing a notification, including validation constraints to ensure data integrity before processing.

This record is part of the notification feature in the UpMatches application and is designed to be used with Jakarta Bean Validation (e.g., Hibernate Validator) to enforce input rules.

## Fields

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `deviceToken` | `String` | `@Size(max = 512)` | The FCM device token to send the notification to. Either this or `email` must be provided. |
| `email` | `String` | `@Email`, `@Size(max = 254)` | The email address of the recipient. Either this or `deviceToken` must be provided. |
| `type` | `NotificationType` | `@NotNull` | The type of notification to send (e.g., GAME_INVITE, MATCH_REMINDER). |
| `gameTitle` | `String` | `@NotBlank`, `@Size(max = 120)` | The title of the game associated with the notification. |
| `venue` | `String` | `@Size(max = 120)` | The venue or location of the game. |
| `courtCount` | `Integer` | `@Min(1)`, `@Max(20)` | The number of courts for the game. |
| `date` | `LocalDate` | None | The date of the game. |
| `startTime` | `LocalTime` | None | The start time of the game. |
| `endTime` | `LocalTime` | None | The end time of the game. |
| `skillLevel` | `String` | `@Size(max = 60)` | The skill level required for the game (e.g., Beginner, Intermediate). |
| `gameUrl` | `String` | `@Size(max = 2048)` | A URL linking to the game details. |
| `badge` | `Integer` | `@Min(0)`, `@Max(999)` | A badge number to display on the notification icon. |

## Validation

The record includes a custom validation method `isTargetProvided()` annotated with `@AssertTrue`. This method ensures that at least one of `deviceToken` or `email` is provided (non-blank). If both are missing or blank, validation will fail with the message: "Either deviceToken or email must be provided".

## Usage Example

```java
SendFcmTestNotificationRequest request = new SendFcmTestNotificationRequest(
    "fcm_device_token_123",
    null,
    NotificationType.GAME_INVITE,
    "Sunday Pickup Soccer",
    "Central Park Field 3",
    2,
    LocalDate.of(2025, 6, 15),
    LocalTime.of(10, 0),
    LocalTime.of(12, 0),
    "Intermediate",
    "https://upmatches.app/game/456",
    5
);
```

## Notes

- This record is immutable by design (Java `record`), making it safe for use in concurrent environments.
- All validation annotations are from the `jakarta.validation.constraints` package, ensuring compatibility with Jakarta EE / Spring Boot validation frameworks.
- The `NotificationType` enum is expected to be defined in the `com.upmatches.app.features.notification.enums` package.
