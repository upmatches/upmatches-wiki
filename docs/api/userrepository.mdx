# UserRepository

The `UserRepository` interface provides data access operations for the `User` entity within the UpMatches application. It extends Spring Data JPA's `JpaRepository`, inheriting standard CRUD operations while adding custom query methods tailored to user authentication and identity management workflows.

## Purpose

This repository serves as the persistence layer for user records, supporting multiple authentication providers (Singpass, Auth0, Apple) and email-based lookups. It also includes a pessimistic locking mechanism for concurrency-safe user updates.

## Class Definition

```java
public interface UserRepository extends JpaRepository<User, UUID>
```

- **Package:** `com.upmatches.app.features.user.repositories`
- **Entity:** `User`
- **Primary Key Type:** `UUID`

## Methods

### Standard CRUD Methods

The following methods are inherited from `JpaRepository<User, UUID>`:

| Method | Description |
|--------|-------------|
| `save(User entity)` | Persists a new user or updates an existing one |
| `findById(UUID id)` | Retrieves a user by their UUID |
| `findAll()` | Returns all users |
| `delete(User entity)` | Removes a user record |
| `count()` | Returns the total number of users |

### Custom Query Methods

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findBySingpassUuid(String singpassUuid)` | `Optional<User>` | `singpassUuid` - The Singpass unique identifier | Finds a user by their Singpass UUID |
| `findByAuth0Uuid(String auth0UserId)` | `Optional<User>` | `auth0UserId` - The Auth0 user identifier | Finds a user by their Auth0 UUID |
| `findByAppleUuid(String appleUuid)` | `Optional<User>` | `appleUuid` - The Apple user identifier | Finds a user by their Apple UUID |
| `findFirstByEmail(String email)` | `Optional<User>` | `email` - The user's email address | Returns the first user matching the given email |
| `findForUpdateById(UUID id)` | `Optional<User>` | `id` - The user's UUID | Retrieves a user with a pessimistic write lock for safe concurrent updates |

## Method Details

### `findBySingpassUuid(String singpassUuid)`

Searches for a user who authenticated via Singpass. Returns an empty `Optional` if no match is found.

### `findByAuth0Uuid(String auth0UserId)`

Searches for a user who authenticated via Auth0. Returns an empty `Optional` if no match is found.

### `findByAppleUuid(String appleUuid)`

Searches for a user who authenticated via Apple Sign-In. Returns an empty `Optional` if no match is found.

### `findFirstByEmail(String email)`

Returns the first user record with the specified email address. Useful when email uniqueness is enforced at the application level rather than the database level.

### `findForUpdateById(UUID id)`

This method applies a `PESSIMISTIC_WRITE` lock to the selected row, preventing other transactions from modifying or reading the row until the current transaction completes. Use this method when performing critical updates that require exclusive access to the user record.

**Lock Behavior:**
- Acquires a database-level write lock
- Blocks other write transactions
- Blocks `PESSIMISTIC_READ` locks
- Does not block standard reads (non-locked queries)

## Usage Example

```java
@Service
public class UserService {
    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }

    @Transactional
    public void updateUserEmail(UUID userId, String newEmail) {
        User user = userRepository.findForUpdateById(userId)
            .orElseThrow(() -> new EntityNotFoundException("User not found"));
        user.setEmail(newEmail);
        userRepository.save(user);
    }
}
```
