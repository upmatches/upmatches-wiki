# SoftDeleteGameService

## Purpose

The `SoftDeleteGameService` class is a Spring service responsible for performing a soft delete operation on a `Game` entity. Instead of permanently removing a game from the database, this service marks the game as deleted, cancels it, and publishes a notification event to inform other parts of the system about the deletion.

This class implements the `ISoftDeleteGameService` interface and is annotated with `@Service`, making it a Spring-managed bean. It is declared as `non-sealed`, indicating it is part of a sealed interface hierarchy.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameRepository` | Repository | Data access layer for `Game` entities |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user's ID |
| `IGameLookupService` | Service | Provides game lookup functionality |
| `IGameAuthorizationService` | Service | Handles authorization checks for game operations |
| `ApplicationEventPublisher` | Spring Event | Publishes application events for notification purposes |

## Public Methods

### `execute(UUID id)`

Performs a soft delete operation on a game identified by the given UUID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to soft delete |

**Return Type:** `void`

**Behavior:**

1. **Authentication:** Retrieves the currently authenticated user's ID using `userResolver.requireUserId()`.
2. **Game Lookup:** Finds the game by its ID using `lookupService.findGameOrThrow(id)`. Throws a `ResourceNotFoundException` if the game does not exist.
3. **Authorization:** Verifies that the authenticated user is the organizer of the game using `authorizationService.assertIsOrganizer(game, userId)`. Throws an authorization exception if the user is not the organizer.
4. **State Changes:**
   - Calls `game.cancel()` to cancel the game.
   - Calls `game.markDeleted()` to mark the game as deleted (soft delete).
5. **Persistence:** Saves the updated game entity to the database using `ServiceOperationExecutor.execute()` with the `DELETE` operation status.
6. **Notification:** Publishes a `GameNotificationEvent` with:
   - The game's ID
   - The user's ID
   - `NotificationType.GAME_REMOVED`
   - The game's activity name (if available)

**Annotations:**
- `@Transactional`: Ensures the entire operation is executed within a database transaction.
- `@Auditable`: Records an audit log entry with action `"GAME_SOFT_DELETED"`, resource type `"GAME"`, and the game ID extracted from the method argument.

**Exceptions:**
- `ResourceNotFoundException`: Thrown if the game is not found or if the database save operation fails.
- Authorization exceptions: Thrown if the authenticated user is not the game organizer.

## Usage Example

```java
@Autowired
private SoftDeleteGameService softDeleteGameService;

public void deleteGame(UUID gameId) {
    softDeleteGameService.execute(gameId);
    // Game is now soft-deleted and a notification has been published
}
```

## Notes

- This service implements a soft delete pattern, meaning the game record remains in the database but is marked as deleted.
- The service publishes a notification event after successful deletion, allowing other components (e.g., email services, real-time updates) to react to the deletion.
- The `ServiceOperationExecutor` provides standardized error handling and logging for database operations.
