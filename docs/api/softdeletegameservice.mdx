# SoftDeleteGameService

The `SoftDeleteGameService` class is a Spring service responsible for performing a soft delete operation on a `Game` entity. Instead of permanently removing a game from the database, this service marks the game as deleted, allowing for potential recovery or audit trails. It ensures that only the authorized organizer of the game can perform this action and publishes a notification event upon successful deletion.

## Purpose

- **Soft Deletion**: Marks a game as deleted without physically removing it from the database.
- **Authorization**: Verifies that the requesting user is the organizer of the game.
- **Audit Logging**: Records the soft delete action via the `@Auditable` annotation.
- **Notification**: Publishes a `GameNotificationEvent` to notify other parts of the system about the removal.

## Dependencies

| Dependency | Description |
|------------|-------------|
| `GameRepository` | Repository for persisting game entities. |
| `IAuthenticatedUserResolver` | Resolves the currently authenticated user's ID. |
| `IGameLookupService` | Service for looking up games by ID. |
| `IGameAuthorizationService` | Service for checking user authorization (e.g., organizer check). |
| `ApplicationEventPublisher` | Spring's event publisher for sending application events. |

## Public Methods

### `execute(UUID id)`

Performs the soft delete operation on the game identified by the given ID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to soft delete. |

**Return Type:** `void`

**Behavior:**

1. **Resolve User**: Retrieves the ID of the currently authenticated user.
2. **Find Game**: Looks up the game by its ID; throws `ResourceNotFoundException` if not found.
3. **Authorize**: Checks that the authenticated user is the organizer of the game; throws an authorization exception if not.
4. **Soft Delete**: Calls `game.cancel()` and `game.markDeleted()` to update the game's state.
5. **Persist**: Saves the updated game entity using `ServiceOperationExecutor` with a `DELETE` operation status.
6. **Notify**: Publishes a `GameNotificationEvent` with the game ID, user ID, notification type `GAME_REMOVED`, and the game's activity name (if available).

**Exceptions:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | If the game with the given ID does not exist. |
| `AuthorizationException` (implied) | If the authenticated user is not the organizer of the game. |

## Usage Example

```java
@Autowired
private SoftDeleteGameService softDeleteGameService;

public void removeGame(UUID gameId) {
    softDeleteGameService.execute(gameId);
}
```

## Notes

- The class is declared as `non-sealed`, meaning it can be extended by other classes in the same package or module.
- The `@Transactional` annotation ensures that the entire operation is performed within a single database transaction.
- The `@Auditable` annotation logs the action with the game ID as the resource identifier.
- The `ServiceOperationExecutor` handles any persistence errors and wraps them in a `ResourceNotFoundException` if the save fails.
