# DatabaseConfiguration

The `DatabaseConfiguration` class is a Spring Boot configuration class responsible for creating and configuring the primary `DataSource` bean for the application. It provides a robust, production-ready database connection pool using HikariCP, with support for PostgreSQL and H2 databases.

## Purpose

This configuration class:
- Creates a HikariCP-based `DataSource` bean
- Automatically detects the database type from the JDBC URL
- Applies database-specific optimizations for PostgreSQL and H2
- Configures connection pooling parameters (size, timeouts, leak detection)
- Integrates with Micrometer for metrics monitoring
- Masks sensitive credentials in log output
- Supports multiple Spring profiles for pool naming

## Class Overview

| Aspect | Details |
|--------|---------|
| **Package** | `com.upmatches.app.shared.database.configurations` |
| **Annotations** | `@Configuration(proxyBeanMethods = false)`, `@EnableConfigurationProperties(DatabaseProperties.class)` |
| **Dependencies** | `DatabaseProperties`, `Environment`, `MeterRegistry` (nullable) |

## Public Methods

### `dataSource()`

Creates and configures the primary HikariCP `DataSource` bean.

| Property | Value |
|----------|-------|
| **Bean Name** | `dataSource` |
| **Primary** | Yes |
| **Condition** | `app.database.enabled=true` (default: true) |
| **Return Type** | `javax.sql.DataSource` |

**Configuration Process:**
1. Validates that the JDBC URL is configured
2. Resolves the JDBC driver class name
3. Configures HikariCP with pool sizing, timeouts, and monitoring
4. Applies database-specific optimizations (PostgreSQL or H2)
5. Logs a comprehensive configuration summary

**Throws:**
- `IllegalStateException` if the database URL is not configured
- `IllegalArgumentException` if the JDBC URL is unsupported

## Configuration Properties

### Pool Sizing

| Property | Default | Description |
|----------|---------|-------------|
| `app.database.hikari.maximum-pool-size` | `10` | Maximum number of connections in the pool |
| `app.database.hikari.minimum-idle` | `10` | Minimum number of idle connections |

### Timeouts

| Property | Default | Description |
|----------|---------|-------------|
| `app.database.hikari.connection-timeout` | `30000` (30s) | Maximum time to wait for a connection |
| `app.database.hikari.idle-timeout` | `600000` (10min) | Maximum time a connection can be idle |
| `app.database.hikari.max-lifetime` | `1800000` (30min) | Maximum lifetime of a connection |
| `app.database.hikari.leak-detection-threshold` | Disabled | Threshold for connection leak detection |
| `app.database.hikari.initialization-fail-timeout` | `1` | Timeout for pool initialization failure |

### Database-Specific Optimizations

#### PostgreSQL Optimizations

| Property | Value | Description |
|----------|-------|-------------|
| `tcpKeepAlive` | `true` | Enable TCP keep-alive |
| `ApplicationName` | Resolved application name | Application identifier |
| `assumeMinServerVersion` | `9.4` | Minimum PostgreSQL server version |
| `reWriteBatchedInserts` | `true` | Enable batched insert rewriting |
| `prepareThreshold` | `5` | Statement preparation threshold |
| `preparedStatementCacheQueries` | `256` | Prepared statement cache size |
| `preparedStatementCacheSizeMiB` | `5` | Prepared statement cache memory limit |
| `maintainTimeStats` | `false` | Disable time statistics maintenance |

#### H2 Optimizations

| Property | Value | Description |
|----------|-------|-------------|
| `DB_CLOSE_DELAY` | `-1` | Keep database open until JVM shutdown |
| `DB_CLOSE_ON_EXIT` | `false` | Disable close on exit |
| `CACHE_SIZE` | `131072` (128MB) | Cache size in KB |
| `LOCK_TIMEOUT` | `10000` (10s) | Lock timeout in milliseconds |

### Monitoring

The class integrates with Micrometer for metrics collection when a `MeterRegistry` bean is available in the application context.

## Logging

The class provides comprehensive logging at INFO level, including:
- Pool name and sizing configuration
- Timeout settings
- Leak detection status
- Database URL (with credentials masked)
- Driver class name
- Application name

## Usage Example

```yaml
# application.yml
app:
  database:
    url: jdbc:postgresql://localhost:5432/mydb
    username: myuser
    password: mypassword
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 5000
      leak-detection-threshold: 60000
```

## Security

The class masks sensitive credentials in log output using the following patterns:
- `URL_CREDENTIALS_PATTERN`: Masks username:password in URLs
- `URL_PASSWORD_PATTERN`: Masks password parameter in URLs

## Dependencies

- **HikariCP**: Connection pool implementation
- **Micrometer**: Metrics collection and monitoring
- **Spring Boot**: Configuration and dependency injection
- **JSpecify**: Nullable annotations
- **SLF4J**: Logging framework
