# PushNotificationService

The `PushNotificationService` class is a Spring service component responsible for sending push notifications to users via Firebase Cloud Messaging (FCM). It handles the complete lifecycle of push notification delivery, including token management, message construction, delivery tracking, and automatic cleanup of invalid device tokens.

## Purpose

This service serves as the bridge between the application's notification system and Firebase Cloud Messaging. It takes a `Notification` entity, retrieves the recipient's registered device tokens, constructs platform-specific notifications (Android and iOS), sends them via FCM multicast, and handles the results including pruning invalid or unregistered tokens from the database.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `DeviceTokenRepository` | Repository | Manages device token persistence and queries |
| `NotificationRepository` | Repository | Manages notification persistence and badge count queries |
| `ObjectProvider<FirebaseMessaging>` | Provider | Lazily provides FirebaseMessaging instance (may be unavailable) |

## Public Methods

### `send(Notification notification)`

Sends a push notification to all registered devices of the notification's recipient.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `notification` | `Notification` | The notification entity containing recipient, title, message, type, and optional resource information |

**Returns:**

| Return Type | Description |
|-------------|-------------|
| `PushDeliveryResult` | Enum indicating the outcome of the delivery attempt |

**Possible Return Values:**

| Value | Description |
|-------|-------------|
| `UNAVAILABLE` | FirebaseMessaging service is not available |
| `NO_TOKENS` | Recipient has no registered device tokens |
| `SENT` | At least one device received the notification successfully |
| `FAILED` | All delivery attempts failed or an exception occurred |

**Behavior:**

1. Checks if FirebaseMessaging is available; returns `UNAVAILABLE` if not
2. Retrieves all device tokens for the notification's recipient
3. Returns `NO_TOKENS` if no tokens are found
4. Constructs a data payload with notification type, ID, and optional resource information
5. Builds platform-specific configurations:
   - iOS: Sets badge count via APNs config
   - Android: Sets notification count via Android config
6. Creates a multicast message targeting all recipient tokens
7. Sends the message via Firebase Messaging
8. Prunes invalid tokens (unregistered or invalid) from the database
9. Returns `SENT` if at least one delivery succeeded, otherwise `FAILED`

## Private Methods

### `resolveBadge(UUID recipientId)`

Calculates the badge count for the recipient based on unread notifications.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `recipientId` | `UUID` | The ID of the notification recipient |

**Returns:**

| Return Type | Description |
|-------------|-------------|
| `int` | The number of unread notifications, capped at `Integer.MAX_VALUE` |

### `pruneInvalidTokens(BatchResponse response, List<String> tokenStrings)`

Removes invalid or unregistered device tokens from the database after a failed delivery attempt.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `response` | `BatchResponse` | The FCM batch response containing individual send results |
| `tokenStrings` | `List<String>` | The list of device tokens that were targeted |

**Behavior:**

- Iterates through each send response
- Skips successful deliveries
- For failed deliveries, checks if the error code is `UNREGISTERED` or `INVALID_ARGUMENT`
- Deletes the corresponding device token from the database if the error matches

## Error Handling

- Logs a debug message when FirebaseMessaging is unavailable
- Logs a warning with the notification ID and error message when a `FirebaseMessagingException` occurs
- Automatically cleans up invalid tokens to prevent repeated failed delivery attempts

## Transactional Behavior

The `send` method is annotated with `@Transactional`, ensuring that any database operations (including token pruning) are performed within a transaction context.
