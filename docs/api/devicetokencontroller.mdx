# Device Token Controller

The `DeviceTokenController` is a REST controller that manages device token registration and unregistration for push notifications. It provides endpoints for clients to register their device tokens with the server and to remove them when no longer needed.

## Purpose

This controller handles the lifecycle of device tokens used for push notification delivery. When a user's device wants to receive push notifications, it registers its unique device token. When the user logs out or disables notifications, the token can be unregistered.

## Endpoints

### Register Device Token

Registers a new device token for push notifications.

**HTTP Method:** `POST`  
**Endpoint:** `/api/v1/device-tokens`  
**HTTP Status on Success:** `201 Created`

#### Request Body

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | `RegisterDeviceTokenRequest` | Yes | The device token registration details |

#### Response

| Field | Type | Description |
|-------|------|-------------|
| `status` | `String` | Success status |
| `message` | `String` | Success message: "Device token registered successfully." |
| `path` | `String` | The request URI |

### Unregister Device Token

Removes a previously registered device token.

**HTTP Method:** `DELETE`  
**Endpoint:** `/api/v1/device-tokens`  
**HTTP Status on Success:** `204 No Content`

#### Request Parameters

| Parameter | Type | Required | Constraints | Description |
|-----------|------|----------|-------------|-------------|
| `deviceToken` | `String` | Yes | Not blank, max 512 characters | The device token to unregister |

#### Response

No response body is returned on success.

## Dependencies

| Service Interface | Description |
|-------------------|-------------|
| `IRegisterDeviceTokenService` | Handles the business logic for registering device tokens |
| `IUnregisterDeviceTokenService` | Handles the business logic for unregistering device tokens |

## Validation

The controller uses Jakarta Bean Validation annotations to ensure input data integrity:

- `@Valid` on request bodies triggers validation of nested objects
- `@NotBlank` ensures the device token parameter is not null or empty
- `@Size(max = 512)` limits the device token length to 512 characters
- `@Validated` at the class level enables method-level validation

## Error Handling

Validation errors will result in HTTP 400 Bad Request responses with appropriate error messages. Service-level exceptions will propagate to the global exception handler for consistent error responses.
