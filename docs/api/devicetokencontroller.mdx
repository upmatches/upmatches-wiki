# Device Token Controller

The `DeviceTokenController` is a REST controller that manages device token registration and unregistration for push notifications. It provides endpoints for clients to register their device tokens with the server and to remove them when no longer needed (e.g., on logout or app uninstall).

## Purpose

This controller handles the lifecycle of device tokens used for push notification delivery. It ensures that only valid, authorized devices can register or unregister their tokens, maintaining the integrity of the notification system.

## Endpoints

### Register Device Token

Registers a new device token for push notifications.

**HTTP Method:** `POST`  
**Endpoint:** `/api/v1/device-tokens`  
**Request Body:** `RegisterDeviceTokenRequest` (validated)  
**Response:** `201 Created` with success message

| Parameter | Type | Description |
|-----------|------|-------------|
| `body` | `RegisterDeviceTokenRequest` | The device token registration details (validated) |
| `request` | `HttpServletRequest` | The HTTP request object for URI generation |

**Response Body:**
```json
{
  "data": null,
  "message": "Device token registered successfully.",
  "path": "/api/v1/device-tokens"
}
```

### Unregister Device Token

Removes a previously registered device token.

**HTTP Method:** `DELETE`  
**Endpoint:** `/api/v1/device-tokens`  
**Query Parameters:**

| Parameter | Type | Constraints | Description |
|-----------|------|-------------|-------------|
| `deviceToken` | `String` | Required, not blank, max 512 characters | The device token to unregister |

**Response:** `204 No Content` (no response body)

## Dependencies

The controller depends on two service interfaces:

| Service Interface | Purpose |
|-------------------|---------|
| `IRegisterDeviceTokenService` | Handles the business logic for registering a device token |
| `IUnregisterDeviceTokenService` | Handles the business logic for unregistering a device token |

## Validation

- Request body validation is performed via `@Valid` annotation on `RegisterDeviceTokenRequest`
- Query parameter validation is performed via `@NotBlank` and `@Size(max = 512)` annotations on `deviceToken`
- Class-level `@Validated` annotation enables method-level validation

## Error Handling

Validation errors will result in appropriate HTTP error responses (typically `400 Bad Request`) with details about the validation failure.
