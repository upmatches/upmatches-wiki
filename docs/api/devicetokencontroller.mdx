# Device Token Controller

The `DeviceTokenController` is a REST controller that manages device tokens for push notifications. It provides endpoints to register and unregister device tokens, enabling the application to send push notifications to specific devices.

## Purpose

This controller handles the lifecycle of device tokens used for push notification delivery. It allows client applications to:
- Register a new device token when a user logs in or enables notifications
- Unregister a device token when a user logs out or disables notifications

## Endpoints

### Register Device Token

Registers a new device token for push notifications.

**HTTP Method:** `POST`  
**Endpoint:** `/api/v1/device-tokens`  
**Response Status:** `201 Created`

#### Request Body

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `body` | `RegisterDeviceTokenRequest` | Yes | The device token registration details |

#### Response

| Field | Type | Description |
|-------|------|-------------|
| `status` | `String` | Success status |
| `message` | `String` | Success message: "Device token registered successfully." |
| `path` | `String` | The request URI |

### Unregister Device Token

Unregisters an existing device token.

**HTTP Method:** `DELETE`  
**Endpoint:** `/api/v1/device-tokens`  
**Response Status:** `204 No Content`

#### Query Parameters

| Parameter | Type | Required | Constraints | Description |
|-----------|------|----------|-------------|-------------|
| `deviceToken` | `String` | Yes | Not blank, max 512 characters | The device token to unregister |

#### Response

No content is returned on successful unregistration.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `IRegisterDeviceTokenService` | Service | Handles the business logic for registering device tokens |
| `IUnregisterDeviceTokenService` | Service | Handles the business logic for unregistering device tokens |

## Validation

The controller uses Jakarta Bean Validation annotations to ensure input data integrity:
- `@Valid` on request bodies triggers validation of nested objects
- `@NotBlank` ensures string parameters are not null or empty
- `@Size(max = 512)` limits the device token length to 512 characters
- `@Validated` at the class level enables method-level validation

## Error Handling

The controller relies on Spring's default error handling mechanisms. Validation errors will return appropriate HTTP 400 responses with error details. Service-level exceptions should be handled by a global exception handler or returned as appropriate HTTP error responses.
