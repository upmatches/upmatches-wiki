# IDeleteNotificationService Interface

The `IDeleteNotificationService` interface defines a contract for deleting notifications within the application. It is a **sealed interface**, meaning that only explicitly permitted classes (in this case, `DeleteNotificationService`) can implement it. This design pattern enforces a controlled hierarchy and ensures that the deletion logic is centralized and secure.

## Purpose

- **Sealed Contract**: Restricts implementation to a single, known class (`DeleteNotificationService`), preventing unauthorized or accidental implementations.
- **Single Responsibility**: Provides a single method for deleting a notification by its unique identifier (`UUID`).
- **Decoupling**: Allows the notification deletion logic to be abstracted away from the caller, promoting loose coupling between components.

## Method Summary

| Method | Description |
|--------|-------------|
| `void execute(UUID id)` | Deletes a notification identified by the given `UUID`. The method does not return a value. |

## Method Details

### `execute(UUID id)`

Deletes a notification from the system based on its unique identifier.

**Parameters:**

| Parameter | Type   | Description |
|-----------|--------|-------------|
| `id`      | `UUID` | The unique identifier of the notification to be deleted. |

**Returns:** `void` (no return value)

**Throws:** The method does not declare any checked exceptions, but implementations may throw runtime exceptions (e.g., `IllegalArgumentException` if the `id` is null, or a custom exception if the notification is not found).

## Usage Example

```java
// Assuming you have an instance of DeleteNotificationService
IDeleteNotificationService deleteService = new DeleteNotificationService();

// Delete a notification by its UUID
UUID notificationId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
deleteService.execute(notificationId);
```

## Implementation Notes

- The interface is **sealed**, so only `DeleteNotificationService` can implement it. This ensures that all deletion logic follows the same pattern and can be easily audited.
- The `execute` method is intentionally simple, accepting only a `UUID` parameter. This keeps the interface focused and easy to use.
- Implementations should handle cases where the notification does not exist, typically by throwing an appropriate exception (e.g., `NotificationNotFoundException`).

## Related Components

- **`DeleteNotificationService`**: The sole permitted implementation of this interface, containing the actual deletion logic.
- **Notification Entity**: The data model representing a notification, which is deleted by this service.
