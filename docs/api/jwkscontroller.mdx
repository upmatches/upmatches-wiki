# JwksController

The `JwksController` is a Spring REST controller that exposes a JSON Web Key Set (JWKS) endpoint for Singpass authentication. It provides public keys in JWKS format, which are used by clients to verify the signatures of JWTs issued by the application.

## Purpose

This controller serves the public keys required for JWT signature verification in the Singpass authentication flow. By exposing the JWKS endpoint at `/.well-known/jwks.json`, it allows clients (such as other services or frontend applications) to retrieve the public keys needed to validate tokens signed by the application's private key.

## Endpoints

### GET `/.well-known/jwks.json`

Returns the public JWKS (JSON Web Key Set) as a JSON string.

**Response**

| Status | Content-Type | Cache Control |
|--------|-------------|---------------|
| 200 OK | `application/json` | `public, max-age=3600` (1 hour) |

**Response Body**

The response body contains a JSON string representing the public JWKS. The structure follows the [RFC 7517](https://tools.ietf.org/html/rfc7517) JWKS format.

## Dependencies

| Dependency | Type | Description |
|-----------|------|-------------|
| `ISingpassKeyProvider` | Service | Interface providing the public JWKS JSON string |

## Configuration

The controller uses the following constants:

| Constant | Value | Description |
|----------|-------|-------------|
| `JWKS_ENDPOINT` | `/.well-known/jwks.json` | The endpoint path for JWKS retrieval |
| `CACHE_MAX_AGE_HOURS` | `1` | Cache duration in hours for the JWKS response |

## Usage Example

```java
// The controller is automatically mapped by Spring
// No manual instantiation required

// Example HTTP request
GET /.well-known/jwks.json
Host: your-domain.com

// Example response (200 OK)
{
  "keys": [
    {
      "kty": "RSA",
      "use": "sig",
      "alg": "RS256",
      "kid": "key-id-1",
      "n": "base64url-encoded-modulus",
      "e": "AQAB"
    }
  ]
}
```

## Implementation Details

The controller:
1. Delegates JWKS generation to the `ISingpassKeyProvider` service
2. Sets appropriate cache headers (1 hour) to reduce load on the key provider
3. Returns the JWKS as a JSON string with proper content type
4. Uses public cache control to allow CDN and browser caching

## Security Considerations

- The endpoint is public and does not require authentication
- Cache headers are set to balance freshness with performance
- The underlying key provider should handle key rotation securely
- Consider rate limiting if the endpoint is exposed to the public internet
