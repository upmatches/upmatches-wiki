# Health Check Controller

The `HealthCheckController` is a REST controller that provides a simple health check endpoint for the UpMatches application. It is used to verify that the service is running and responsive, which is essential for monitoring, load balancers, and container orchestration platforms (e.g., Kubernetes).

## Location

- **Package:** `com.upmatches.app.features.health.controllers`
- **Base URL:** `/api/v1/public/health`

## Endpoints

### GET `/api/v1/public/health`

Returns a simple health check response indicating that the service is operational.

#### Request

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | Injected automatically by Spring. Used to capture the request URI for the response. |

#### Response

| Status Code | Description |
|-------------|-------------|
| `200 OK` | The service is running. |

The response body is an `ApiResponse<String>` with the following structure:

| Field | Type | Description |
|-------|------|-------------|
| `status` | `String` | Always `"OK"` |
| `message` | `String` | Always `"Service is running"` |
| `data` | `String` | The request URI (e.g., `/api/v1/public/health`) |

#### Example Response

```json
{
  "status": "OK",
  "message": "Service is running",
  "data": "/api/v1/public/health"
}
```

## Usage

This endpoint is typically used by:

- **Monitoring systems** (e.g., Prometheus, Grafana) to check service availability.
- **Load balancers** (e.g., AWS ELB, Nginx) for health checks.
- **Container orchestration** (e.g., Kubernetes liveness/readiness probes).
- **CI/CD pipelines** to verify deployment success.

## Implementation Details

The controller uses:

- `@RestController` – Marks the class as a REST controller.
- `@RequestMapping("/api/v1/public/health")` – Maps all requests to the base path.
- `@GetMapping` – Handles HTTP GET requests.
- `ApiResponse.success()` – A static factory method that creates a standardized success response.

The response is wrapped in `ResponseEntity.ok()` to return HTTP 200 with the response body.
