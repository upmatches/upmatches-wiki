# Health Check Controller

The `HealthCheckController` is a REST controller that provides a simple health check endpoint for the UpMatches application. It is used to verify that the service is running and responsive, making it useful for monitoring, load balancers, and deployment health checks.

## Location

- **Package:** `com.upmatches.app.features.health.controllers`
- **Base Path:** `/api/v1/public/health`

## Endpoints

### GET `/api/v1/public/health`

Returns a simple health check response indicating that the service is operational.

#### Request

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The HTTP request object (injected automatically by Spring) |

#### Response

| Status Code | Description |
|-------------|-------------|
| `200 OK` | Service is running |

The response body is an `ApiResponse<String>` object with the following structure:

| Field | Type | Description |
|-------|------|-------------|
| `status` | `String` | Always returns `"OK"` |
| `message` | `String` | Always returns `"Service is running"` |
| `path` | `String` | The request URI path |

#### Example Response

```json
{
  "status": "OK",
  "message": "Service is running",
  "path": "/api/v1/public/health"
}
```

## Usage

This endpoint is typically used by:

- **Load balancers** to determine if the service instance is healthy and should receive traffic
- **Monitoring systems** to check service availability
- **CI/CD pipelines** to verify successful deployments
- **Kubernetes** readiness and liveness probes

## Implementation Details

The controller uses the `ApiResponse.success()` static method to construct a standardized response. The `HttpServletRequest` parameter is automatically injected by Spring and used to populate the `path` field in the response, providing context about which endpoint was called.
