# SingpassCallbackController

## Purpose

The `SingpassCallbackController` handles the OAuth 2.0 callback from Singpass, Singapore's national digital identity platform. It processes the authorization code returned by Singpass, exchanges it for tokens, creates or retrieves user accounts, and generates JWT tokens for the application's authentication flow.

This controller is a critical component in the authentication pipeline, bridging the Singpass OAuth flow with the application's internal authentication system.

## Endpoints

### `GET /callback/singpass`

Handles the Singpass OAuth callback after user authentication.

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `code` | String | No | Authorization code from Singpass |
| `state` | String | No | State parameter for CSRF protection |

**Response:**

| Status Code | Description |
|-------------|-------------|
| 302 Found | Redirects to frontend callback URL with tokens |
| 400 Bad Request | Missing required parameters |
| 401 Unauthorized | Authentication failure |

## Public Methods

### `callbackSingpass`

```java
public ResponseEntity<Object> callbackSingpass(
    @RequestParam(required = false) final String code,
    @RequestParam(required = false) final String state,
    final HttpServletRequest request,
    final HttpServletResponse response)
```

The main callback handler that orchestrates the entire authentication flow.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `code` | String | Authorization code from Singpass |
| `state` | String | State parameter for CSRF validation |
| `request` | HttpServletRequest | HTTP request object |
| `response` | HttpServletResponse | HTTP response object |

**Returns:** `ResponseEntity<Object>` - Redirect response with authentication tokens

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `InvalidAuthRequestException` | Missing `code` or `state` parameters |
| `AuthenticationException` | State mismatch, token exchange failure, or invalid token payload |


**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `code` | String | Authorization code from Singpass |

| `sub` | String | Subject claim from Singpass token |

**Returns:** `SingpassUuid` - Parsed UUID value object

**Throws:** `AuthenticationException` if the `sub` claim is invalid or cannot be parsed

## Error Handling

The controller handles several error scenarios:

1. **Provider Errors**: If Singpass returns an error, it logs the error and throws an `AuthenticationException`
2. **Missing Parameters**: Throws `InvalidAuthRequestException` if `code` or `state` are missing
3. **State Mismatch**: Throws `AuthenticationException` if the state doesn't match any session
4. **Token Exchange Failure**: Logs the error and throws `AuthenticationException`
5. **Invalid Token Payload**: Throws `AuthenticationException` if the `sub` claim is invalid
6. **Concurrent User Creation**: Handles `DataIntegrityViolationException` by looking up the existing user

## Usage Example

```java

// GET /callback/singpass?code=abc123&state=xyz789

// The controller will:
// 1. Validate the state parameter
// 2. Exchange the authorization code for tokens
// 3. Find or create the user
// 4. Generate JWT tokens
// 5. Redirect to the frontend with tokens
```
