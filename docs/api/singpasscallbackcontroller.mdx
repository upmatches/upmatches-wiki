# SingpassCallbackController

## Purpose

The `SingpassCallbackController` is a Spring REST controller that handles the OAuth 2.0 callback from Singpass, Singapore's national digital identity platform. It processes the authorization code returned by Singpass after user authentication, exchanges it for tokens, creates or retrieves user accounts, and generates JWT tokens for the application's session management.

This controller is responsible for:
- Validating the callback parameters (`code` and `state`)
- Exchanging the authorization code for Singpass tokens
- Parsing the Singpass user identifier (`sub` claim)
- Creating new users or retrieving existing ones
- Generating application-level JWT access and refresh tokens
- Redirecting users back to the application (web or mobile)

## Public Methods

### `callbackSingpass`

Handles the Singpass OAuth callback endpoint at `/callback/singpass`.

```java
@GetMapping("/callback/singpass")
public ResponseEntity<Object> callbackSingpass(
    @RequestParam(required = false) final String code,
    @RequestParam(required = false) final String state,
    final HttpServletRequest request,
    final HttpServletResponse response)
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `code` | `String` | No | The authorization code from Singpass |
| `state` | `String` | No | The state parameter for CSRF protection |
| `request` | `HttpServletRequest` | Yes | The HTTP request object |
| `response` | `HttpServletResponse` | Yes | The HTTP response object |

**Returns:**

| Type | Description |
|------|-------------|
| `ResponseEntity<Object>` | Redirect response to the application callback URL or mobile deep link |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `InvalidAuthRequestException` | When `code` or `state` parameters are missing or blank |
| `AuthenticationException` | When Singpass returns an error, state mismatch occurs, token exchange fails, or user creation fails |

**Flow:**
1. Checks if Singpass returned an error parameter
2. Validates the presence of `code` and `state` parameters
3. Retrieves and removes the stored auth session using the `state` parameter
4. Exchanges the authorization code for a Singpass token
5. Parses the `sub` claim from the token to get the Singpass UUID
6. Finds or creates a user based on the Singpass UUID
7. Generates JWT access and refresh tokens
8. Redirects the user based on platform (web or mobile)

## Error Handling

The controller handles several error scenarios:

| Error | HTTP Status | Description |
|-------|-------------|-------------|
| Missing `code` or `state` | 400 Bad Request | Invalid callback request |
| State mismatch | 401 Unauthorized | CSRF protection failure |
| Singpass provider error | 401 Unauthorized | Singpass returned an error |
| Token exchange failure | 401 Unauthorized | Unable to exchange authorization code |
| Invalid token payload | 401 Unauthorized | Malformed Singpass token |
| User creation failure | 401 Unauthorized | Database or concurrent creation issues |
