# GetGameFilterOptionsService

## Purpose

The `GetGameFilterOptionsService` class is a Spring service that retrieves and aggregates distinct filter options (venues, skill levels, start times, and game types) from a set of games matching a user's filter criteria. It is designed to populate filter dropdowns or selection UI components in a game discovery application.

The service performs a database query based on the provided filter request, then extracts unique values for each filter dimension from the resulting game list. It also handles geospatial bounding box calculations for location-based filtering and enforces validation rules on the input request.

## Public Methods

### `execute`

```java
@Transactional(readOnly = true)
public GameFilterOptionsResponse execute(GameFilterOptionsRequest filter)
```

Executes the filter options retrieval process. Validates the input request, runs a database query to find matching games, and returns a response containing distinct venues, skill levels, start times, and game types.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `filter` | `GameFilterOptionsRequest` | The filter criteria including date range, time range, location, venue IDs, skill level IDs, and game type |

**Returns:**

| Type | Description |
|------|-------------|
| `GameFilterOptionsResponse` | Contains four lists: `venues` (List of VenueResponse), `skillLevels` (List of SkillLevelResponse), `startTimes` (List of String in "HH:mm" format), and `gameTypes` (List of GameType) |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `IllegalArgumentException` | If validation fails (e.g., date range exceeds 90 days, location fields are incomplete, or skill level IDs exceed 20) |
| `ResourceNotFoundException` | If no games match the filter criteria |

## Internal Methods

### `runQuery`

Executes the database query using `gameRepository.findVisibleForFilterOptions()` with the processed filter parameters. Converts date/time fields to appropriate formats and computes a bounding box for location-based filtering.

### `distinctVenues`

Extracts unique venues from the game list, preserving insertion order. Returns a list of `VenueResponse` objects.

### `distinctSkillLevels`

Extracts unique skill levels from both `skillLevelFrom` and `skillLevelTo` fields of each game. Sorts by `sortOrder` and returns a list of `SkillLevelResponse` objects.

### `distinctStartTimes`

Extracts unique start times from the game list, formats them as "HH:mm" strings, sorts them, and returns a list.

### `distinctGameTypes`

Extracts unique game types from the game list, sorts them, and returns a list of `GameType` enum values.

### `toMinutes`

Converts a `LocalTime` to total minutes since midnight. Returns `null` if the input is `null`.

### `validateCrossFields`

Validates the filter request:
- Ensures location fields (latitude, longitude, radiusKm) are all provided together
- Validates that `toDate` is not before `fromDate`
- Ensures the date range does not exceed 90 days
- Limits skill level IDs to a maximum of 20

### `computeBoundingBox`

Calculates a geographic bounding box based on the provided latitude, longitude, and radius. Uses the Haversine approximation with a fixed conversion factor of 111.045 km per degree of latitude.

## Constants

| Constant | Value | Description |
|----------|-------|-------------|
| `SGT` | `ZoneId.of("Asia/Singapore")` | Singapore time zone for date/time conversions |
| `KM_PER_DEGREE_LAT` | `111.045` | Approximate kilometers per degree of latitude |
| `MINUTES_PER_HOUR` | `60` | Minutes in one hour |
| `MIN_COS_LAT` | `1e-6` | Minimum cosine of latitude to prevent division by zero |
| `MC` | `MathContext(16, HALF_UP)` | Math context for BigDecimal calculations |
| `HOUR_MINUTE` | `"HH:mm"` | Time format pattern |
| `MAX_DATE_RANGE_DAYS` | `90` | Maximum allowed date range in days |
| `MAX_SKILL_LEVEL_IDS` | `20` | Maximum number of skill level IDs allowed |
| `MAX_GAMES_SAMPLED` | `500` | Maximum number of games to sample for filter options |

## Dependencies

- `GameRepository` - Data access layer for game entities
- `IAuthenticatedUserResolver` - Resolves the currently authenticated user (optional)
- `ServiceOperationExecutor` - Utility for executing service operations with standardized error handling

## Usage Example

```java
// Create a filter request
GameFilterOptionsRequest filter = new GameFilterOptionsRequest(
    LocalDate.now(),
    LocalDate.now().plusDays(7),
    LocalTime.of(9, 0),
    LocalTime.of(22, 0),
    null, // latitude
    null, // longitude
    null, // radiusKm
    null, // venueIds
    null, // skillLevelIds
    null  // gameType
);

// Execute the service
GameFilterOptionsResponse options = getGameFilterOptionsService.execute(filter);

// Use the options to populate UI filters
List<VenueResponse> venues = options.venues();
List<SkillLevelResponse> skillLevels = options.skillLevels();
List<String> startTimes = options.startTimes();
List<GameType> gameTypes = options.gameTypes();
```
