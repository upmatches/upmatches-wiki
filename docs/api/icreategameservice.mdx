# ICreateGameService Interface

The `ICreateGameService` interface defines the contract for creating a new game within the UpMatches application. It follows a sealed interface pattern to restrict implementation to a single concrete class (`CreateGameService`), ensuring controlled and secure extension of the game creation logic.

## Purpose

This interface serves as the abstraction layer for the game creation use case. By defining a single `execute` method, it enforces a consistent API for creating games while allowing the underlying implementation to handle business logic, validation, and persistence. The sealed modifier guarantees that only the permitted `CreateGameService` class can implement this interface, preventing unauthorized extensions.

## Interface Definition

```java
public sealed interface ICreateGameService permits CreateGameService {
    GameResponse execute(CreateGameRequest request);
}
```

## Methods

### `execute`

Creates a new game based on the provided request data and returns the resulting game information.

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `CreateGameRequest` | The request object containing all necessary data to create a new game (e.g., game name, settings, participants) |

| Returns | Type | Description |
|---------|------|-------------|
| `GameResponse` | `GameResponse` | The response object containing the details of the newly created game (e.g., game ID, status, creation timestamp) |

**Usage Example:**

```java
ICreateGameService gameService = new CreateGameService();
CreateGameRequest request = new CreateGameRequest(/* ... */);
GameResponse response = gameService.execute(request);
```

## Related Classes

- **`CreateGameService`**: The sole permitted implementation of this interface, containing the actual game creation logic.
- **`CreateGameRequest`**: The input data transfer object (DTO) encapsulating game creation parameters.
- **`GameResponse`**: The output DTO representing the result of a successful game creation operation.

## Design Considerations

- **Sealed Interface**: The `sealed` keyword restricts implementation to only the `CreateGameService` class, providing compile-time safety and preventing unintended implementations.
- **Single Responsibility**: The interface focuses solely on the game creation use case, adhering to the Interface Segregation Principle.
- **Immutability**: Both request and response objects are designed to be immutable, ensuring thread safety and predictable behavior.
