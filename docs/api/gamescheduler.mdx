# GameScheduler

The `GameScheduler` class is a Spring Boot component that automatically manages game lifecycle transitions. It runs two scheduled tasks every five minutes to update game statuses:

1. **Mark games as STARTED** – Updates games whose scheduled start time has passed.
2. **Mark games as EXPIRED** – Updates games that have exceeded their allowed duration.

This scheduler ensures that game states remain consistent without manual intervention, relying on dedicated service interfaces for the actual business logic.

## Dependencies

The scheduler depends on two service interfaces injected via constructor injection:

| Dependency | Type | Purpose |
|------------|------|---------|
| `IMarkStartedGamesService` | Interface | Marks eligible games as STARTED |
| `IMarkExpiredGamesService` | Interface | Marks eligible games as EXPIRED |

## Scheduled Methods

Both methods run on the same cron schedule: every 5 minutes (`0 */5 * * * *`).

### `markStartedGames()`

```java
@Scheduled(cron = "0 */5 * * * *")
public void markStartedGames()
```

**Behavior:**
- Calls `markStartedGamesService.execute()` to process games that should transition to STARTED status.
- Logs the number of games updated using the format: `Marked {count} games as STARTED.`

**Returns:** `void`

### `markExpiredGames()`

```java
@Scheduled(cron = "0 */5 * * * *")
public void markExpiredGames()
```

**Behavior:**
- Calls `markExpiredGamesService.execute()` to process games that should transition to EXPIRED status.
- Logs the number of games updated using the format: `Marked {count} games as EXPIRED.`

**Returns:** `void`

## Configuration

The cron expression is defined as a constant:

```java
private static final String CRON_EVERY_FIVE_MINUTES = "0 */5 * * * *";
```

This expression runs at the start of every 5th minute (e.g., 12:00, 12:05, 12:10, etc.).

## Logging

The class uses SLF4J logging with the following constants:

| Constant | Value |
|----------|-------|
| `LOG_STARTED` | `"Marked {} games as STARTED."` |
| `LOG_EXPIRED` | `"Marked {} games as EXPIRED."` |

The `{}` placeholder is replaced with the count of updated games returned by the respective service.

## Usage Notes

- The scheduler is automatically activated when the Spring context loads due to the `@Component` annotation.
- Both scheduled methods run independently and can execute concurrently.
- The actual game status update logic is delegated to the injected service implementations, making the scheduler testable and the business logic reusable.
- If either service throws an exception, the scheduler will log the error but will not affect the other scheduled task.
