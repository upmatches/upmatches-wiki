# GameScheduler

The `GameScheduler` class is a Spring `@Component` that provides scheduled task execution for updating game statuses. It runs two distinct cron jobs every five minutes to automatically mark games as `STARTED` or `EXPIRED` based on their current state and timing conditions.

## Purpose

This scheduler automates the lifecycle management of games within the application. By periodically executing two services, it ensures that:

- Games that should have started are transitioned to the `STARTED` status.
- Games that have passed their expiration time are transitioned to the `EXPIRED` status.

This eliminates the need for manual intervention and keeps the game state consistent with real-world time.

## Dependencies

The scheduler relies on two service interfaces injected via constructor injection:

| Dependency | Type | Description |
|------------|------|-------------|
| `markStartedGamesService` | `IMarkStartedGamesService` | Service responsible for marking eligible games as `STARTED`. |
| `markExpiredGamesService` | `IMarkExpiredGamesService` | Service responsible for marking eligible games as `EXPIRED`. |

## Scheduled Methods

Both methods are triggered by the same cron expression: `0 */5 * * * *` (every five minutes).

### `markStartedGames()`

```java
@Scheduled(cron = CRON_EVERY_FIVE_MINUTES)
public void markStartedGames()
```

**Description:** Executes the `markStartedGamesService` to identify and update games that should be marked as `STARTED`. Logs the number of games updated.

**Parameters:** None

**Returns:** `void`

**Logging:** Logs at `INFO` level with the message format: `"Marked {} games as STARTED."`

### `markExpiredGames()`

```java
@Scheduled(cron = CRON_EVERY_FIVE_MINUTES)
public void markExpiredGames()
```

**Description:** Executes the `markExpiredGamesService` to identify and update games that should be marked as `EXPIRED`. Logs the number of games updated.

**Parameters:** None

**Returns:** `void`

**Logging:** Logs at `INFO` level with the message format: `"Marked {} games as EXPIRED."`

## Configuration

The cron schedule is defined as a constant:

```java
private static final String CRON_EVERY_FIVE_MINUTES = "0 */5 * * * *";
```

This expression runs the tasks at the start of every 5th minute (e.g., 12:00, 12:05, 12:10, etc.).

## Usage Notes

- The scheduler is automatically discovered and registered by Spring's component scanning due to the `@Component` annotation.
- Both scheduled methods run independently and concurrently if the underlying services are thread-safe.
- The actual business logic for determining which games to update is delegated to the injected service implementations.
- Logging uses SLF4J with a dedicated logger for this class, making it easy to monitor scheduler activity in log files.
