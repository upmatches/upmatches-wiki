# MintDevTokenRequest

The `MintDevTokenRequest` class is a Java record used to encapsulate the request payload for minting a developer token. It ensures that the required `userId` field is provided and validated before processing the token generation.

## Purpose

This record serves as a Data Transfer Object (DTO) for API endpoints that handle developer token minting. By leveraging Java records, it provides a concise, immutable data carrier with built-in `equals()`, `hashCode()`, and `toString()` methods. The `@NotNull` validation annotation enforces that the `userId` must be present in the request.

## Record Definition

```java
public record MintDevTokenRequest(@NotNull UUID userId) {}
```

## Fields

| Field    | Type   | Validation | Description                                      |
|----------|--------|------------|--------------------------------------------------|
| `userId` | `UUID` | `@NotNull` | The unique identifier of the user requesting the developer token. |

## Usage

The `MintDevTokenRequest` record is typically used in a Spring Boot controller or service layer to receive and validate incoming requests for developer token generation. Example:

```java
@PostMapping("/mint-dev-token")
public ResponseEntity<?> mintDevToken(@Valid @RequestBody MintDevTokenRequest request) {
    UUID userId = request.userId();
    // Process token minting logic...
}
```

## Validation

- The `@NotNull` annotation (from `jakarta.validation.constraints`) ensures that the `userId` field cannot be `null`.
- If a request is submitted without a `userId`, a validation error will be thrown, typically resulting in a `400 Bad Request` response.

## Notes

- The record is immutable, making it thread-safe and suitable for use in concurrent environments.
- The `UUID` type provides a universally unique identifier, reducing the risk of ID collisions.
- This class is part of the `com.upmatches.app.features.auth.requests` package, indicating its role in authentication-related request handling.
