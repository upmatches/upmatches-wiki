# JwtTokenService

The `JwtTokenService` class is a Spring service responsible for generating JWT access tokens and refresh tokens for authentication in the UpMatches application. It implements the `IJwtTokenService` interface and uses Nimbus JOSE + JWT library for JWT creation and signing with ES256 (ECDSA using P-256 and SHA-256) algorithm.

## Purpose

This service handles token generation for multiple authentication providers (Singpass, Auth0, and Apple). It ensures that a user can only have one authentication provider at a time and generates cryptographically secure refresh tokens.

## Dependencies

- **SigningKeyProvider**: Provides the ECDSA signing key and key ID for JWT signing
- **JwtProperties**: Configuration properties for JWT (issuer, audience, token expiry)

## Public Methods

### `generateAccessToken`

Generates a signed JWT access token for a user.

| Parameter | Type | Description |
|-----------|------|-------------|
| `userId` | `UUID` | The unique identifier of the user |
| `singpassUuid` | `String` | UUID from Singpass authentication (nullable) |
| `auth0Uuid` | `String` | UUID from Auth0 authentication (nullable) |
| `appleUuid` | `String` | UUID from Apple authentication (nullable) |

**Returns**: `AccessTokenResult` - A record containing:
- `token` (`String`): The serialized JWT access token
- `expiresAtUtc` (`Long`): Unix timestamp (seconds) when the token expires

**Throws**:
- `IllegalArgumentException` if more than one authentication provider UUID is provided
- `IllegalStateException` if JWT signing fails

### `generateRefreshToken`

Generates a cryptographically secure random refresh token.

| Parameter | Type | Description |
|-----------|------|-------------|
| None | | |

**Returns**: `String` - A Base64 URL-encoded refresh token (32 random bytes, 43 characters)

## Internal Implementation Details

### Token Claims

The generated access token includes the following claims:
- `sub`: User UUID
- `iss`: Issuer (from `JwtProperties`)
- `aud`: Audience (from `JwtProperties`)
- `iat`: Issued at time
- `nbf`: Not before time
- `exp`: Expiration time
- Provider-specific claims (only one of the following):
  - `singpass_uuid` + `auth_provider: "singpass"`
  - `auth0_uuid` + `auth_provider: "auth0"`
  - `apple_uuid` + `auth_provider: "apple"`

### Provider Validation

The `applyProviderClaims` method ensures that only one authentication provider UUID is provided. If multiple provider UUIDs are non-null and non-blank, it throws an `IllegalArgumentException`.

### Token Signing

Tokens are signed using ES256 (ECDSA with P-256 curve) algorithm. The signing key is obtained from the `SigningKeyProvider` and the key ID (`kid`) is included in the JWT header.

## Usage Example

```java
@Autowired
private JwtTokenService jwtTokenService;

// Generate access token for a Singpass user
AccessTokenResult result = jwtTokenService.generateAccessToken(
    userId,
    "singpass-uuid-123",
    null,
    null
);

String accessToken = result.token();
Long expiresAt = result.expiresAtUtc();

// Generate refresh token
String refreshToken = jwtTokenService.generateRefreshToken();
```

## Configuration

The service requires the following configuration via `JwtProperties`:
- `accessTokenExpiryMinutes`: Token expiration time in minutes
- `issuer`: JWT issuer claim value
- `audience`: JWT audience claim value

## Notes

- The service is conditionally loaded with `@ConditionalOnBean(SigningKeyProvider.class)`
- The class is declared as `non-sealed`, allowing it to be extended if needed
- Refresh tokens are generated using `SecureRandom` for cryptographic security
- Token expiry is calculated in seconds from the current time
