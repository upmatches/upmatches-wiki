# ListGameBookmarksService

The `ListGameBookmarksService` class provides paginated retrieval of game bookmarks for the authenticated user. It implements cursor-based pagination to efficiently fetch bookmarks in a scalable manner, including real-time participant counts for each bookmarked game.

## Purpose

This service handles the business logic for listing a user's game bookmarks with the following key responsibilities:

- **Authentication**: Resolves the authenticated user's identity
- **Cursor-based Pagination**: Decodes and encodes pagination cursors for efficient data retrieval
- **Participant Counts**: Enriches bookmark data with current active participant counts
- **Error Handling**: Wraps operations in standardized error handling with appropriate exception types

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameBookmarkRepository` | Repository | Data access for game bookmark entities |
| `GameParticipantRepository` | Repository | Data access for game participant counts |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `GameCursor` | Helper | Handles cursor encoding/decoding for pagination |
| `ServiceOperationExecutor` | Utility | Provides standardized operation execution with error handling |

## Public Methods

### `execute(String cursor, int size)`

Retrieves a paginated list of game bookmarks for the authenticated user.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `cursor` | `String` | Pagination cursor from previous request. `null` or empty for first page |
| `size` | `int` | Maximum number of bookmarks to return per page |

**Returns:**

| Type | Description |
|------|-------------|
| `CursorPagedResponse<GameBookmarkResponse>` | Paginated response containing bookmark data and next cursor |

**Behavior:**

1. Resolves the authenticated user's UUID
2. Decodes the provided cursor string (if present) to extract pagination parameters
3. Fetches bookmarks from the repository using cursor-based pagination
4. Collects all game IDs from the retrieved bookmarks
5. Queries participant counts for those games with `ACTIVE` status
6. Maps bookmarks to response objects enriched with participant counts
7. Generates a next cursor if there are more results available
8. Returns the paginated response wrapped in standardized error handling

**Example Usage:**

```java
// First page request
CursorPagedResponse<GameBookmarkResponse> firstPage = service.execute(null, 20);

// Subsequent page request
CursorPagedResponse<GameBookmarkResponse> nextPage = service.execute(firstPage.getNextCursor(), 20);
```

## Implementation Details

### Cursor-Based Pagination

The service uses a composite cursor consisting of:
- `startTime`: The `bookmarkedAt` timestamp of the last bookmark in the current page
- `id`: The UUID of the last bookmark in the current page

This approach ensures stable pagination even when new bookmarks are added between requests.

### Participant Count Enrichment

For each page of bookmarks, the service performs a batch query to count active participants for all bookmarked games. This avoids N+1 query problems by using a single database call with a list of game IDs.

### Transaction Management

The method is annotated with `@Transactional(readOnly = true)` to:
- Ensure consistent reads during pagination
- Optimize database connection usage
- Prevent unintended data modifications

## Error Handling

The service uses `ServiceOperationExecutor.execute()` with:
- **Operation Status**: `RETRIEVE`
- **Exception Factory**: `ResourceNotFoundException::new`

This ensures that any database or runtime exceptions are properly wrapped and handled according to the application's error handling conventions.
