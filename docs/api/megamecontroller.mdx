# MeGameController

The `MeGameController` is a REST controller that provides endpoints for authenticated users to retrieve their personal game-related data. It exposes two main functionalities: listing games the user has joined and listing games the user is hosting. Both endpoints support cursor-based pagination for efficient data retrieval.

## Purpose

This controller serves as the primary interface for users to manage and view their game participation history. It separates concerns by delegating the actual business logic to dedicated service interfaces (`IListMyJoinedGamesCursorService` and `IListMyHostedGamesCursorService`), following the Single Responsibility Principle.

## Endpoints

### Base URL

All endpoints are prefixed with `/api/v1/me/games`.

### 1. List Joined Games

Retrieves a paginated list of games that the authenticated user has joined.

**Endpoint:** `GET /api/v1/me/games/joined`

**Query Parameters:**

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `cursor` | String | No | - | Cursor for pagination. If not provided, returns the first page. |
| `size` | Integer | No | 20 | Number of items per page. Must be between 1 and 100. |

**Response:** `200 OK`

```json
{
  "success": true,
  "message": "Joined games retrieved successfully.",
  "data": {
    "items": [
      {
        "id": "string",
        "name": "string",
        "description": "string",
        "status": "string",
        "createdAt": "2024-01-01T00:00:00Z"
      }
    ],
    "nextCursor": "string",
    "hasMore": true
  },
  "path": "/api/v1/me/games/joined"
}
```

### 2. List Hosted Games

Retrieves a paginated list of games that the authenticated user is hosting.

**Endpoint:** `GET /api/v1/me/games/hosted`

**Query Parameters:**

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `cursor` | String | No | - | Cursor for pagination. If not provided, returns the first page. |
| `size` | Integer | No | 20 | Number of items per page. Must be between 1 and 100. |

**Response:** `200 OK`

```json
{
  "success": true,
  "message": "Hosted games retrieved successfully.",
  "data": {
    "items": [
      {
        "id": "string",
        "name": "string",
        "description": "string",
        "status": "string",
        "createdAt": "2024-01-01T00:00:00Z"
      }
    ],
    "nextCursor": "string",
```

## Error Handling

Both endpoints validate the `size` parameter using `ValidationHelper.validateCursorPaginationParameters(size)`. If validation fails, the helper will throw an appropriate exception that is handled by the global exception handler, returning a structured error response.

## Dependencies

The controller depends on the following service interfaces:

- `IListMyJoinedGamesCursorService` - Handles business logic for retrieving joined games with cursor-based pagination.
- `IListMyHostedGamesCursorService` - Handles business logic for retrieving hosted games with cursor-based pagination.

Both services are injected via constructor injection, ensuring immutability and testability.

## Usage Example

```bash
# Get first page of joined games (20 items)
curl -X GET "https://api.example.com/api/v1/me/games/joined" \
  -H "Authorization: Bearer <token>"

# Get next page using cursor
curl -X GET "https://api.example.com/api/v1/me/games/joined?cursor=abc123&size=10" \
  -H "Authorization: Bearer <token>"

# Get hosted games
curl -X GET "https://api.example.com/api/v1/me/games/hosted" \
  -H "Authorization: Bearer <token>"
```

## Notes

- Both endpoints require authentication (handled by Spring Security configuration, not shown in this controller).
- Cursor-based pagination is more efficient than offset-based pagination for large datasets.
- The `size` parameter is validated to ensure it falls within acceptable bounds (typically 1-100).
