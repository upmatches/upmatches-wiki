# SecurityConfiguration

The `SecurityConfiguration` class is a Spring Security configuration component that defines the security policies for the UpMatches application. It configures authentication, authorization, CORS, session management, and JWT decoding using Singpass (Singapore's national digital identity) as the identity provider.

## Purpose

This class serves as the central security configuration for the application, handling:

- **Authentication**: Uses OAuth2 resource server with JWT tokens for API security
- **Authorization**: Defines which endpoints are public and which require authentication
- **CORS**: Configures Cross-Origin Resource Sharing for web clients
- **Session Management**: Enforces stateless session management
- **Token Resolution**: Supports JWT tokens from both Authorization headers and cookies

## Public Methods

### `securityFilterChain(HttpSecurity http)`

Configures the main security filter chain for the application.

| Parameter | Type | Description |
|-----------|------|-------------|
| `http` | `HttpSecurity` | The HTTP security configuration object |

**Returns**: `SecurityFilterChain` - The configured security filter chain

**Configuration Details**:
- Disables CSRF protection
- Enables CORS with default configuration
- Sets session management to stateless
- Defines public endpoints (see Public Endpoints section)
- Requires authentication for all other requests
- Configures OAuth2 resource server with JWT support
- Uses cookie fallback for bearer token resolution

### `jwtDecoder(ISingpassKeyProvider keyProvider)`

Creates a JWT decoder that validates tokens using Singpass public keys.

| Parameter | Type | Description |
|-----------|------|-------------|
| `keyProvider` | `ISingpassKeyProvider` | Provider for Singpass signing keys |

**Returns**: `JwtDecoder` - A configured JWT decoder using ES256 algorithm

### `cookieFallbackBearerTokenResolver()`

Creates a bearer token resolver that first checks the Authorization header, then falls back to cookies.

**Returns**: `BearerTokenResolver` - A resolver that extracts JWT tokens from headers or cookies

### `corsConfigurationSource(String allowedOrigins)`

Configures CORS settings for the application.

| Parameter | Type | Description |
|-----------|------|-------------|
| `allowedOrigins` | `String` | Semicolon-separated list of allowed origins (default: `http://localhost:3002`) |

**Returns**: `CorsConfigurationSource` - The CORS configuration source

## Dependencies

- **Spring Security**: For security configuration and OAuth2 resource server
- **Nimbus JOSE + JWT**: For JWT processing and verification
- **Singpass Key Provider**: Custom service for obtaining Singpass signing keys

## Usage Example

```java
// The configuration is automatically applied when Spring Security is enabled
// No manual instantiation required
```

## Notes

- The application uses ES256 (ECDSA using P-256 and SHA-256) for JWT signing
- CORS allows credentials (cookies) to be sent with requests
- The bearer token resolver provides flexibility for different client types (web, mobile)
- All authenticated endpoints require a valid JWT token from Singpass
