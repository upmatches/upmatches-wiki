# IRefreshTokenStore Interface

The `IRefreshTokenStore` interface defines the contract for managing refresh tokens in the authentication system. It provides methods for storing, validating, rotating, and revoking refresh tokens associated with user accounts.

This interface is a **sealed interface**, meaning it can only be implemented by the `RefreshTokenStore` class. This design pattern ensures that all refresh token operations go through a single, controlled implementation, enhancing security and maintainability.

## Interface Definition

```java
public sealed interface IRefreshTokenStore permits RefreshTokenStore {
    // Methods defined below
}
```

## Methods

| Method | Description | Parameters | Returns |
|--------|-------------|------------|---------|
| `store` | Stores a new refresh token for a given user | `UUID userId` - The unique identifier of the user<br/>`String refreshToken` - The refresh token string to store | `void` |
| `validateAndRotate` | Validates a refresh token and rotates it (issues a new one) | `String refreshToken` - The refresh token to validate | `ValidationResult` - Contains the validation outcome and potentially a new token |
| `revokeAllForUser` | Revokes all refresh tokens associated with a specific user | `UUID userId` - The unique identifier of the user whose tokens should be revoked | `void` |

## Usage Examples

### Storing a Refresh Token

```java
IRefreshTokenStore tokenStore = new RefreshTokenStore();
UUID userId = UUID.randomUUID();
String refreshToken = "some-refresh-token-value";
tokenStore.store(userId, refreshToken);
```

### Validating and Rotating a Token

```java
String existingToken = "existing-refresh-token";
ValidationResult result = tokenStore.validateAndRotate(existingToken);

if (result.isValid()) {
    // Token is valid, use the new token if rotation occurred
    String newToken = result.getNewToken();
} else {
    // Token is invalid or expired
    throw new SecurityException("Invalid refresh token");
}
```

### Revoking All Tokens for a User

```java
UUID userId = UUID.randomUUID();
tokenStore.revokeAllForUser(userId);
// All refresh tokens for this user are now invalid
```

## Related Components

- **RefreshTokenStore**: The sole implementation of this interface
- **ValidationResult**: Inner class of `RefreshTokenStore` that encapsulates the validation outcome
- **AuthService**: Typically uses this interface to manage authentication sessions

## Security Considerations

- Refresh tokens should be stored securely (e.g., hashed) in the database
- Token rotation helps prevent token theft by invalidating old tokens after use
- Revoking all tokens for a user is useful when a password change or account compromise is detected
- The sealed interface pattern prevents unauthorized implementations that could bypass security measures
