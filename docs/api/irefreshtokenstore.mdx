# IRefreshTokenStore Interface

The `IRefreshTokenStore` interface defines the contract for managing refresh tokens in the authentication system. It provides a sealed interface pattern that restricts implementation to the `RefreshTokenStore` class, ensuring a single, controlled implementation for token storage operations.

This interface is part of the `com.upmatches.app.features.auth.services` package and serves as the abstraction layer for refresh token lifecycle management, including storage, validation, rotation, and revocation.

## Interface Definition

```java
public sealed interface IRefreshTokenStore permits RefreshTokenStore
```

The interface is declared as `sealed`, meaning only the `RefreshTokenStore` class is permitted to implement it. This design pattern provides:
- **Controlled extensibility**: Only the specified class can implement the interface
- **Security**: Prevents unauthorized implementations that could compromise token management
- **Performance**: Allows the JVM to optimize method calls since the implementation set is known at compile time

## Methods

| Method | Description | Parameters | Returns |
|--------|-------------|------------|---------|
| `store` | Stores a refresh token associated with a user | `UUID userId` - The user's unique identifier<br/>`String refreshToken` - The refresh token to store | `void` |
| `validateAndRotate` | Validates a refresh token and rotates it (creates a new one while invalidating the old) | `String refreshToken` - The refresh token to validate | `ValidationResult` - Contains the validation status and new token if rotation was successful |
| `revokeAllForUser` | Revokes all refresh tokens associated with a specific user | `UUID userId` - The user's unique identifier | `void` |

## Usage Examples

### Storing a Refresh Token

```java
IRefreshTokenStore tokenStore = new RefreshTokenStore();
UUID userId = UUID.randomUUID();
String refreshToken = "eyJhbGciOiJIUzI1NiIs...";

tokenStore.store(userId, refreshToken);
```

### Validating and Rotating a Token

```java
String existingToken = "eyJhbGciOiJIUzI1NiIs...";
ValidationResult result = tokenStore.validateAndRotate(existingToken);

if (result.isValid()) {
    String newToken = result.getNewToken();
    // Use the new token for subsequent requests
} else {
    // Handle invalid token
}
```

### Revoking All Tokens for a User

```java
UUID userId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
tokenStore.revokeAllForUser(userId);
// All refresh tokens for this user are now invalid
```

## Related Types

The interface references the `ValidationResult` type from the `RefreshTokenStore` class, which contains the outcome of token validation and rotation operations.

## Implementation Notes

- The sealed interface pattern ensures that all token storage operations go through the `RefreshTokenStore` implementation
- Token validation and rotation are combined in a single atomic operation to prevent race conditions
- The `revokeAllForUser` method is useful for security scenarios such as password changes or account lockouts
