# CreateGameBookmarkService

## Purpose

The `CreateGameBookmarkService` class is a Spring service responsible for creating bookmarks for games by authenticated users. It handles the complete bookmark creation workflow, including:

- Authenticating the user and resolving their identity
- Looking up the game and verifying it exists
- Authorizing the user to view the game
- Checking for duplicate bookmarks to prevent double-bookmarking
- Persisting the new bookmark
- Returning a response with the bookmark details and active participant count

This service implements the `ICreateGameBookmarkService` interface and is marked as `non-sealed`, allowing for future extension.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameBookmarkRepository` | Repository | Persistence layer for game bookmarks |
| `GameParticipantRepository` | Repository | Persistence layer for game participants |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Looks up games and users by ID |
| `IGameAuthorizationService` | Service | Handles authorization checks for game access |

## Public Methods

### `execute(UUID gameId)`

Creates a bookmark for the specified game on behalf of the authenticated user.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `gameId` | `UUID` | The unique identifier of the game to bookmark |

**Returns:**

| Type | Description |
|------|-------------|
| `GameBookmarkResponse` | A response object containing the created bookmark details and the count of active participants |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `AlreadyBookmarkedException` | If the user has already bookmarked the specified game |
| `ResourceNotFoundException` | If the game or user is not found, or if the bookmark save operation fails |

**Behavior:**

1. Resolves the authenticated user's ID via `userResolver.requireUserId()`
2. Looks up the game using `lookupService.findGameOrThrow(gameId)`
3. Authorizes the user to view the game via `authorizationService.assertCanViewGame(game, userId)`
4. Checks for an existing bookmark using `bookmarkRepository.existsByGameIdAndUserId(gameId, userId)`
5. If a bookmark already exists, throws `AlreadyBookmarkedException` with a formatted message
6. Looks up the user entity via `lookupService.findUserOrThrow(userId)`
7. Creates a new `GameBookmark` entity using the factory method `GameBookmark.create(game, user)`
8. Persists the bookmark using `ServiceOperationExecutor.execute()` with the `SAVE` operation status
9. Counts active participants via `participantRepository.countByGameIdAndStatus(gameId, ParticipantStatus.ACTIVE)`
10. Returns a `GameBookmarkResponse` constructed from the saved bookmark and participant count

## Transactional Behavior

The `execute` method is annotated with `@Transactional`, ensuring that the entire bookmark creation process (including the existence check, save, and participant count) is executed within a single database transaction. If any step fails, the transaction is rolled back.
