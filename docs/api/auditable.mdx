# Auditable Annotation

The `@Auditable` annotation is a custom Java annotation used to mark methods that should be audited. When applied to a method, it enables automatic audit logging of the method's execution, capturing metadata such as the action performed, the category of the audit event, the resource type, and whether the operation involves sensitive data.

## Purpose

This annotation is designed to integrate with an audit framework to track and log user actions or system events. It provides a declarative way to specify audit metadata directly on methods, reducing boilerplate code and ensuring consistent audit logging across the application.

## Usage

Apply the `@Auditable` annotation to any method that requires audit logging. The annotation's attributes allow you to customize the audit entry for each method.

### Example

```java
import com.upmatches.app.features.audit.annotations.Auditable;
import com.upmatches.app.features.audit.enums.AuditCategory;

public class UserService {

    @Auditable(
        action = "CREATE_USER",
        category = AuditCategory.WRITE,
        resourceType = "User",
        resourceIdExpression = "#user.id",
        sensitive = true
    )
    public void createUser(User user) {
        // Method implementation
    }
}
```

## Attributes

| Attribute | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `action` | `String` | Yes | - | A descriptive name for the action being audited (e.g., "CREATE_USER", "UPDATE_PROFILE"). |
| `category` | `AuditCategory` | No | `AuditCategory.WRITE` | The category of the audit event, such as `READ`, `WRITE`, `DELETE`, or `EXECUTE`. |
| `resourceType` | `String` | No | `""` | The type of resource being acted upon (e.g., "User", "Order", "Document"). |
| `resourceIdExpression` | `String` | No | `""` | A SpEL (Spring Expression Language) expression to dynamically resolve the resource ID at runtime. |
| `sensitive` | `boolean` | No | `false` | Indicates whether the audited operation involves sensitive data. When `true`, the audit framework may mask or omit sensitive details. |

## Retention and Target

- **Retention**: `RetentionPolicy.RUNTIME` – The annotation is retained at runtime, allowing it to be accessed via reflection by the audit framework.
- **Target**: `ElementType.METHOD` – The annotation can only be applied to methods.

## Integration Notes

- The `AuditCategory` enum is expected to define categories such as `READ`, `WRITE`, `DELETE`, and `EXECUTE`.
- The `resourceIdExpression` attribute supports SpEL expressions, enabling dynamic resolution of resource identifiers from method parameters.
- When `sensitive` is set to `true`, the audit framework should handle the data appropriately (e.g., redacting sensitive fields in logs).
