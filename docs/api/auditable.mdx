## Overview

The `Auditable` annotation is part of the `com.upmatches.app.features.audit.annotations` package. It is designed to be used on methods to specify that they should be audited. This annotation provides metadata about the action being performed, the category of the audit, and additional details about the resource involved. It is retained at runtime, allowing for dynamic processing during the execution of the application.

## Public Methods

The `Auditable` annotation defines several elements that can be used to configure the auditing behavior. Below is a table documenting each element, its purpose, and its return type.

| Element Name         | Description                                                                 | Return Type                  |
|----------------------|-----------------------------------------------------------------------------|------------------------------|
| `action`             | Specifies the action being audited. This is a required element.             | `String`                     |
| `category`           | Defines the category of the audit. Defaults to `AuditCategory.WRITE`.       | `AuditCategory`              |
| `resourceType`       | Describes the type of resource being audited. Defaults to an empty string.  | `String`                     |
| `resourceIdExpression` | Provides an expression to determine the resource ID. Defaults to an empty string. | `String`                     |
| `sensitive`          | Indicates whether the audited action involves sensitive information. Defaults to `false`. | `boolean`                    |

## Usage

To use the `Auditable` annotation, apply it to a method within your application where auditing is required. Configure the elements as needed to provide the necessary audit metadata.
