# UpdateActivityRequest

The `UpdateActivityRequest` is a Java record used to encapsulate the data required for updating an existing activity. It ensures that the incoming request payload is validated before processing, leveraging Jakarta Bean Validation annotations.

## Purpose

This record serves as a Data Transfer Object (DTO) for the activity update endpoint. It defines the structure and validation rules for the request body, ensuring that the activity name is provided and does not exceed the maximum allowed length.

## Record Definition

```java
public record UpdateActivityRequest(
    @NotBlank
    @Size(max = 100)
    String name
) {}
```

## Fields

| Field | Type   | Validation Constraints | Description                                      |
|-------|--------|------------------------|--------------------------------------------------|
| name  | String | `@NotBlank`, `@Size(max = 100)` | The updated name of the activity. Must not be blank and must not exceed 100 characters. |

## Validation Rules

- **@NotBlank**: The `name` field must not be `null`, empty, or contain only whitespace characters.
- **@Size(max = 100)**: The `name` field must not exceed 100 characters in length.

## Usage Example

The record is typically used as a parameter in a REST controller method:

```java
@PutMapping("/activities/{id}")
public ResponseEntity<ActivityResponse> updateActivity(
    @PathVariable Long id,
    @Valid @RequestBody UpdateActivityRequest request) {
    // Business logic to update the activity
}
```

## Notes

- This record is immutable by design, as all Java records are.
- Validation is automatically triggered when the `@Valid` annotation is used in the controller method.
- The record is located in the `com.upmatches.app.features.activity.requests` package.
