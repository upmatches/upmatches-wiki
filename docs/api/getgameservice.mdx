# GetGameService

The `GetGameService` class is a Spring service responsible for retrieving a single game's details for a requesting user. It handles both authenticated and anonymous user scenarios, providing appropriate game response data including participant counts and joinability status.

## Purpose

This service orchestrates the retrieval of a game by its unique identifier (UUID). It performs the following operations in sequence:

1. Resolves the current authenticated user (if any)
2. Looks up the game entity by ID
3. Authorizes the user to view the game
4. Counts active participants
5. Computes joinability for authenticated users
6. Returns a tailored `GameResponse` based on user authentication state

## Dependencies

| Dependency | Type | Purpose |
|------------|------|---------|
| `GameParticipantRepository` | Repository | Counts active participants for a game |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user |
| `IGameLookupService` | Service | Finds a game by ID or throws `ResourceNotFoundException` |
| `IGameAuthorizationService` | Service | Validates user permissions to view the game |
| `IGameJoinabilityService` | Service | Computes whether the user can join the game |

## Public Methods

### `execute(UUID id)`

Retrieves game details for the specified game ID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game to retrieve |

**Returns:** `GameResponse` - A response object containing game details, participant count, and (for authenticated users) joinability information.

**Throws:** `ResourceNotFoundException` if the game does not exist or the user lacks permission to view it.

**Behavior:**
- If the user is **anonymous** (`userId` is empty), returns a `GameResponse` with anonymous game data and participant count only.
- If the user is **authenticated**, computes joinability and returns a `GameResponse` with full viewer data including joinability status.

## Implementation Details

The method is annotated with `@Transactional(readOnly = true)`, ensuring the database operations are executed within a read-only transaction context for performance optimization.

The participant count is wrapped in `ServiceOperationExecutor.execute()` which provides standardized error handling and logging for the retrieval operation.

## Usage Example

```java
@Autowired
private GetGameService getGameService;

public void someMethod() {
    UUID gameId = UUID.fromString("123e4567-e89b-12d3-a456-426614174000");
    GameResponse response = getGameService.execute(gameId);
    // Process the response
}
```
