# MarkAllReadService

The `MarkAllReadService` class is a Spring service component responsible for marking all notifications as read for the currently authenticated user. It implements the `IMarkAllReadService` interface and provides a transactional operation that updates the read status of all notifications belonging to the authenticated user.

## Purpose

This service handles the bulk operation of marking all notifications as read for a specific user. It leverages the `NotificationRepository` to perform the database update and uses the `IAuthenticatedUserResolver` to obtain the authenticated user's ID. The operation is wrapped in a transaction to ensure data consistency.

## Dependencies

| Dependency | Description |
|------------|-------------|
| `NotificationRepository` | Repository interface for performing database operations on notifications |
| `IAuthenticatedUserResolver` | Interface for resolving the currently authenticated user's ID |
| `ServiceOperationExecutor` | Utility class for executing service operations with standardized error handling |

## Public Methods

### `execute()`

Marks all notifications as read for the currently authenticated user.

**Signature:**
```java
@Transactional
public Integer execute()
```

**Returns:**
- `Integer` - The number of notifications that were marked as read

**Throws:**
- `ResourceNotFoundException` - If the operation fails or the user cannot be resolved

**Behavior:**
1. Retrieves the authenticated user's ID using `userResolver.requireUserId()`
2. Executes the `markAllReadByRecipientId` method on the notification repository with the user ID and current timestamp
3. Wraps the operation in `ServiceOperationExecutor.execute()` for standardized error handling and logging

**Example Usage:**
```java
@Autowired
private MarkAllReadService markAllReadService;

public void markAllNotificationsAsRead() {
    int updatedCount = markAllReadService.execute();
    System.out.println("Marked " + updatedCount + " notifications as read");
}
```

## Implementation Details

The service uses Spring's `@Transactional` annotation to ensure the database update operation is performed within a transaction context. The `ServiceOperationExecutor` provides a consistent pattern for executing service operations, automatically handling exceptions and logging.

The `non-sealed` modifier on the class declaration indicates that this class is part of a sealed class hierarchy, allowing it to be extended by other classes in the same package or module.
