# SecurityHeadersFilter

The `SecurityHeadersFilter` is a Spring Boot servlet filter that automatically adds essential security headers to every HTTP response. By implementing `OncePerRequestFilter` and registering with the highest precedence, it ensures that all outgoing responses include protections against common web vulnerabilities such as clickjacking, MIME-type sniffing, and cross-site scripting (XSS).

This filter is part of the `com.upmatches.app.features.auth.filters` package and is intended for use in production environments where security hardening is required.

## Purpose

- **Prevent clickjacking** by setting `X-Frame-Options: DENY`.
- **Disable MIME-type sniffing** via `X-Content-Type-Options: nosniff`.
- **Control referrer information** with `Referrer-Policy: strict-origin-when-cross-origin`.
- **Restrict cross-domain policies** using `X-Permitted-Cross-Domain-Policies: none`.
- **Limit browser features** (camera, microphone, geolocation) via `Permissions-Policy`.
- **Enforce a strict Content Security Policy** that blocks all resources by default and prevents framing.
- **Remove server fingerprinting** by blanking out `Server` and `X-Powered-By` headers.

## Public Methods

### `doFilterInternal`

```java
protected final void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
    throws ServletException, IOException
```

This is the core method that applies security headers to every HTTP response. It is invoked once per request by the servlet container.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request (not modified by this filter). |
| `response` | `HttpServletResponse` | The outgoing HTTP response to which headers are added. |
| `filterChain` | `FilterChain` | The filter chain to continue processing the request. |

**Behavior:**

1. Sets the following security headers on the response:
   - `X-Content-Type-Options: nosniff`
   - `X-Frame-Options: DENY`
   - `Referrer-Policy: strict-origin-when-cross-origin`
   - `X-Permitted-Cross-Domain-Policies: none`
   - `Permissions-Policy: camera=(), microphone=(), geolocation=()`
   - `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`
2. Blanks out the `Server` and `X-Powered-By` headers to prevent information leakage.
3. Calls `filterChain.doFilter(request, response)` to continue processing the request.

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `ServletException` | If the filter chain throws a servlet exception. |
| `IOException` | If an I/O error occurs during filtering. |

## Usage

Since the class is annotated with `@Component`, Spring Boot automatically discovers and registers it as a filter. No additional configuration is required.

```java
// No explicit instantiation needed; Spring Boot auto-configures it.
```

## Security Considerations

- **Ordering**: The filter runs at `HIGHEST_PRECEDENCE + 5`, meaning it executes before most other filters but after any filters with `HIGHEST_PRECEDENCE` or `HIGHEST_PRECEDENCE + 1` through `+4`.
- **CSP Strictness**: The Content Security Policy (`default-src 'none'`) is extremely restrictive. If your application loads external resources (scripts, styles, images), you must modify the `CONTENT_SECURITY_POLICY_VALUE` constant to allow those resources.
- **Header Overwriting**: The filter overwrites any existing values for the headers it sets. If other parts of your application set these headers, this filter's values will take precedence.
- **Server Fingerprinting**: Blanking out `Server` and `X-Powered-By` helps prevent attackers from identifying your technology stack, but it is not a complete security measure.

## Example Response Headers

After this filter processes a request, the response will include:

```
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
X-Permitted-Cross-Domain-Policies: none
Permissions-Policy: camera=(), microphone=(), geolocation=()
Content-Security-Policy: default-src 'none'; frame-ancestors 'none'
Server:
X-Powered-By:
```
