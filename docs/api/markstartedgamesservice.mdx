# MarkStartedGamesService

The `MarkStartedGamesService` is a Spring service class responsible for automatically marking games as "started" when their scheduled start time has passed. It provides a transactional operation that updates the status of games in the database based on the current timestamp.

## Purpose

This service handles the business logic for transitioning games from a "pending" or "scheduled" state to a "started" state. It uses the current system time to identify games whose start time has elapsed and updates their status accordingly. The operation is wrapped in a transaction to ensure data consistency.

## Public Methods

### `execute()`

Executes the operation to mark games as started. This method is transactional and will roll back if an error occurs.

| Aspect | Details |
|--------|---------|
| **Return Type** | `int` |
| **Return Value** | The number of games that were marked as started |
| **Annotations** | `@Transactional` |
| **Exceptions** | `ResourceNotFoundException` (wrapped from the executor) |

#### Method Logic

1. Captures the current timestamp using `Instant.now()`
2. Calls `gameRepository.markStartedBefore(now, now)` to update games whose start time is before the current time
3. The operation is executed through `ServiceOperationExecutor` with:
   - Operation type: `UPDATE`
   - Exception supplier: `ResourceNotFoundException::new`

| `ServiceOperationExecutor` | Utility | Handles execution of service operations with standardized error handling |

## Usage Example

```java
@Autowired
private MarkStartedGamesService markStartedGamesService;

public void processGameStartTimes() {
    int updatedCount = markStartedGamesService.execute();
    System.out.println("Marked " + updatedCount + " games as started");
}
```

## Notes

- The class is declared as `non-sealed`, allowing it to be extended by other classes in the same module
- The `@Transactional` annotation ensures that the database update is atomic
- The `ServiceOperationExecutor` provides consistent error handling and logging for the operation
- The method uses the same `Instant` value for both the comparison and the update timestamp, ensuring temporal consistency
