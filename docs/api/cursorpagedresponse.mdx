# CursorPagedResponse

The `CursorPagedResponse` record is a generic data carrier used to represent a single page of results in a cursor-based pagination system. It encapsulates the list of items for the current page and a cursor string that points to the next page of results.

This record is typically returned by API endpoints that implement cursor-based pagination, allowing clients to efficiently iterate through large datasets without the overhead of offset-based pagination.

## Purpose

- Provides a standardized response format for cursor-paginated endpoints.
- Encapsulates the current page's content and the cursor for the next page.
- Supports generic typing, making it reusable across different entity types.

## Record Components

| Component    | Type          | Description                                                                 |
|--------------|---------------|-----------------------------------------------------------------------------|
| `content`    | `List<T>`     | The list of items for the current page.                                     |
| `nextCursor` | `String`      | A cursor string that can be used to fetch the next page of results. If `null` or empty, indicates there are no more pages. |

## Usage Example

```java
// Example: Creating a response for a page of User objects
List<User> users = userService.getUsers(10, lastCursor);
String nextCursor = users.size() == 10 ? users.get(users.size() - 1).getId() : null;

CursorPagedResponse<User> response = new CursorPagedResponse<>(users, nextCursor);
```

## Notes

- The `nextCursor` field is typically `null` when the current page is the last page of results.
- The generic type `T` allows this record to be used with any entity or DTO class.
- This record is immutable and thread-safe by design, as it is a Java `record`.
