# DeviceToken

The `DeviceToken` entity represents a push notification device token registered by a user in the UpMatches application. It maps to the `notification_device_tokens` database table and enforces a unique constraint on the combination of `user_id` and `device_token` to prevent duplicate registrations.

## Purpose

This entity is used to store and manage device tokens for push notifications. Each token is associated with a specific user and platform (e.g., iOS, Android). The entity supports lifecycle callbacks to automatically set timestamps on creation and updates.

## Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | `UUID` | Primary key, auto-generated using UUID strategy |
| `user` | `User` | The user who owns this device token (many-to-one relationship) |
| `deviceToken` | `String` | The actual device token string (max 512 characters) |
| `platform` | `DevicePlatform` | The platform type (e.g., iOS, Android) stored as a string |
| `createdAt` | `Instant` | Timestamp when the token was created (non-updatable) |
| `updatedAt` | `Instant` | Timestamp when the token was last updated |

## Public Methods

### `create(User user, String deviceToken, DevicePlatform platform)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `user` | `User` | The user to associate with this device token |
| `deviceToken` | `String` | The device token string |
| `platform` | `DevicePlatform` | The platform type |

**Returns:** `DeviceToken` - A new DeviceToken instance with the provided values.

This static factory method creates a new `DeviceToken` instance. It is the preferred way to instantiate the entity, as the default constructor is protected.

### `touch(DevicePlatform platform)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `platform` | `DevicePlatform` | The new platform value to set |

**Returns:** `void`

Updates the platform associated with this device token. This method is used when a token's platform needs to be updated without creating a new entity instance.

## Lifecycle Callbacks

The entity uses JPA lifecycle callbacks to automatically manage timestamps:

- **`@PrePersist`** (`onCreate`): Sets `createdAt` to the current instant before the entity is persisted.
- **`@PreUpdate`** (`onUpdate`): Sets `updatedAt` to the current instant before the entity is updated.

## Database Constraints

The table `notification_device_tokens` has a unique constraint named `uq_notification_device_tokens_user_token` on the combination of `user_id` and `device_token` columns. This ensures that a user cannot register the same device token twice.

## Usage Example

```java
// Create a new device token
DeviceToken token = DeviceToken.create(
    user,
    "abc123-device-token-xyz",
    DevicePlatform.IOS
);

// Save using repository
deviceTokenRepository.save(token);

// Update platform
token.touch(DevicePlatform.ANDROID);
deviceTokenRepository.save(token);
```
