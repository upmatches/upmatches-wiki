# ShareLinkRateLimitFilter

The `ShareLinkRateLimitFilter` is a Spring Boot servlet filter that enforces rate limiting on share-link API endpoints. It extends `OncePerRequestFilter` to ensure each request is processed exactly once. The filter uses Redis as a backing store for rate limit counters and applies different limits for resolving (GET) and creating (POST) share links.

## Purpose

This filter protects the share-link API from abuse by limiting the number of requests a client can make within a 60-second window. It distinguishes between two operations:

- **Resolve (GET)**: Limited to 30 requests per 60 seconds per IP address.
- **Create (POST)**: Limited to 10 requests per 60 seconds per authenticated user (or IP address if unauthenticated).

When a client exceeds the limit, the filter returns a `429 Too Many Requests` response with a `ProblemDetail` JSON body and a `Retry-After` header.

## Dependencies

- **Spring Boot**: `OncePerRequestFilter`, `ConditionalOnBean`
- **Spring Data Redis**: `StringRedisTemplate`
- **Spring Security**: `Authentication`, `Jwt`
- **Jackson**: `ObjectMapper`
- **Jakarta Servlet**: `HttpServletRequest`, `HttpServletResponse`, `FilterChain`

## Configuration

The filter is automatically activated when a `StringRedisTemplate` bean is present in the application context (via `@ConditionalOnBean(StringRedisTemplate.class)`).

## Public Methods

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `shouldNotFilter` | `boolean` | `HttpServletRequest request` | Determines if the filter should be skipped. Returns `true` if the request URI does not start with `/api/v1/share-links`. |
| `doFilterInternal` | `void` | `HttpServletRequest request`, `HttpServletResponse response`, `FilterChain filterChain` | Main filter logic. Applies rate limiting for GET requests matching `/api/v1/share-links/{id}` and POST requests to `/api/v1/share-links`. |

## Internal Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `isRateLimited` | `boolean` | Checks if a Redis key has exceeded its rate limit. Increments the counter and sets expiration on first request. |
| `resolveClientIp` | `String` | Extracts the client IP from the `X-Forwarded-For` header or falls back to `request.getRemoteAddr()`. |
| `resolveSubjectOrIp` | `String` | Returns the JWT subject for authenticated users, or the client IP for unauthenticated requests. |
| `writeRateLimitResponse` | `void` | Writes a `429 Too Many Requests` response with a `ProblemDetail` JSON body and `Retry-After` header. |

## Rate Limit Configuration

| Parameter | Value | Description |
|-----------|-------|-------------|
| `RESOLVE_LIMIT` | 30 | Maximum number of GET requests per window |
| `CREATE_LIMIT` | 10 | Maximum number of POST requests per window |
| `WINDOW_SECONDS` | 60 | Time window in seconds for rate limit counters |

## Redis Key Structure

- **Resolve**: `rl:share-link:resolve:{client_ip}`
- **Create**: `rl:share-link:create:{subject_or_ip}`

## Error Response

When rate limited, the filter returns:

- **HTTP Status**: 429 Too Many Requests
- **Content-Type**: `application/problem+json`
- **Headers**: `Retry-After: 60`
- **Body** (ProblemDetail JSON):
  ```json
  {
    "type": "https://upmatches.com/problems/rate-limit-exceeded",
    "title": "Too Many Requests",
    "status": 429,
    "detail": "Rate limit exceeded for share-link 'resolve' endpoint. Retry after 60 seconds.",
    "instance": "/api/v1/share-links/abc123"
  }
  ```

## Usage Example

```java
// The filter is automatically applied to all requests starting with /api/v1/share-links
// No additional configuration is needed beyond having a StringRedisTemplate bean.

// Example: A client making 31 GET requests to /api/v1/share-links/abc123 within 60 seconds
// will receive a 429 response on the 31st request.
```

## Notes

- The filter only applies to requests with URIs starting with `/api/v1/share-links`.
- For POST requests, the filter uses the JWT subject (if available) as the rate limit key, allowing authenticated users to have their own limit separate from their IP address.
- The `X-Forwarded-For` header is used to determine the client IP when behind a proxy or load balancer.
- Redis keys automatically expire after 60 seconds if no further requests are made.
