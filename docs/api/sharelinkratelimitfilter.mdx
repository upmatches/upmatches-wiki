# ShareLinkRateLimitFilter

## Purpose

The `ShareLinkRateLimitFilter` is a Spring Boot servlet filter that enforces rate limiting on share-link API endpoints. It extends `OncePerRequestFilter` to ensure each request is processed exactly once. The filter distinguishes between two types of operations:

- **Resolve** (GET requests to `/api/v1/share-links/{id}`): Rate-limited by client IP address.
- **Create** (POST requests to `/api/v1/share-links`): Rate-limited by authenticated user subject (JWT subject) or client IP as a fallback.

Rate limits are enforced using Redis as a distributed counter with a sliding window approach. When a limit is exceeded, the filter returns a `429 Too Many Requests` response with a `ProblemDetail` JSON body and a `Retry-After` header.

## Configuration

The filter is automatically enabled when a `StringRedisTemplate` bean is present in the application context (via `@ConditionalOnBean(StringRedisTemplate.class)`).

### Rate Limit Defaults

| Parameter | Resolve (GET) | Create (POST) |
|-----------|---------------|---------------|
| Max Requests | 30 | 10 |
| Window Duration | 60 seconds | 60 seconds |

## Public Methods

### `shouldNotFilter(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `boolean` - `true` if the request URI does not start with `/api/v1/share-links`, meaning the filter will be skipped for non-share-link endpoints.

### `doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |
| `response` | `HttpServletResponse` | The HTTP response |
| `filterChain` | `FilterChain` | The filter chain to continue processing |

**Behavior:**
1. Checks if the request matches a share-link resolve (GET) or create (POST) endpoint.
2. For resolve requests: extracts the client IP and checks the resolve rate limit.
3. For create requests: extracts the authenticated user subject (or IP fallback) and checks the create rate limit.
4. If rate-limited, writes a `429 Too Many Requests` response and stops further processing.
5. Otherwise, continues the filter chain.

### `isRateLimited(String key, int limit)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `key` | `String` | The Redis key for the rate counter |
| `limit` | `int` | The maximum number of requests allowed |

**Returns:** `boolean` - `true` if the current request count exceeds the limit.

**Implementation:** Uses Redis `INCR` to atomically increment the counter. If the counter is 1 (first request), sets the key expiration to the window duration. Returns `true` when the count exceeds the limit.

### `resolveClientIp(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `String` - The resolved client IP address.

**Logic:**
1. Checks the `X-Forwarded-For` header for proxy-aware IP resolution.
2. If present, takes the first IP from the comma-separated list.
3. Falls back to `request.getRemoteAddr()`.

### `resolveSubjectOrIp(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `String` - The authenticated user's JWT subject, or the client IP if no valid authentication is found.

**Logic:**
1. Retrieves the current `Authentication` from `SecurityContextHolder`.
2. If the principal is a `Jwt` instance, extracts the subject claim.
3. Falls back to `resolveClientIp(request)`.

### `writeRateLimitResponse(HttpServletResponse response, String bucket, String instance)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `response` | `HttpServletResponse` | The HTTP response to write to |
| `bucket` | `String` | The rate limit bucket name (e.g., "resolve" or "create") |
| `instance` | `String` | The request URI for the `instance` field in the problem detail |

**Behavior:** Constructs and writes a `ProblemDetail` response with:
- Status: `429 Too Many Requests`
- Content-Type: `application/problem+json`
- `Retry-After` header set to the window duration (60 seconds)
- Problem detail fields: `type`, `title`, `status`, `detail`, `instance`

## Error Response Format

When rate-limited, the API returns a `429 Too Many Requests` response with the following JSON structure:

```json
{
  "type": "https://upmatches.com/problems/rate-limit-exceeded",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded for share-link 'resolve' endpoint. Retry after 60 seconds.",
  "instance": "/api/v1/share-links/abc123"
}
```

## Redis Key Structure

| Key Pattern | Description |
|-------------|-------------|
| `rl:share-link:resolve:{ip}` | Counter for resolve requests by IP |
| `rl:share-link:create:{subject}` | Counter for create requests by subject or IP |
