# ShareLinkRateLimitFilter

## Purpose

The `ShareLinkRateLimitFilter` is a Spring Boot servlet filter that enforces rate limiting on share-link API endpoints. It extends `OncePerRequestFilter` to ensure each request is processed exactly once. The filter distinguishes between two types of operations:

- **Resolve** (GET requests to `/api/v1/share-links/{id}`): Rate-limited by client IP address.
- **Create** (POST requests to `/api/v1/share-links`): Rate-limited by the authenticated user's subject (JWT subject) or, if unauthenticated, by client IP address.

Rate limiting is implemented using Redis (via `StringRedisTemplate`) with a sliding window counter pattern. When a limit is exceeded, the filter returns a `429 Too Many Requests` response with a `ProblemDetail` JSON body and a `Retry-After` header.

## Dependencies

- **Spring Boot** (Web, Security, Data Redis)
- **Jackson** (for JSON serialization of `ProblemDetail`)
- **Redis** (for rate limit counters)

## Configuration

The filter is automatically registered as a Spring bean when a `StringRedisTemplate` bean is present in the application context (via `@ConditionalOnBean(StringRedisTemplate.class)`).

### Rate Limit Parameters

| Parameter | Value | Description |
|-----------|-------|-------------|
| `RESOLVE_LIMIT` | 30 | Maximum number of resolve requests per window |
| `CREATE_LIMIT` | 10 | Maximum number of create requests per window |
| `WINDOW_SECONDS` | 60 | Time window in seconds for rate limit counters |

## Public Methods

### `shouldNotFilter(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `boolean` — `true` if the request URI does not start with `/api/v1/share-links`, otherwise `false`.

This method determines whether the filter should be skipped for a given request. Only requests to share-link endpoints are processed.

### `doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |
| `response` | `HttpServletResponse` | The HTTP response |
| `filterChain` | `FilterChain` | The filter chain to continue processing |

**Returns:** `void`

This method performs the actual rate limiting logic:

1. **Resolve requests**: If the request is a GET matching the pattern `/api/v1/share-links/{id}`, it extracts the client IP and checks the resolve rate limit.
2. **Create requests**: If the request is a POST to `/api/v1/share-links`, it extracts the subject (JWT subject or IP) and checks the create rate limit.
3. If the rate limit is exceeded, it writes a `429 Too Many Requests` response and returns without calling the rest of the filter chain.
4. Otherwise, it continues the filter chain.

## Private Methods

### `isRateLimited(String key, int limit)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `key` | `String` | Redis key for the rate limit counter |
| `limit` | `int` | Maximum allowed requests within the window |

**Returns:** `boolean` — `true` if the request count exceeds the limit, otherwise `false`.

This method increments the Redis counter for the given key. If the counter was just created (value is 1), it sets the key's TTL to the configured window duration. Returns `true` if the current count exceeds the limit.

### `resolveClientIp(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `String` — The resolved client IP address.

This method attempts to extract the client IP from the `X-Forwarded-For` header (taking the first IP in a comma-separated list). If the header is absent or blank, it falls back to `request.getRemoteAddr()`.

### `resolveSubjectOrIp(HttpServletRequest request)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `request` | `HttpServletRequest` | The incoming HTTP request |

**Returns:** `String` — The JWT subject if available, otherwise the client IP.

This method checks the current security context for an authenticated JWT token. If found, it returns the token's subject claim. Otherwise, it falls back to `resolveClientIp()`.

### `writeRateLimitResponse(HttpServletResponse response, String bucket, String instance)`

| Parameter | Type | Description |
|-----------|------|-------------|
| `response` | `HttpServletResponse` | The HTTP response |
| `bucket` | `String` | The rate limit bucket name (e.g., "resolve" or "create") |
| `instance` | `String` | The request URI for the `instance` field in the problem detail |

**Returns:** `void`

This method constructs and writes a `ProblemDetail` response with:
- Status: `429 Too Many Requests`
- Content-Type: `application/problem+json`
- `Retry-After` header set to the window duration in seconds
- A JSON body containing the problem details (type, title, status, detail, instance)

## Error Responses

When rate limited, the API returns:

```
HTTP/1.1 429 Too Many Requests
Content-Type: application/problem+json
Retry-After: 60

{
  "type": "https://upmatches.com/problems/rate-limit-exceeded",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded for share-link 'resolve' endpoint. Retry after 60 seconds.",
  "instance": "/api/v1/share-links/abc123"
}
```

## Redis Key Structure

| Key Pattern | Description |
|-------------|-------------|
| `rl:share-link:resolve:{ip}` | Counter for resolve requests by IP |
| `rl:share-link:create:{subject}` | Counter for create requests by subject/IP |

## Usage Notes

- The filter only processes requests starting with `/api/v1/share-links`.
- Resolve rate limiting is based on client IP, which may be affected by proxies or load balancers.
- Create rate limiting uses the authenticated user's JWT subject when available, providing more accurate per-user limits.
- The filter requires Redis to be configured and available; otherwise, it will not be registered.
- Rate limit counters automatically expire after the configured window duration.
