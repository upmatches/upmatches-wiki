# GameNotificationListener

The `GameNotificationListener` is a Spring component that listens for game-related events and handles the creation and delivery of notifications to the appropriate recipients. It processes events such as players joining or leaving games, game updates, cancellations, and skill-level warnings.

## Purpose

This listener acts as an event-driven notification handler that:
- Listens for `GameNotificationEvent` events after database transactions commit
- Resolves the appropriate recipients for each notification type
- Creates in-app notifications
- Delivers notifications via push and email channels
- Prevents duplicate notifications for certain event types

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameRepository` | Repository | Retrieves game entities |
| `GameParticipantRepository` | Repository | Queries game participants |
| `NotificationRepository` | Repository | Checks for existing notifications |
| `ICreateNotificationService` | Service | Creates notification records |
| `IPushNotificationService` | Service | Sends push notifications |
| `IEmailNotificationService` | Service | Sends email notifications |
| `ShareLinkProperties` | Configuration | Provides web base URL for game links |

## Public Methods

### `onGameNotification(GameNotificationEvent event)`

The main event handler method, annotated with `@Async` and `@TransactionalEventListener`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `event` | `GameNotificationEvent` | The game notification event containing type, game ID, and actor information |

**Behavior:**
1. Retrieves the game from the repository
2. Resolves recipients based on event type
3. Builds notification title and message
4. Creates email context with game details
5. For each recipient:
   - Checks for duplicate notifications (if applicable)
   - Creates an in-app notification
   - Attempts external delivery (push/email)

## Private Methods

### `deliverExternally(Notification notification, EmailContext emailContext)`

Handles external notification delivery with fallback logic.

| Parameter | Type | Description |
|-----------|------|-------------|
| `notification` | `Notification` | The created notification entity |
| `emailContext` | `EmailContext` | Context data for email delivery |

**Behavior:**
- Attempts push notification delivery first
- Falls back to email if push fails and recipient has an email address
- Logs if only in-app delivery is possible

### `isDedupable(NotificationType type)`

Determines if a notification type should be deduplicated.

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The type of notification |

**Returns:** `boolean` - `true` for `PLAYER_JOINED`, `GAME_FULL`, and `PLAYER_WARNING_MISMATCH`

### `resolveRecipients(GameNotificationEvent event, Game game)`

Determines the set of recipients for a given event.

| Parameter | Type | Description |
|-----------|------|-------------|
| `event` | `GameNotificationEvent` | The notification event |
| `game` | `Game` | The associated game entity |

**Returns:** `Set<UUID>` - Set of recipient user IDs

**Recipient Resolution Logic:**

| Event Type | Recipients |
|------------|------------|
| `PLAYER_JOINED`, `PLAYER_LEFT`, `GAME_FULL`, `PLAYER_WARNING_MISMATCH` | Game organizer (excluding the actor) |
| `GAME_UPDATED`, `GAME_REMOVED` | All active participants (excluding the actor) |
| `PLAYER_REMOVED_FROM_GAME` | The actor (removed player) |

### `buildTitle(NotificationType type)`

Generates the notification title based on event type.

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The type of notification |

**Returns:** `String` - The notification title

### `buildMessage(NotificationType type, String gameTitle)`

Generates the notification message based on event type and game title.

| Parameter | Type | Description |
|-----------|------|-------------|
| `type` | `NotificationType` | The type of notification |
| `gameTitle` | `String` | The title of the game (may be null or blank) |

**Returns:** `String` - The notification message

## Notification Types and Messages

| Type | Title | Message |
|------|-------|---------|
| `PLAYER_JOINED` | A player joined your game | A new player joined {gameTitle}. |
| `PLAYER_LEFT` | A player left your game | A player left {gameTitle}. |
| `PLAYER_WARNING_MISMATCH` | Skill-level warning | A player joined your game. |
| `GAME_FULL` | Your game is full | Your badminton game has max out. |
| `GAME_UPDATED` | Game updated | {gameTitle} has been updated. |
| `GAME_REMOVED` | Game cancelled | Your badminton game has been cancelled. |
| `PLAYER_REMOVED_FROM_GAME` | You were removed from a game | You have been removed from a badminton game. |
| Default | Notification | Update from Upmatches. |

## Configuration

The listener uses `ShareLinkProperties` to construct game URLs:
```
{webBaseUrl}/games/{gameId}
```

## Logging

The component uses SLF4J logging with the following log levels:
- **WARN**: Game not found, delivery failures
- **DEBUG**: Duplicate notification skipping
- **INFO**: In-app only delivery fallback

## Error Handling

- If a game is not found, the method logs a warning and returns early
- Individual notification creation/delivery failures are caught and logged without affecting other recipients
- External delivery failures fall back gracefully from push to email to in-app only
