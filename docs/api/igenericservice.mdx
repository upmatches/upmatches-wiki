# IGenericService Interface

The `IGenericService` interface defines a generic contract for CRUD (Create, Read, Update, Delete) operations on entities within the application. It provides a standardized way to interact with different types of entities while maintaining consistent method signatures and response patterns.

This interface is designed to work with two generic type parameters:
- `T`: The entity type (input type for create/update operations)
- `K`: The response DTO type (output type for read operations)

## Purpose

The primary purpose of this interface is to establish a reusable service layer pattern that:
- Provides consistent CRUD operations across all entity types
- Supports both numeric (Long) and UUID-based entity identification
- Implements soft delete functionality alongside hard delete
- Returns paginated responses for list operations
- Maintains separation between entity models and response DTOs

## Method Summary

### Pagination and Listing

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `getAll` | `PagedResponse<K>` | `int page`, `int size`, `String sortBy`, `String sortDirection` | Retrieves a paginated list of entities with sorting capabilities |

### Read Operations

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `getById` | `K` | `Long id` | Retrieves a single entity by its numeric identifier |
| `getByUuid` | `K` | `UUID uuid` | Retrieves a single entity by its UUID identifier |

### Create Operations

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `save` | `K` | `T entity` | Creates a new entity and returns the response DTO |

### Update Operations

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `update` | `K` | `Long id`, `T entity` | Updates an existing entity identified by numeric ID |
| `updateByUuid` | `K` | `UUID uuid`, `T entity` | Updates an existing entity identified by UUID |

### Delete Operations

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `softDelete` | `void` | `Long id` | Marks an entity as deleted (soft delete) by numeric ID |
| `softDeleteByUuid` | `void` | `UUID uuid` | Marks an entity as deleted (soft delete) by UUID |
| `delete` | `void` | `Long id` | Permanently removes an entity by numeric ID |
| `deleteByUuid` | `void` | `UUID uuid` | Permanently removes an entity by UUID |

## Usage Example

```java
// Example implementation for a User entity
public class UserService implements IGenericService<UserDTO, UserResponse> {
    
    @Override
    public PagedResponse<UserResponse> getAll(int page, int size, String sortBy, String sortDirection) {
        // Implementation for paginated user retrieval
    }
    
    @Override
    public UserResponse getById(Long id) {
        // Implementation for fetching user by ID
    }
    
    @Override
    public UserResponse save(UserDTO userDTO) {
        // Implementation for creating a new user
    }
    
    // ... other method implementations
}
```

## Notes

- The `PagedResponse<K>` return type for `getAll` provides pagination metadata including total pages, current page, and page size
- Soft delete operations (`softDelete`, `softDeleteByUuid`) typically set a `deletedAt` timestamp rather than removing the record
- Hard delete operations (`delete`, `deleteByUuid`) permanently remove the entity from the database
- The interface supports dual identification strategies (Long and UUID) to accommodate different use cases and legacy systems
