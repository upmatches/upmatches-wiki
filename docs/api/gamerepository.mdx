# GameRepository

The `GameRepository` interface provides data access operations for the `Game` entity in the UpMatches application. It extends Spring Data JPA's `JpaRepository` and includes custom query methods for retrieving, filtering, and updating game records. This repository handles complex queries involving visibility rules, user participation, geolocation filtering, skill level matching, and time-based scheduling.

## Package

`com.upmatches.app.features.game.repositories`

## Interface Declaration

```java
public interface GameRepository extends JpaRepository<Game, UUID>
```

## Methods

### Basic Retrieval

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findByIdAndDeletedAtIsNull` | `Optional<Game>` | `UUID id` | Finds a game by its ID where the `deletedAt` field is null (i.e., not soft-deleted). |
| `findForUpdateById` | `Optional<Game>` | `UUID id` | Finds a game by ID with a pessimistic write lock, ensuring exclusive access for updates. The game must not be soft-deleted. |

### Visibility and Filtering

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findVisibleToUser` | `Page<Game>` | `UUID userId`, `Pageable pageable` | Retrieves a paginated list of scheduled games visible to a user. A game is visible if it is public, the user is the organizer, the user is an active participant, or the user has been granted share access. |
| `findVisibleToUserFiltered` | `List<Game>` | See parameter table below | Retrieves a filtered, cursor-based list of scheduled games visible to a user, with support for venue, skill level, time range, and geolocation filters. |
| `findVisibleForFilterOptions` | `List<Game>` | See parameter table below | Retrieves a filtered list of scheduled games visible to a user, designed for filter option previews. Includes game type filtering and a maximum result limit. |

### User-Specific Game Lists

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findJoinedByUser` | `List<Game>` | `UUID userId`, `Instant afterStartTime`, `UUID afterId`, `int size` | Retrieves a cursor-based list of scheduled games that the user has joined as an active participant. |
| `findHostedByUser` | `List<Game>` | `UUID userId`, `Instant afterStartTime`, `UUID afterId`, `int size` | Retrieves a cursor-based list of scheduled games that the user is hosting (organizing). |
| `countJoinedByUser` | `long` | `UUID userId` | Counts the number of expired games that the user has joined as an active participant. |
| `countHostedByUser` | `long` | `UUID userId` | Counts the number of expired games that the user has hosted. |

### Batch Status Updates

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `markStartedBefore` | `int` | `Instant cutoff`, `Instant now` | Updates the status of all scheduled games that have a `startTime` at or before the cutoff to `STARTED`. Returns the number of affected rows. |
| `markExpiredBefore` | `int` | `Collection<GameStatus> statuses`, `Instant cutoff`, `Instant now` | Updates the status of all games with the given statuses that have an `endTime` before the cutoff to `EXPIRED`. Returns the number of affected rows. |

### Scheduling Queries

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findScheduledStartingBetween` | `List<Game>` | `Instant from`, `Instant to` | Retrieves all scheduled games (not soft-deleted) that start within the specified time range. |
| `findDistinctStartTimesBetween` | `List<Instant>` | `Instant from`, `Instant to` | Retrieves distinct start times of all non-deleted games within the specified time range. |

## Usage Notes

- **Soft Delete**: Most queries exclude games where `deletedAt IS NOT NULL`, ensuring soft-deleted games are not returned.
- **Visibility Logic**: Games are visible to a user if they are public, the user is the organizer, the user is an active participant, or the user has share access.
- **Pessimistic Locking**: The `findForUpdateById` method uses `PESSIMISTIC_WRITE` lock mode to prevent concurrent modifications during critical operations.
- **Cursor-Based Pagination**: Methods like `findVisibleToUserFiltered`, `findJoinedByUser`, and `findHostedByUser` use cursor-based pagination with `afterStartTime` and `afterId` parameters for stable, efficient pagination.
- **Geolocation Filtering**: The repository uses the Haversine formula to calculate distances and filter games by geographic proximity to a given location.
- **Time Zone Handling**: Time-of-day filtering uses the `Asia/Singapore` timezone for consistent behavior.
- **Native Queries**: Several methods use native SQL queries for complex filtering logic that cannot be expressed with JPQL alone.
