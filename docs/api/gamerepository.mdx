# GameRepository

The `GameRepository` interface provides data access operations for the `Game` entity in the UpMatches application. It extends Spring Data JPA's `JpaRepository` to inherit standard CRUD functionality and defines custom query methods for retrieving, filtering, and updating game records.

## Purpose

This repository serves as the data access layer for game management, offering methods to:
- Find games by ID with soft-delete awareness
- Retrieve games visible to specific users based on permissions
- Filter games by various criteria (time, location, skill level, venue)
- Track games joined or hosted by users
- Perform batch status updates for game lifecycle management

## Public Methods

### Basic Queries

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findByIdAndDeletedAtIsNull` | `Optional<Game>` | `UUID id` | Finds a game by ID that hasn't been soft-deleted |
| `findForUpdateById` | `Optional<Game>` | `UUID id` | Finds a game with pessimistic write lock for concurrent updates |

### Visibility and Filtering

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findVisibleToUser` | `Page<Game>` | `UUID userId, Pageable pageable` | Returns paginated games visible to a user (public, organized, joined, or shared) |
| `findVisibleToUserFiltered` | `List<Game>` | Multiple filter parameters | Returns games visible to user with advanced filtering (time, venue, skill level, location, availability) |
| `findVisibleForFilterOptions` | `List<Game>` | Multiple filter parameters | Returns games for filter options with additional game type filtering |

### User-Specific Queries

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findJoinedByUser` | `List<Game>` | `UUID userId, Instant afterStartTime, UUID afterId, int size` | Returns games the user has joined, with cursor-based pagination |
| `findHostedByUser` | `List<Game>` | `UUID userId, Instant afterStartTime, UUID afterId, int size` | Returns games the user is hosting, with cursor-based pagination |
| `countJoinedByUser` | `long` | `UUID userId` | Counts expired games the user has joined |
| `countHostedByUser` | `long` | `UUID userId` | Counts expired games the user has hosted |

### Batch Status Updates

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `markStartedBefore` | `int` | `Instant cutoff, Instant now` | Updates scheduled games that should have started to `STARTED` status |
| `markExpiredBefore` | `int` | `Collection<GameStatus> statuses, Instant cutoff, Instant now` | Updates games that should have expired to `EXPIRED` status |

### Time-Based Queries

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `findScheduledStartingBetween` | `List<Game>` | `Instant from, Instant to` | Finds scheduled games starting within a time range |
| `findDistinctStartTimesBetween` | `List<Instant>` | `Instant from, Instant to` | Returns distinct start times for games within a time range |

## Filtering Capabilities

The repository supports comprehensive filtering through native queries:

- **Time Filters**: Start time ranges, time-of-day filtering (in minutes from midnight, Singapore timezone)
- **Location Filters**: Geographic radius search using the Haversine formula
- **Skill Level Filters**: Skill level range matching based on sort order
- **Venue Filters**: Filtering by specific venue IDs
- **Game Type Filter**: Filtering by game type (available in `findVisibleForFilterOptions`)
- **Availability Filter**: Only returns games with available slots

## Usage Notes

- All queries respect soft-delete by checking `deletedAt IS NULL`
- Visibility queries consider public games, user-organized games, active participations, and shared access
- Cursor-based pagination is used for efficient large dataset traversal
- Batch update methods (`markStartedBefore`, `markExpiredBefore`) return the number of affected rows
- The `findForUpdateById` method uses `PESSIMISTIC_WRITE` lock to prevent concurrent modifications
