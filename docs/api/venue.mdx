# Venue Entity

The `Venue` class is a JPA entity that represents a physical location where activities take place within the UpMatches application. It maps to the `venues` database table and encapsulates all location-related data including geographic coordinates, address information, and associations with activities and nearby stations.

## Purpose

This entity serves as the core location model in the system, providing:
- Geographic positioning through latitude/longitude coordinates
- Physical address details for mapping and navigation
- Association with a specific activity type
- Many-to-many relationship with nearby stations (e.g., metro, train, or bus stations)
- Automatic timestamp management for creation and updates

## Class Overview

| Aspect | Details |
|--------|---------|
| **Package** | `com.upmatches.app.features.venue.entities` |
| **Annotations** | `@Entity`, `@Table(name = "venues")`, `@Getter` |
| **Table** | `venues` |
| **Primary Key** | `id` (auto-generated via identity strategy) |

## Fields

| Field | Type | Database Column | Constraints | Description |
|-------|------|-----------------|-------------|-------------|
| `id` | `Long` | `id` | Primary Key, Auto-generated | Unique identifier for the venue |
| `sourceId` | `String` | `source_id` | Not null, Unique, Max 50 chars | External source identifier |
| `activity` | `Activity` | `activity_id` (FK) | Not null | Associated activity type |
| `name` | `String` | `name` | Not null, Max 200 chars | Venue name |
| `address` | `String` | `address` | Not null, Max 500 chars | Full street address |
| `postalCode` | `String` | `postal_code` | Not null, Max 10 chars | Postal/ZIP code |
| `latitude` | `BigDecimal` | `latitude` | Not null, Precision 13, Scale 10 | Geographic latitude |
| `longitude` | `BigDecimal` | `longitude` | Not null, Precision 13, Scale 10 | Geographic longitude |
| `stations` | `Set<Station>` | `venue_stations` (join table) | Many-to-Many | Associated stations |
| `createdAt` | `Instant` | `created_at` | Not null, Non-updatable | Record creation timestamp |
| `updatedAt` | `Instant` | `updated_at` | - | Last update timestamp |

|--------|-------------|------------|-------------|
| `create()` | `Venue` | `String sourceId`, `Activity activity`, `String name`, `String address`, `String postalCode`, `BigDecimal latitude`, `BigDecimal longitude` | Creates a new Venue instance with required fields |

### Instance Methods

| Method | Return Type | Parameters | Description |
|--------|-------------|------------|-------------|
| `addStation()` | `void` | `Station station` | Associates a station with this venue |
| `removeStation()` | `void` | `Station station` | Removes a station association from this venue |

## Lifecycle Callbacks

| Method | Annotation | Description |
|--------|------------|-------------|
| `onCreate()` | `@PrePersist` | Sets `createdAt` and `updatedAt` to current time before first persistence |
| `onUpdate()` | `@PreUpdate` | Updates `updatedAt` to current time before any update |

## Usage Example

```java
// Create a new venue
Venue venue = Venue.create(
    "ext_001",
    activity,
    "Central Park",
    "59th St to 110th St, New York, NY",
    "10022",
    new BigDecimal("40.7829000"),
    new BigDecimal("-73.9654000")
);

// Add a station
Station station = stationRepository.findById(1L).orElseThrow();
venue.addStation(station);

// Save the venue
venueRepository.save(venue);
```

## Relationships

- **Many-to-One with Activity**: Each venue is associated with exactly one activity type
- **Many-to-Many with Station**: Venues can have multiple associated stations (e.g., nearby public transit stops), and stations can be associated with multiple venues

## Notes

- The class uses Lombok's `@Getter` annotation to automatically generate getters for all fields
- The protected no-argument constructor is required by JPA and should not be used directly
- Geographic coordinates use `BigDecimal` with precision 13 and scale 10 for high accuracy
- Timestamps are stored as `Instant` for timezone-independent time tracking
