# ListGameParticipantsService

The `ListGameParticipantsService` class is a Spring service responsible for retrieving the list of active participants for a specific game. It ensures that only authorized users (those who can view the game) can access the participant list, and it conditionally includes contact information if the requesting user is the game organizer.

## Purpose

- Fetches all active participants for a given game ID.
- Enforces authorization: only users who are allowed to view the game can retrieve the participant list.
- Conditionally includes contact methods (e.g., phone, email) in the response if the requester is the game organizer.
- Wraps the database operation in a transactional read-only context for performance and consistency.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Data access for `GameParticipant` entities. |
| `IAuthenticatedUserResolver` | Service | Resolves the currently authenticated user's ID. |
| `IGameLookupService` | Service | Looks up a `Game` entity by its ID, throwing an exception if not found. |
| `IGameAuthorizationService` | Service | Validates whether a user has permission to view a game. |

## Public Methods

### `execute(UUID id)`

Retrieves the list of active participants for the game identified by the given ID.

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game. |

**Returns:**

| Type | Description |
|------|-------------|
| `List<GameParticipantResponse>` | A list of `GameParticipantResponse` objects representing active participants. |

**Throws:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | If the game does not exist or the participant retrieval fails. |
| `AuthorizationException` | If the authenticated user does not have permission to view the game. |

**Behavior:**

1. Resolves the authenticated user's ID via `userResolver.requireUserId()`.
2. Looks up the game using `lookupService.findGameOrThrow(id)`.
3. Verifies that the user can view the game via `authorizationService.assertCanViewGame(game, userId)`.
4. Determines the activity ID from the game (if any) and whether to include contact methods (if the user is the organizer).
5. Queries the repository for all participants with status `ACTIVE` for the given game, ordered by join date ascending.
6. Maps each `GameParticipant` entity to a `GameParticipantResponse` using the `fromGameParticipant` factory method, passing the activity ID and the `includeContactMethods` flag.
7. Wraps the entire operation in `ServiceOperationExecutor.execute()` for consistent error handling and logging.

## Usage Example

```java
@RestController
public class GameController {
    private final ListGameParticipantsService listGameParticipantsService;

    public GameController(ListGameParticipantsService listGameParticipantsService) {
        this.listGameParticipantsService = listGameParticipantsService;
    }

    @GetMapping("/games/{id}/participants")
    public ResponseEntity<List<GameParticipantResponse>> getParticipants(@PathVariable UUID id) {
        List<GameParticipantResponse> participants = listGameParticipantsService.execute(id);
        return ResponseEntity.ok(participants);
    }
}
```

## Notes

- The service is annotated with `@Service` and `@Transactional(readOnly = true)` to ensure it operates within a read-only transaction context.
- The class is declared as `non-sealed`, indicating it is part of a sealed interface hierarchy (likely `IListGameParticipantsService`).
- Contact methods are only included in the response if the requesting user is the game organizer, protecting participant privacy.
