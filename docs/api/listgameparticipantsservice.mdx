# ListGameParticipantsService

The `ListGameParticipantsService` class is a Spring service responsible for retrieving the list of active participants for a specific game. It enforces authentication and authorization rules, ensuring that only authorized users can view participant data. The service also conditionally includes contact information for the game organizer.

## Purpose

- **Retrieve Active Participants**: Fetches all participants with an `ACTIVE` status for a given game ID.
- **Authorization**: Verifies that the authenticated user has permission to view the game's participants.
- **Conditional Contact Details**: If the requesting user is the game organizer, the response includes contact methods for each participant.
- **Transactional Read**: The operation is marked as `readOnly = true` for performance optimization.

## Dependencies

| Dependency | Type | Description |
|------------|------|-------------|
| `GameParticipantRepository` | Repository | Data access layer for `GameParticipant` entities |
| `IAuthenticatedUserResolver` | Interface | Resolves the currently authenticated user's ID |
| `IGameLookupService` | Interface | Service to find a game by its ID |
| `IGameAuthorizationService` | Interface | Service to check authorization for game operations |

## Constructor

### `ListGameParticipantsService(GameParticipantRepository, IAuthenticatedUserResolver, IGameLookupService, IGameAuthorizationService)`

Initializes the service with required dependencies via constructor injection.

## Public Methods

### `execute(UUID id)`

Retrieves the list of active participants for the specified game.

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | `UUID` | The unique identifier of the game |

| Returns | Type | Description |
|---------|------|-------------|
| `List<GameParticipantResponse>` | List | A list of participant response objects |

**Behavior:**

1. Resolves the authenticated user's ID.
2. Looks up the game by its ID; throws `ResourceNotFoundException` if not found.
3. Verifies that the authenticated user has permission to view the game's participants.
4. Determines whether to include contact methods based on whether the user is the game organizer.
5. Queries the repository for all participants with `ACTIVE` status, ordered by join date ascending.
6. Maps each `GameParticipant` entity to a `GameParticipantResponse` DTO, optionally including contact details.
7. Wraps the operation in `ServiceOperationExecutor` for consistent error handling and logging.

**Exceptions:**

| Exception | Condition |
|-----------|-----------|
| `ResourceNotFoundException` | Thrown if the game does not exist or if the operation fails |

## Usage Example

```java
@Service
public class GameController {
    private final ListGameParticipantsService listParticipantsService;

    public GameController(ListGameParticipantsService listParticipantsService) {
        this.listParticipantsService = listParticipantsService;
    }

    public List<GameParticipantResponse> getParticipants(UUID gameId) {
        return listParticipantsService.execute(gameId);
    }
}
```

## Notes

- The service uses `non-sealed` modifier, indicating it is part of a sealed class hierarchy.
- Contact methods are only included in the response if the requesting user is the game organizer.
- The `ServiceOperationExecutor` handles transaction management and exception translation.
- The query filters participants by `ACTIVE` status only; other statuses are excluded.
