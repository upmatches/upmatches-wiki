## Overview

The `LogAspect` class is a Spring AOP (Aspect-Oriented Programming) aspect that provides centralized logging, metrics collection, and request tracing for service and controller methods in the application. It automatically intercepts method executions, logs their performance, records metrics to Micrometer, and manages MDC (Mapped Diagnostic Context) for request correlation.

## Purpose

- **Automatic Logging**: Logs method execution time and status (success/failure) for all public service and controller methods
- **Performance Monitoring**: Tracks slow method executions and logs warnings when thresholds are exceeded
- **Metrics Collection**: Records execution metrics to Micrometer with component and status tags
- **Request Tracing**: Generates and manages unique request IDs for distributed tracing
- **Error Handling**: Wraps checked exceptions into `MethodExecutionException` while preserving runtime exceptions and errors

## Configuration

The aspect is enabled by default but can be disabled via configuration:

```yaml
app:
  logging:
    aspect:
      enabled: true  # Set to false to disable the aspect
```

## Dependencies

- **Micrometer**: For metrics collection via `MeterRegistry`
- **SLF4J**: For logging with MDC support
- **Spring Web**: For HTTP request context access
- **AspectJ**: For AOP pointcut and advice definitions

## Public Methods

| Method | Return Type | Description |
|--------|-------------|-------------|
| `logExecution(ProceedingJoinPoint joinPoint)` | `Object` | Main advice method that intercepts service and controller method executions |

## Method Details

### `logExecution(ProceedingJoinPoint joinPoint)`

This is the `@Around` advice that wraps all matched method executions.

**Parameters:**
- `joinPoint` - The AspectJ join point representing the intercepted method

**Returns:**
- The result of the intercepted method execution

**Throws:**
- `Throwable` - Propagates errors and runtime exceptions; wraps checked exceptions in `MethodExecutionException`

**Behavior:**
1. Generates a new request ID if none exists in the current MDC context
2. Captures HTTP request context (method and URI) if available
3. Executes the target method and measures execution time
4. Records metrics to Micrometer with component and status tags
5. Logs success with execution time (warns if slow)
6. On failure, logs error details and re-throws appropriately
7. Cleans up MDC context in the `finally` block

## Pointcut Definitions

| Pointcut | Expression | Target |
|----------|------------|--------|
| `serviceMethods()` | `execution(public * com.upmatches.app..services..*(..))` | All public methods in service packages |
| `controllerMethods()` | `within(@RestController *) \|\| within(@Controller *)` | All methods in RestController and Controller classes |

## MDC Context Management

The aspect manages the following MDC keys:

| MDC Key | Description | Set When |
|---------|-------------|----------|
| `requestId` | Unique 8-character request identifier | New request context |
| `method` | Short method signature | Every execution |
| `httpMethod` | HTTP method (GET, POST, etc.) | HTTP context available |
| `endpoint` | Request URI path | HTTP context available |

## Metrics

Metrics are recorded using Micrometer's `Timer` with the following structure:

- **Metric Name**: Defined in `AspectConstant.METRIC_NAME`
- **Tags**:
  - `component`: Either `controller` or `service`
  - `status`: Either `success` or `failure`

## Logging Behavior

| Condition | Log Level | Message Pattern |
|-----------|-----------|-----------------|
| Success (fast) | INFO | Method executed successfully |
| Success (slow) | WARN | Method execution exceeded threshold |
| Failure | ERROR | Method failed with exception details |

The slow execution threshold is configurable via `LogAspectProperties.slowExecutionThresholdMs()`.

## Error Handling Strategy

- **Errors**: Propagated as-is (unrecoverable)
- **RuntimeExceptions**: Propagated as-is
- **Checked Exceptions**: Wrapped in `MethodExecutionException` with method name and duration context

## Usage Example

```java
@RestController
public class UserController {
    
    @GetMapping("/users/{id}")
    public User getUser(@PathVariable Long id) {
        // This method will be automatically logged and monitored
        return userService.findById(id);
    }
}
```

The aspect will:
1. Generate a request ID and add it to MDC
2. Log the HTTP method and endpoint
3. Measure execution time
4. Record metrics to Micrometer
5. Log success or failure with timing information

## Notes

- The aspect is conditionally enabled via `@ConditionalOnProperty`
- Request IDs are truncated to 8 characters for readability
- HTTP context is optional; the aspect works without web requests
- MDC cleanup is guaranteed in the `finally` block to prevent context leaks
